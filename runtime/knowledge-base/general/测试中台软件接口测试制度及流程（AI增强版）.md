## 1. 前言

### 1.1 目的

本制度描述测试中台进行软件接口测试所需要遵守的流程，融入AI智能体协作机制：

- ✅ **接口测试全流程AI化**：从计划到报告，AI智能体全程参与
- ✅ **接口测试标准化执行**：api-executor自动执行所有接口测试
- ✅ **知识库驱动**：接口规范和测试经验沉淀到知识库
- ✅ **AI质量三重审核**：确保测试产出物质量

### 核心原则

> **AI = 标准化执行引擎，人 = 策略决策与质量门禁**

### 1.2 对象

本制度面向软件产品接口测试的所有相关人员：研发负责人、项目经理、开发人员、测试人员、配置管理人员、QA、AI智能体。

### 1.3 要求

软件测试人员和AI智能体必须遵守相应流程和制度。

### 1.4 适用范围

本制度适用于测试中台软件项目的接口测试，描述了测试应遵循的制度及流程以及AI智能体协作机制。

## 2. 测试过程（AI版）

### 2.1 测试计划（AI版）

#### 2.1.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 项目经理 | 提供计划书和需求文档 | - |
| 配置管理员 | 基线化文档 | - |
| 测试负责人 | 编写计划、组织评审 | test-master自动评估工作量 |
| QA | 监控过程、质量审核 | AI自动采集度量数据 |

#### 2.1.2 输入

- 《项目开发计划书》
- 《产品需求说明书》
- 📌 知识库：general + project-test + project-biz

#### 2.1.3 执行步骤

1. 项目经理提供《项目开发计划书》和《产品需求说明书》
2. **📌 test-requirement-analyzer自动分析接口需求**
3. 测试负责人编写《接口测试计划》
4. **📌 test-master自动评估接口测试工作量**
5. 测试负责人组织评审
6. 配置管理员基线化审核通过的文档

#### 2.1.4 输出

- 《软件接口测试计划》
- 📌 接口需求分析报告（AI自动生成）

### 2.2 测试用例的编写（AI版）

#### 2.2.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 测试工程师 | 审核和补充用例 | test-case-generator自动生成接口用例 |
| 测试负责人 | 组织评审 | - |
| QA | 监控过程 | AI自动采集用例质量数据 |

#### 2.2.2 输入

- 《接口测试计划》
- 《产品需求说明书》
- 《概要设计说明书》
- 📌 知识库：general + project-test + project-biz

#### 2.2.3 执行步骤

1. **📌 test-case-generator自动生成接口测试用例**（参数校验、边界值、异常处理、并发测试等）
2. **📌 test-data-generator自动生成接口测试数据**
3. **📌 data-masking自动脱敏敏感测试数据**
4. 测试工程师审核和补充AI生成的用例
5. 测试负责人组织评审
6. 配置管理员基线化审核通过的用例

#### 2.2.4 输出

- 《接口测试用例》（人工审核 + AI生成）
- 📌 测试数据集（AI自动生成）
- 📌 用例覆盖度报告（AI自动生成）

### 2.3 测试实施（AI版）

#### 2.3.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 测试工程师 | 搭建环境 | api-executor自动执行接口测试 |
| 项目经理 | 安排发布 | - |
| 测试负责人 | 组织评审 | - |
| QA | 监控过程 | AI自动采集数据 |

#### 2.3.2 输入

- 《接口测试用例》
- 《概要设计说明书》
- 《产品需求说明书》
- 📌 知识库：general + project-test + project-biz

#### 2.3.3 执行步骤

1. 产品满足提交测试要求后进入测试
2. **📌 api-executor自动执行预测试（冒烟测试）**
3. 预测试通过后，**📌 api-executor自动执行系统接口测试**
4. **📌 api-executor自动执行15种接口测试方法**：
   - 静态分析 → 基本测试用例 → 验证输入输出数据 → 边界值测试
   - 错误处理测试 → 并发与负载测试 → 接口协议和参数测试
   - 安全性测试 → 兼容性测试 → 接口参数基本校验
   - 接口正常功能逻辑校验 → 接口异常处理逻辑
   - 接口日志检查 → 接口数据一致性 → 性能并发问题
5. **📌 defect-analyzer自动分析缺陷**
6. **📌 test-reporter自动生成接口测试报告**
7. **📌 AI质量三重审核**审核接口测试报告
8. 测试负责人组织评审

#### 2.3.4 输出

- 《接口测试报告》（人工审核 + AI生成）
- 📌 缺陷分析报告（AI自动生成）
- 📌 AI质量审核报告

### 2.4 缺陷管理（AI版）

#### 2.4.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 测试人员 | 确认bug | defect-analyzer自动识别和分类缺陷 |
| 项目经理 | 缺陷管理和跟踪 | AI自动跟踪缺陷状态 |
| 开发人员 | 修改错误 | - |
| QA | 监控过程 | AI自动采集缺陷度量数据 |

#### 2.4.2 执行步骤

1. **📌 defect-analyzer自动识别缺陷并提单到JIRA**
2. **📌 AI自动对缺陷进行分级和分类**
3. JIRA研发接口人分流
4. 开发人员修改bug并进行内部回归
5. **📌 api-executor自动执行回归测试**
6. 项目经理跟踪修改情况

## 3. 测试流程（AI版）

```
需求文档 → test-requirement-analyzer（接口需求分析）
                ↓
          test-scheme-generator（接口测试方案）
                ↓
          test-case-generator（接口用例生成）
                ↓
          test-data-generator（接口测试数据）
                ↓
          data-masking（数据脱敏）
                ↓
          api-executor（接口测试执行）
              ↓   ↓
     正常测试    15种测试方法
              ↓   ↓
          defect-analyzer（缺陷分析）
                ↓
          test-reporter（接口报告生成）
                ↓
          AI质量三重审核
                ↓
          人工确认（质量门禁）
```

## 6. AI智能体协作规范

### 智能体调度流程

| 阶段 | 智能体 | 职责 |
|------|--------|------|
| 需求分析 | test-requirement-analyzer | 分析接口需求文档 |
| 测试方案 | test-scheme-generator | 生成接口测试方案 |
| 用例设计 | test-case-generator | 自动生成接口测试用例 |
| 数据准备 | test-data-generator | 生成接口测试数据 |
| 数据脱敏 | data-masking | 脱敏敏感数据 |

| 审核维度 | 审核智能体 | 权重 |
|----------|-----------|------|
| 事实幻觉 + 逻辑一致性 | ai-quality-reviewer-1 | 50% |
| 安全合规 | ai-quality-reviewer-2 | 25% |
| 格式结构 | ai-quality-reviewer-3 | 25% |

**通过标准**：所有三个审核智能体评分 ≥ 95分
