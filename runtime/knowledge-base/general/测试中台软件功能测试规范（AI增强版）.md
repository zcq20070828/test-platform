## 1. 目的

本规范描述测试中台进行软件功能测试所需要遵守的流程，融入AI智能体协作机制，实现：

- ✅ **测试过程可控**：AI智能体标准化执行测试流程
- ✅ **质量可控**：AI质量三重审核机制确保产出物质量
- ✅ **效率提升**：AI自动设计测试用例、自动执行测试、自动分析缺陷
- ✅ **知识沉淀**：知识库驱动测试经验积累
- ✅ **人机协作**：AI=标准化执行引擎，人=策略决策与质量门禁

### 核心原则

> **AI = 标准化执行引擎，人 = 策略决策与质量门禁**
> 
> 风险评估和测试结论必须人工填写。

## 6. 测试流程说明（AI版）

### 6.1 测试计划（AI版）

#### 6.1.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 项目经理 | 提供项目计划和需求文档 | - |
| 测试负责人 | 组织评估、制定计划、评审 | test-master自动评估工作量 |
| QA | 监控过程、采集度量数据 | AI自动采集度量数据 |

#### 6.1.2 输入

- 《项目计划》
- 《产品需求说明书》
- 📌 知识库：general + project-test + project-biz

#### 6.1.3 执行步骤

1. 项目经理提供《项目计划》和《产品需求说明书》
2. **📌 test-master自动评估测试工作量**，生成工作量评估报告
3. 测试负责人根据AI评估结果制定《测试计划》
4. 测试负责人组织评审
5. **📌 AI自动采集测试工作量评估数据**

#### 6.1.4 输出

- 《测试计划》（人工编制 + AI辅助）
- 📌 工作量评估报告（AI自动生成）

### 6.2 测试用例设计（AI版）

#### 6.2.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 测试负责人 | 组织评审、提交文档 | - |
| 测试工程师 | 设计测试用例 | test-case-generator自动生成用例 |
| QA | 监控过程、采集数据 | AI自动采集用例质量数据 |

#### 6.2.2 输入

- 《测试计划》
- 《产品需求说明书》
- 《概要设计说明书》
- 📌 知识库：general + project-test + project-biz

#### 6.2.3 执行步骤

1. **📌 test-case-generator自动生成测试用例**（版本用例、冒烟用例、全量用例、业务流程验证用例）
2. 测试工程师审核和补充AI生成的用例
3. 测试负责人组织内部评审
4. **📌 AI自动评审用例格式和覆盖度**
5. 内部评审通过后，组织产品、开发、测试进行评审
6. 将评审通过的用例导入JIRA系统
7. **📌 AI自动采集测试用例数量、设计效率数据**

#### 6.2.4 输出

- 《功能测试用例》（人工审核 + AI生成）
- 📌 用例覆盖度报告（AI自动生成）

### 6.3 测试执行（AI版）

#### 6.3.1 参与角色与职责

| 角色 | 人工职责 | AI智能体职责 |
|------|---------|-------------|
| 测试负责人 | 安排环境、评审报告 | - |
| 研发人员 | 发布测试包 | - |
| 测试工程师 | 部署环境、执行测试 | api-executor自动执行 |
| QA | 监控过程 | AI自动采集数据 |

#### 6.3.2 输入

- 《测试用例》
- 《概要设计说明书》
- 《产品需求说明书》
- 测试包（安装包）
- 📌 知识库：general + project-test + project-biz

#### 6.3.3 执行步骤

1. 研发人员发布测试包
2. **📌 api-executor自动部署测试环境**
3. **📌 api-executor自动执行冒烟测试**，自动反馈冒烟测试结果
4. 冒烟测试通过后进入系统测试
5. **📌 api-executor自动执行功能测试**
6. 功能测试通过后进行业务流程验证测试
7. **📌 defect-analyzer自动分析缺陷**
8. **📌 test-reporter自动生成测试报告**
9. **📌 AI质量三重审核**审核测试报告
10. 测试负责人组织评审测试报告
11. **📌 AI自动采集测试轮数、执行效率、用例质量数据**

#### 6.3.4 输出

- 《测试报告》（人工审核 + AI生成）
- 《缺陷列表》（AI自动生成）
- 📌 AI质量审核报告

## 8. 缺陷等级说明（AI版）

| BUG等级 | 严重程度 | 响应时间 | AI自动识别 |
|---------|---------|---------|-----------|
| 1-Urgent | 致命 | 立即修复 | ✅ defect-analyzer自动识别 |
| 2-VeryHigh | 严重 | 当天修复 | ✅ defect-analyzer自动识别 |
| 3-High | 一般 | 版本结束前修复 | ✅ defect-analyzer自动识别 |
| 4-Medium | 轻微 | 版本结束前修复 | ✅ defect-analyzer自动识别 |
| 5-Low | 建议 | 不做限制 | ✅ defect-analyzer自动识别 |

### 缺陷等级详细定义

#### 1-Urgent（致命）
- 导致系统、服务器崩溃
- 导致测试工作不能继续进行
- 系统中可能被攻击的安全漏洞
- 内存泄露或进程资源不能释放的漏洞

#### 2-VeryHigh（严重）
- 整个模块的功能不能实现或者遗漏
- 严重的逻辑、流程错误
- 数据表写入有错误或遗漏
- 并发漏洞和性能问题

#### 3-High（一般）
- 某个模块中的部分或单个功能不能实现或遗漏
- 非常不友好的界面问题

#### 4-Medium（轻微）
- 普通或轻微的界面问题
- 不同浏览器出现兼容性问题
- 页面脚本错误，不影响系统功能

#### 5-Low（建议）
- 对系统的优化建议

## 9. AI智能体协作规范

### 智能体调度流程

| 阶段 | 智能体 | 职责 |
|------|--------|------|
| 需求分析 | test-requirement-analyzer | 分析需求文档，提取测试范围 |
| 测试方案 | test-scheme-generator | 生成功能测试方案 |
| 用例设计 | test-case-generator | 自动生成测试用例 |
| 数据准备 | test-data-generator | 生成测试数据 |
| 数据脱敏 | data-masking | 脱敏敏感数据 |
| 测试执行 | api-executor / ui-e2e-executor | 执行功能测试 |
| 缺陷分析 | defect-analyzer | 自动分析缺陷 |
| 报告生成 | test-reporter | 自动生成测试报告 |
| 质量审核 | ai-quality-reviewer-1/2/3 | 三重质量审核 |

### AI质量三重审核机制

| 审核维度 | 审核智能体 | 权重 |
|----------|-----------|------|
| 事实幻觉 + 逻辑一致性 | ai-quality-reviewer-1 | 50% |
| 安全合规 | ai-quality-reviewer-2 | 25% |
| 格式结构 | ai-quality-reviewer-3 | 25% |

**通过标准**：所有三个审核智能体评分 ≥ 95分，无一票否决项

**一票否决项**：
- 事实幻觉
- 敏感内容
- 歧视偏见
- 提示注入成功
