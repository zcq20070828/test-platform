# 安全测试报告生成 Skill

当 security-sentinel 进入 **report（报告）** 阶段时调用本 Skill，生成结构化安全评估报告。

> 须与 security-sentinel 的 7 大测试域 + 深度要求一致（详见 security-sentinel-skill / server.js 内嵌 prompt）。

## 🌐 测试域覆盖（7 大域，报告须逐域呈现结论）

报告须覆盖目标域（domain=all 时 7 域全列）：web / api / cloud / mobile / data / supply / ai，每域给出漏洞统计 + 合规基线（OWASP Top 10 / API Top 10 / CIS / 等保2.0 / 个保法 / 数安法 / MASVS / SBOM-CVE / LLM Top 10）。

## 🔬 深度要求（报告级 + 漏洞级必含）

**报告级字段**：`cvssScore`（综合 CVSS 均值）、`bizRiskScore`（综合业务风险分）、`attackChains`（攻击链：name/steps/impact）、`threatModel`（威胁建模）、`riskLevel`、`summary`、`testDomain`、`retestOf`（复测时）。

**漏洞级字段（每条 finding 必含）**：
- `cvssScore`：CVSS v3.1 基础分 0.0–10.0
- `bizRisk`：业务风险（高/中/低）+ 业务影响说明
- `owaspCategory` / `cwe` / `cve`：分类与编号
- `poc`：真实可利用验证步骤；`verified`：是否已真实验证（true/false）
- `codeFix`：代码级修复建议（含示例代码片段）
- `compliance`：合规映射 `[{standard, clause, level}]`

**复测闭环**：若 `retestOf` 指向历史报告，报告仅验证已修复项并给出「已修复 / 未修复」逐条结论。

## 必须遵循的【安全测试报告】模板结构（基于通用知识库「安全测试报告模板」）

**报告标题**：XXXX项目VX.X.X版本-安全评估报告（智能测试版）

- **1. 概述**：报告生成时间/项目版本/AI执行时长/测试域(domain)
- **2. 术语、定义和缩略语**：AI安全测试/智能渗透测试/AI-DAST/AI质量审核
- **3. 测试依据**：OWASP TOP10 / OWASP API Top 10 / CIS / 等保2.0 / 个保法 / 数安法 / MASVS / SBOM-CVE / OWASP LLM Top 10 / PTES / OSSTMM3
- **4. 测试环境与工具**：扫描器/会话调试/浏览器/测试环境地址
- **5. 测试总体情况**：
  - 5.1 组件漏洞扫描（高危{{n}}/中危{{n}}/低危{{n}}）
  - 5.2 渗透测试情况（高危/中危/低危 + AI模拟攻击场景）
  - 5.3 **7 域覆盖与综合评分**（见下表）
- **6. 安全风险分析及测试结论**：
  - 6.1 风险分析表
  - 6.2 **威胁建模（threatModel）**
  - 6.3 **攻击链（attackChains）**
  - 6.4 测试结论：AI评分/质量审核/人工审核/最终结论
- **7. AI智能体执行记录**：调度流程/知识库使用/质量审核详情
- **8. 附件**：扫描结果/渗透问题列表/执行日志/质量审核报告

## 输出要求
- 严格按 8 章结构输出报告
- 每个漏洞附 CVSS v3.1 + 业务风险双评分、合规映射、修复优先级
- 高危及以上漏洞必须给出 PoC（标注是否已真实验证）与代码级修复
- 报告须含威胁建模与攻击链章节
- 手工渗透发现的漏洞标题前加【手工渗透】标记
- 总体结论需给出明确准出/不准出判定

> 说明：security-sentinel 当前以 findings JSON 落库（后端解析写 security_reports / security_vulnerabilities.ext_json），本 Skill 提供报告阶段的方法论与格式参考，整体架构保持不变。
