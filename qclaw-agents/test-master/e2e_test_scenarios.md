# 用户登录功能 — E2E测试场景文档

**版本：V1.0 | 日期：2026-06-23 | 基于《用户登录功能测试用例 V2.1》**

---

## 文档说明

本文档定义用户登录功能的端到端（E2E）测试场景，覆盖完整业务流程而非单一功能点。每个场景模拟真实用户的操作路径，验证多模块协作下的业务正确性。

场景优先级定义：
- **P0**：核心业务流程，阻塞上线，必须100%通过
- **P1**：重要业务流程，影响用户体验，优先保障

自动化可行性定义：
- **高**：可完全自动化，无需人工干预
- **中**：部分步骤需Mock或半自动化
- **低**：需要人工操作或物理设备配合

## 场景1：账号密码登录 → 登出 → 重新登录

| 属性 | 值 |
|------|-----|
| **优先级** | P0 |
| **覆盖用例** | TC-LOGIN-001, TC-LOGIN-012, TC-LOGIN-014, TC-LOGIN-013 |
| **自动化可行性** | 高 |
| **预估时长** | 2分钟 |

### 前置条件
- 已注册账号：testuser01 / Passw0rd!
- 登录页可正常访问
- 系统处于未登录状态

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开登录页 | 页面正常加载，显示用户名/密码输入框和登录按钮 |
| 2 | 输入用户名 `testuser01` | 输入框正确显示用户名 |
| 3 | 输入密码 `Passw0rd!` | 密码以密文形式显示 |
| 4 | 点击登录按钮 | 按钮变为加载状态，页面跳转至首页 |
| 5 | 验证首页加载 | 首页正确显示，用户菜单可见，包含用户名信息 |
| 6 | 检查Cookie/Token | 浏览器Cookie中包含有效的Session/Token，HttpOnly和Secure属性已设置 |
| 7 | 点击用户菜单 | 展开下拉菜单，包含"退出登录"选项 |
| 8 | 点击"退出登录" | 页面跳转回登录页，Cookie/Token被清除 |
| 9 | 验证登出状态 | 访问 `/home` 被重定向到登录页 |
| 10 | 重新输入用户名和密码 | 输入框正确填入 |
| 11 | 点击登录按钮 | 再次登录成功，跳转首页 |
| 12 | 快速连续点击登录按钮3次 | 仅创建一个会话，不重复提交（防重复提交验证） |

### 验证要点
- 登录成功后Session/Token正确设置（HttpOnly + Secure）
- 登出后Cookie/Token彻底清除
- 重新登录不受之前会话影响
- 防重复提交机制有效

### 异常分支
- 步骤4网络超时 → 提示"网络异常，请检查网络后重试"
- 步骤8登出失败 → 页面仍停留在首页，需重试

## 场景2：手机验证码登录 → 验证码错误 → 重新获取 → 登录成功

|------|-----|

| **自动化可行性** | 中（需Mock短信验证码） |
| **预估时长** | 3分钟 |

### 前置条件
- 手机号 13800138002 已注册
- 测试环境短信验证码可获取（或使用Mock接口）
- 登录页可正常访问

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开登录页，切换到"验证码登录"Tab | 显示手机号输入框和获取验证码按钮 |
| 2 | 输入手机号 `13800138002` | 手机号输入框正确显示 |
| 3 | 点击"获取验证码" | 按钮变为倒计时状态（60s），短信发送成功 |
| 4 | 立即再次点击"获取验证码" | 按钮禁用，无法再次发送 |
| 5 | 输入错误验证码 `000000` | 验证码输入框正确显示 |
| 6 | 点击登录 | 提示"验证码错误，请重新输入" |
| 7 | 再次输入错误验证码 `000001` | 验证码输入框可清空重新输入 |
| 8 | 点击登录 | 提示"验证码错误，请重新输入" |
| 9 | 第三次输入错误验证码 `000002` | — |
| 10 | 点击登录 | 提示"验证码错误次数过多，请重新获取"，验证码失效 |
| 11 | 等待60秒倒计时结束 | 按钮恢复可点击状态 |
| 12 | 点击"获取验证码" | 新验证码发送成功，按钮再次倒计时 |
| 13 | 输入正确验证码（6位数字） | 验证码输入框正确显示 |
| 14 | 点击登录 | 登录成功，跳转首页 |
| 15 | 登出后使用同一验证码再次登录 | 提示"验证码已失效"（一次性使用验证） |

### 验证要点
- 验证码错误3次后自动失效，需重新获取
- 60秒冷却期间不可重复获取验证码
- 验证码一次性使用，登录成功后即失效
- 重新获取验证码后可正常登录

### 异常分支
- 步骤3短信未到达 → 提供"语音验证码"备选入口
- 步骤12超过每日发送上限 → 提示"今日发送次数已达上限"

## 场景3：扫码登录完整流程

| 属性 | 值 |
|------|-----|
| **优先级** | P0 |
| **覆盖用例** | TC-LOGIN-033, TC-LOGIN-034, TC-LOGIN-035, TC-LOGIN-038, TC-LOGIN-041, TC-LOGIN-042 |
| **自动化可行性** | 低（需手机端扫码配合） |
| **预估时长** | 5分钟 |

### 前置条件
- PC端登录页可正常访问
- 手机端App已登录且账号状态正常
- 手机端与PC端网络连通

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开PC端登录页，切换到"扫码登录"Tab | 页面正确显示二维码，二维码可正常扫描 |
| 2 | 等待2分钟不操作 | 二维码过期，页面提示"二维码已过期"并显示刷新按钮或自动刷新 |
| 3 | 点击刷新按钮（或等待自动刷新） | 生成新的二维码，旧二维码失效 |
| 4 | 使用手机端App扫描新二维码 | 手机端弹出登录确认页面，显示"是否确认登录" |
| 5 | PC端观察状态 | 页面显示"已扫描，请在手机端确认" |
| 6 | 手机端点击"取消" | PC端提示"用户取消登录"，保持登录页状态 |
| 7 | 刷新二维码 | 生成新的二维码 |
| 8 | 再次扫描新二维码 | 手机端弹出确认页面 |
| 9 | 手机端点击"确认登录" | PC端自动跳转首页，登录成功 |
| 10 | 在安全中心查看设备列表 | 扫码登录的设备正确出现在设备列表中 |

### 验证要点
- 二维码有过期机制（2分钟），过期后无法扫码登录
- 扫码后手机端确认/取消操作正确同步到PC端
- 扫码登录成功后设备信息正确记录
- 二维码刷新后旧码立即失效

### 异常分支
- 步骤4扫码过程中网络断开 → 恢复网络后状态轮询继续正常
- 步骤9确认超时 → 提示"扫码超时，请刷新后重试"
- 步骤8使用截获的旧二维码 → 扫码无效（防重放攻击）

### 前置条件

- 已录入生物特征且已授权生物识别登录
- 账号状态正常

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 打开App | App启动，自动触发生物识别弹窗 |
| 2 | 使用正确的指纹/Face ID验证 | 识别通过，完成登录，跳转首页 |
| 3 | 登出App | 返回登录页 |
| 4 | 再次触发生物识别 | 弹出生物识别验证 |
| 5 | 使用错误指纹/照片验证 | 识别失败，提示"识别失败，请使用密码登录" |
| 6 | 再次使用错误指纹 | 识别失败，失败计数+1 |
| 7 | 连续失败5次 | 生物识别被锁定，提示需使用密码解锁 |
| 8 | 输入正确密码 | 密码验证通过，登录成功 |

### 验证要点
- 生物识别成功可完成登录
- 识别失败后正确降级到密码登录
- 连续5次失败后生物识别被锁定，需密码解锁
- 生物识别关闭后不显示相关入口
- 重新开启后功能恢复

### 异常分支
- 步骤5设备不支持生物识别 → 提示"当前设备不支持生物识别"，不闪退
- 步骤7密码也忘记 → 引导至"忘记密码"流程

## 场景5：暴力破解防护流程

| 属性 | 值 |
|------|-----|
| **优先级** | P0 |
| **覆盖用例** | TC-SECURITY-005, TC-SECURITY-006, TC-SECURITY-035, TC-SECURITY-030 |
| **自动化可行性** | 中（需并发工具配合） |
| **预估时长** | 10分钟（含30分钟锁定等待） |

### 前置条件
- 已注册账号：testuser01
- 测试环境为隔离环境
- 系统暴力破解防护策略已配置（5次失败锁定30分钟，3次失败弹出图形验证码）

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 输入正确用户名，输入错误密码 | 登录失败，提示"用户名或密码错误" |
| 2 | 第2次输入错误密码 | 登录失败，提示"用户名或密码错误" |
| 3 | 第3次输入错误密码 | 登录失败，**页面弹出图形验证码或滑动验证** |
| 4 | 完成图形验证码，第4次输入错误密码 | 登录失败，提示"用户名或密码错误" |
| 5 | 第5次输入错误密码 | **账号锁定**，提示"账号已锁定，请30分钟后重试或联系客服" |
| 6 | 立即用正确密码尝试登录 | 仍提示账号锁定，无法登录 |
| 7 | 使用常见弱口令字典（如123456, password, qwerty等）对其他账号批量尝试 | 前5次失败后触发锁定，后续请求被拦截 |
| 8 | 同一IP使用不同账号名在10分钟内发起20+次登录请求 | IP被限流，返回429或需等待 |
| 9 | 等待30分钟后 | 用正确密码登录成功，锁定状态解除 |

### 验证要点
- 连续3次失败后弹出图形验证码/人机验证
- 连续5次失败后账号锁定30分钟
- 锁定期间即使正确密码也无法登录
- 弱口令字典攻击被锁定机制拦截
- 同IP大量请求被限流
- 30分钟锁定到期后自动解锁

### 异常分支
- 步骤8攻击者使用代理IP → 需结合设备指纹和风控规则防护
- 步骤9锁定时间未到尝试 → 仍提示锁定

| 1 | 打开登录页 | 显示第三方登录入口（微信、支付宝图标） |
| 2 | 点击微信登录 | 跳转微信授权页面 |

| 4 | 再次点击微信登录 | 跳转微信授权页面 |

- 第三方服务不可用时有降级提示

- 步骤8用户拒绝绑定直接关闭页面 → 返回登录页，不创建幽灵账号
- 步骤11所有第三方服务不可用 → 至少保留账号密码和验证码登录方式

## 场景7：会话超时重新登录

| 属性 | 值 |
|------|-----|
| **优先级** | P1 |
| **覆盖用例** | TC-LOGIN-012, TC-SECURITY-004, TC-SECURITY-012 |
| **自动化可行性** | 高 |
| **预估时长** | 35分钟（含30分钟超时等待，可Mock） |

### 前置条件
- 已注册账号：testuser01 / Passw0rd!
- 系统会话超时时间为30分钟（短会话）
- 勾选"记住我"后会话超时时间为7天（长会话）

### 测试步骤

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 使用正确凭证登录（不勾选"记住我"） | 登录成功，跳转首页 |
| 2 | 记录当前Session ID和Token | Session ID和Token值已记录 |
| 3 | 等待30分钟不操作 | 会话超时 |
| 4 | 尝试在首页进行操作 | 提示"登录已过期，请重新登录"，自动跳转到登录页 |
| 5 | 验证Cookie/Token | Cookie/Token已被清除或过期 |
| 6 | 重新输入用户名和密码登录 | 登录成功 |
| 7 | 记录新的Session ID | 新的Session ID与步骤2中的不同（防会话固定攻击） |
| 8 | 勾选"记住我"登录 | 登录成功 |
| 9 | 关闭浏览器 | — |
| 10 | 重新打开浏览器访问首页 | 自动登录（Cookie持久化），无需重新输入凭证 |
| 11 | 在另一个浏览器使用同一账号登录 | 第一个浏览器的会话被终止（单点登录模式） |
| 12 | 在第一个浏览器尝试操作 | 提示"您的账号已在其他设备登录"，需重新登录 |

### 验证要点
- 短会话（不勾选记住我）30分钟超时后需重新登录
- 重新登录后Session ID更新（防会话固定攻击）
- 勾选"记住我"后关闭浏览器再打开可自动登录
- 单点登录模式下新登录踢掉旧会话
- 超时后Cookie/Token被正确清理

### 异常分支
- 步骤3用户在超时前1秒提交操作 → 操作应正常完成
- 步骤11并发登录冲突 → 按系统策略处理（互踢或允许多端）

## 场景汇总

| 序号 | 场景名称 | 优先级 | 自动化可行性 | 覆盖用例数 | 预估时长 |
|------|---------|--------|-------------|-----------|---------|
| 1 | 账号密码登录 → 登出 → 重新登录 | P0 | 高 | 4 | 2min |
| 2 | 手机验证码登录 → 验证码错误 → 重新获取 → 登录成功 | P0 | 中 | 5 | 3min |

### 自动化优先级建议

| 执行轮次 | 场景 | 理由 |
|---------|------|------|
| 第1轮（CI回归） | 场景1、2、5、7 | 自动化可行性高/中，P0优先 |
| 第2轮（集成测试） | 场景6 | 自动化可行性中，P1 |
| 第3轮（手工验证） | 场景3、4 | 需物理设备或人工配合 |
