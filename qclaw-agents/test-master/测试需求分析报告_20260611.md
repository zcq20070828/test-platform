# 测试需求分析报告：用户反馈问题优化及6.0功能补齐（3月）

## 1. 需求概述

本次迭代以**用户体验优化**和**6.0功能补齐**为核心目标，涵盖10个需求项，涉及邮件列表交互优化、样式对齐、写信页改进、浏览器兼容性、草稿箱角标逻辑变更、邮件日期识别与日程提醒、会话邮件功能补齐、PC客户端账户关闭提示、列表操作交互优化及全局体验优化等方面。覆盖平台包括Web6.0/7.0、小程序、H5、鸿蒙及PC客户端。

---

## 4. 详细测试点分析

### REQ-01：多选框可点击范围优化

**前置条件：** 收件箱中存在多封邮件（含已读、未读、会话邮件）

**测试要点：**

| 场景类型 | 测试点 |
|---------|--------|
| 正常场景 | 预览模式下点击复选框扩大区域可勾选邮件 |
| 正常场景 | 列表模式下点击复选框扩大区域可勾选邮件 |
| 正常场景 | 会话模式下点击复选框扩大区域可勾选邮件 |
| 正常场景 | 勾选单个邮件，复选框状态切换正常 |
| 正常场景 | 勾选多个邮件，逐个勾选均正常 |
| 正常场景 | 全选邮件，所有邮件均被勾选 |
| 正常场景 | 鼠标hover复选框区域，显示hover效果（背景色/边框变化） |
| 异常场景 | 快速连续点击复选框，状态不紊乱 |
| 边界场景 | 邮件列表为空时，全选复选框状态正确（不可选/灰显） |
| 边界场景 | 大量邮件（>100封）时，全选性能正常 |

**兼容要求：** Chrome、Firefox、Edge、Safari；macOS/Windows

**验收标准：** 复选框可点击范围明显扩大，hover效果可见，单选/多选/全选功能正常

### REQ-05：草稿箱角标数字规则修改

**前置条件：** 账号下存在草稿（含已读和未读草稿）

**测试要点：**

| 场景类型 | 测试点 |
|---------|--------|
| 正常场景 | Web6.0草稿箱角标显示全部草稿数量（含已读+未读） |
| 正常场景 | Web7.0草稿箱角标显示全部草稿数量 |
| 正常场景 | 小程序草稿箱角标显示全部草稿数量 |
| 正常场景 | H5草稿箱角标显示全部草稿数量 |
| 正常场景 | 鸿蒙草稿箱角标显示全部草稿数量 |
| 正常场景 | 草稿箱角标不显示数字时，角标不展示 |
| 正常场景 | Web7.0拖动邮件到草稿箱时，鼠标显示禁止操作图标 |
| 边界场景 | 草稿数量为0时，角标不显示 |
| 边界场景 | 草稿数量为1时，角标显示"1" |

### REQ-06：邮件日期识别与日程提醒

**前置条件：** 邮件主题或正文中包含可识别的日期格式信息

**测试要点：**

| 场景类型 | 测试点 |
|---------|--------|
| 正常场景 | 邮件主题中含日期格式（如"3月15日"、"2024-03-15"），日期下方显示虚线 |
| 正常场景 | 邮件正文中含日期格式，日期下方显示虚线 |
| 正常场景 | 鼠标悬停日期关键字时，鼠标变为可点击状态 |
| 正常场景 | 点击日期/关键字，右侧弹出日历日程提醒侧边栏 |
| 正常场景 | 日历提醒弹窗事项默认带入邮件主题 |
| 正常场景 | 日历提醒弹窗时间默认为第二天9:00 |
| 正常场景 | 提醒方式默认为短信提醒，可切换为邮件提醒 |
| 正常场景 | 点击保存后，日程保存至日历模块，可查看 |
| 正常场景 | 设置提醒后的提醒流程与现网一致 |
| 边界场景 | 主题和正文均含日期，均识别 |
| 边界场景 | 同一邮件含多个日期，均可识别和点击 |
| 边界场景 | 邮件主题为空时，弹窗事项默认值处理 |
| 异常场景 | 日期格式为模糊描述（如"下周"、"后天"）的识别情况 |
| 异常场景 | 识别到的日期为过去日期时的处理 |
| 异常场景 | 跨天/跨月/跨年的日期格式识别（如"12月31日"、"明年1月"） |

**兼容要求：** Chrome、Firefox、Edge、Safari

**验收标准：** 邮件中日期被正确识别并标注虚线，点击可弹出日程提醒侧边栏，默认值正确，保存后可在日历查看

### REQ-07：会话邮件功能对齐及问题修复

**前置条件：** 收件箱中存在会话邮件（含多封邮件的会话）

**测试要点：**

| 场景类型 | 测试点 |
|---------|--------|
| 正常场景 | 会话邮件中【标记为】功能可用，流程与6.0一致 |
| 正常场景 | 会话邮件中【移动到】功能可用，流程与6.0一致 |
| 正常场景 | 列表页对会话标星，会话内全部邮件均标星 |
| 正常场景 | 从收件箱列表页点击进入会话列表，未读邮件不自动全部置为已读 |
| 正常场景 | 会话邮件中展开某封邮件时，该封从未读变为已读 |
| 异常场景 | 会话内含大量邮件（>20封）时，标星操作全部生效 |
| 边界场景 | 会话内仅1封邮件时，标星仅标识该封（逻辑一致） |
| 边界场景 | 部分邮件已标星状态下，列表页标星操作结果 |

**兼容要求：** Chrome、Firefox、Edge、Safari

**验收标准：** 会话邮件补齐【标记为】和【移动到】功能；标星作用于全部会话邮件；进入会话不自动全部已读

## 6. 风险评估矩阵

| 风险项 | 风险等级 | 应对策略 |
|--------|---------|---------|
| REQ-06日期正则识别准确率不足，误识别或漏识别 | 高 | 建立日期格式用例库，覆盖常见/边界/模糊格式，与开发确认正则规则 |
| REQ-07会话邮件标星/已读逻辑影响现有功能 | 高 | 回归测试会话模式全部交互，重点验证标星和已读状态一致性 |
| REQ-05多端角标逻辑不一致 | 中 | 逐端验证，建立多端对比测试checklist |
| REQ-08短信验证码安全校验与现网规则不一致 | 中 | 与安全团队对齐验证码和防火墙规则，专项测试 |
| REQ-04火狐小屏适配不充分 | 中 | 准备多分辨率测试设备/模拟器，建立分辨率测试矩阵 |
| REQ-02样式对齐在不同浏览器渲染差异 | 低 | 多浏览器截图对比测试 |
| REQ-09操作后数据加载性能问题 | 低 | 大数据量场景下性能测试 |
| REQ-10滚动条样式浏览器兼容性 | 低 | 主流浏览器滚动条样式逐一验证 |
