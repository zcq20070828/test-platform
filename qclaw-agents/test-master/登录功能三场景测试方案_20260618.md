# 登录功能测试方案 — 三场景覆盖

> 任务：验证登录功能在正常登录、密码错误、账号锁定三个场景下的表现
> 文档生成时间：2026-06-18

---

## 一、测试场景清单

| 场景 | 测试目标 | 对应需求编号 | 优先级 |
|------|---------|-------------|--------|
| 场景一：正常登录 | 使用正确的用户名和密码成功登录，并生成有效会话 | F-01 / F-04 | P0 |
| 场景二：密码错误 | 密码错误时返回安全提示，不泄露账号是否存在 | F-10 / F-09 | P0 |
| 场景三：账号锁定 | 连续多次输错密码后账号锁定，锁定期间即使密码正确也无法登录 | F-15 / F-11 / S-08 / S-09 | P0 |

## 二、场景一：正常登录

### 2.1 测试条件
- 账号已注册且状态正常（未锁定/未禁用/已激活）
- 用户名、密码正确
- 网络可达

### 2.2 操作步骤
1. 打开登录页面 / 准备登录接口请求
2. 输入正确的用户名和密码
3. 点击登录按钮 / 发送登录请求

### 2.3 预期结果
- 接口返回状态码 200，并返回有效 Token/Session
- 页面跳转至首页或用户上次访问页面
- 用户昵称、头像、角色等关键信息正确展示
- 响应时间 ≤ 2 秒（正常负载）

### 2.4 验证点
- [ ] 登录成功标识正确
- [ ] Token 有效期合理，可被后续请求使用
- [ ] 登录后页面元素正确渲染
- [ ] 登录日志记录（时间、IP、设备）

---

## 三、场景二：密码错误

### 3.1 测试条件
- 账号存在且状态正常
- 使用错误的密码（其他字符 / 大小写错误 / 旧密码）

### 3.2 操作步骤
1. 输入正确的用户名
2. 输入错误的密码
3. 提交登录请求

### 3.3 预期结果
- 登录失败，返回统一提示："用户名或密码错误"
- 不提示具体是用户名不存在还是密码错误
- 密码字段清空或保持输入（按产品策略）
- 记录登录失败次数，但不影响账号状态（未达锁定阈值）

### 3.4 验证点
- [ ] 提示信息一致，不暴露账号是否存在
- [ ] 失败计数器正确递增
- [ ] 响应不包含敏感信息（如真实密码哈希）
- [ ] 前端不会将密码明文显示在 URL 或日志中

## 四、场景三：账号锁定

### 4.1 测试条件
- 准备一个已注册测试账号
- 连续输错密码达到锁定阈值（常见：5 次）
- 锁定时间：例如 15 分钟

### 4.2 操作步骤

#### 4.2.1 触发锁定
1. 输入正确用户名
2. 连续 5 次输入错误密码并提交
3. 第 6 次输入正确密码并提交

#### 4.2.2 验证锁定生效
1. 在锁定时间内输入正确密码登录
2. 观察提示信息

#### 4.2.3 验证锁定解除
1. 等待锁定时间结束（如 15 分钟）
2. 使用正确密码再次登录

### 4.3 预期结果
- 连续 5 次输错密码后，账号进入锁定状态
- 锁定期间提示："账号已被锁定，请稍后重试/联系管理员"
- 即使输入正确密码，锁定期间也无法登录
- 锁定时间到期后，使用正确密码可正常登录
- 锁定期间失败计数不再累加或按策略处理

### 4.4 验证点
- [ ] 锁定阈值触发准确
- [ ] 锁定状态在数据库/缓存中正确记录
- [ ] 锁定期间正确密码也无法登录
- [ ] 锁定时间到期后自动解锁
- [ ] 锁定状态变更记录审计日志

## 五、执行建议

### 5.1 接口测试
- 若目标提供 HTTP 接口，建议优先用接口自动化执行，效率高、可控性强
- 需要信息：登录接口 URL、请求方法、参数格式、正常账号与错误密码、锁定阈值、锁定时间

### 5.2 UI 测试
- 若需验证前端交互，使用 Playwright/Selenium 模拟登录页面
- 需要信息：登录页面 URL、账号输入框/密码输入框/登录按钮定位方式、错误提示元素

### 5.3 测试数据
- 准备一个正常状态测试账号
- 准备若干错误密码
- 准备模拟锁定时间，必要时可通过数据库/缓存直接设置锁定状态以加速验证

---

## 六、风险与注意事项

1. **账号锁定会阻塞真实账号**：务必使用测试账号，避免影响用户
2. **密码错误次数会触发安全策略**：提前确认阈值，避免误触发生产风控
3. **验证码/二次验证**：如果登录流程包含验证码，需提前准备绕过方案或 mock 方案
4. **隐私与合规**：测试过程中不得记录或传播真实用户密码
