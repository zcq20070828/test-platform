#### 5.1.1 P0 失败用例详情

**① TC-051：HTTP 请求未自动重定向到 HTTPS**（🔴 High 严重）

| 属性 | 内容 |
|------|------|
| 用例编号 | TC-051 |
| 测试标题 | HTTP 请求自动重定向到 HTTPS |
| 优先级 | P0 |
| 对应 TP 编号 | TP-140 / TP-169 |
| 模块 | 安全测试 |
| 执行时间 | 2026-07-02 14:53:41 |
| 执行结果 | ❌ 失败 |
| 预期结果 | HTTP 请求自动重定向到 HTTPS |
| 实际结果 | HTTP 请求未自动重定向至 HTTPS，部分 HTTP 请求可能泄露敏感数据 |
| 根本原因 | Web 服务器（Nginx/Apache）未配置强制 HTTPS 重定向，导致 HTTP 协议可被直接访问 |
| 安全风险 | 协议降级（SSL Stripping）攻击风险，攻击者可在用户与服务器之间的网络链路上拦截 HTTP 请求并获取敏感信息（如登录凭证、Session Cookie） |
| 修复建议 | 在 Web 服务器配置中添加 HTTP 到 HTTPS 的强制重定向规则：<br>Nginx: `return 301 https://$host$request_uri;`<br>Apache: `Redirect permanent / https://domain.com/` |
| 影响范围 | 所有通过 HTTP 协议访问登录页面的用户 |
| 修复优先级 | **P0 — 必须在上线前修复** |

Web 服务器（Nginx/Apache）未配置 HTTP 到 HTTPS 的强制重定向规则，导致用户通过 HTTP 协议（如 `http://example.com/login`）访问登录页面时，页面以 HTTP 明文方式加载，登录表单数据虽然通过 HTTPS POST 提交，但攻击者可在用户首次访问时劫持 HTTP 请求，实施中间人攻击（Man-in-the-Middle）或 SSL Stripping 攻击。

**安全影响**：

1. **中间人攻击**：攻击者可在用户与服务器之间截获、篡改 HTTP 流量
2. **Session Cookie 劫持**：如果 Session Cookie 未正确设置 Secure 属性，非 HTTPS 连接可能泄露 Cookie
3. **凭证泄露风险**：非技术用户可能因浏览器未显示安全锁图标而误以为系统不安全
4. **合规风险**：不满足等保 2.0 对 HTTPS 全站加密的要求

**复现步骤**：

1. 在浏览器地址栏输入 `http://example.com/login`（HTTP 协议）
2. 观察页面是否在 3 秒内自动跳转到 `https://example.com/login`
3. 预期：应自动跳转；实际：页面停留在 HTTP 版本，无跳转

**修复方案**：

**Nginx 配置方案**：
```nginx
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name example.com;
    # HTTPS 配置保持不变
}
```

**Apache 配置方案**：
```apache
<VirtualHost *:80>
    ServerName example.com
    Redirect permanent / https://example.com/
</VirtualHost>
```

**同时建议设置 HSTS（HTTP Strict Transport Security）**：
```nginx
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
```

**验证方法**：

1. 修复后重新执行 TC-051，确认 HTTP 请求自动重定向到 HTTPS
2. 使用 Burp Suite 抓包，确认所有 HTTP 请求均返回 301 重定向
3. 检查响应头中是否包含 `Strict-Transport-Security` 头
