### 2.2 通用响应格式

> ⭐ 以下为推测格式，需根据实际API文档确认字段名。

**成功响应：**
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_in": 1800,
    "token_type": "Bearer"
  }
}
```

**失败响应：**
```json
{
  "code": 400,
  "message": "用户名或密码错误",
  "data": null
}
```

### 2.3 通用错误码

| 错误码 | 说明 | 可能原因 |
|--------|------|---------|
| 200 | 成功 | - |
| 400 | 请求参数错误 | 参数格式错误、缺少必填参数 |
| 401 | 未认证 | Token无效或已过期 |
| 403 | 禁止访问 | CSRF Token验证失败 |
| 404 | 接口不存在 | URL路径错误 |
| 429 | 请求过于频繁 | 触发限速 |
| 500 | 服务器内部错误 | 服务端异常 |

### 3.1 登录接口 POST /api/auth/login

#### 基本信息

| 属性 | 说明 |
|------|------|
| **接口路径** | ⭐ `/api/auth/login`（需确认） |
| **HTTP方法** | POST |
| **Content-Type** | `application/json` ⭐ |
| **是否需要认证** | 否 |
| **CSRF Token** | 部分场景需要（根据TC-08-007） |

#### 请求参数

```json
{
  "username": "testuser01",
  "password": "Test@123456",
  "captcha": "A7B2",
  "captcha_key": "uuid-xxx-xxx"
}
```

| 参数名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| `username` | string | 是 | 用户名或手机号或邮箱 | `testuser01` |
| `password` | string | 是 | 密码（明文或前端加密） | `Test@123456` |
| `captcha` | string | 条件必填 | 图片验证码（触发验证码后必填） | `A7B2` |
| `captcha_key` | string | 条件必填 | 图片验证码Key（与captcha配套） | `uuid-xxx` |
| `remember_me` | boolean | 否 | 记住登录（延长会话有效期） | `true` |

#### 正常响应

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "user_id": 10001,
    "username": "testuser01",
    "nickname": "测试用户",
    "avatar": "https://example.com/avatar/10001.png",
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expires_in": 1800,
    "token_type": "Bearer"
  }
}
```

#### 异常响应

| 场景 | code | message（示例） |
|------|------|----------------|
| 用户名为空 | 400 | `用户名不能为空` |
| 密码为空 | 400 | `密码不能为空` |
| 用户名不存在 | 401 | `用户名或密码错误`（不应提示"用户不存在"） |
| 密码错误 | 401 | `用户名或密码错误` |
| 验证码错误 | 400 | `验证码错误` |
| 验证码过期 | 400 | `验证码已过期` |
| 账号被锁定 | 401 | `账号已被锁定，请XX分钟后再试` |
| 账号已禁用 | 401 | `账号已被禁用，请联系客服` |

#### 测试用例映射

| 用例ID | 测试场景 | 测试数据 |
|--------|---------|---------|
| TC-01-001 | 正常登录 | `testuser01 / Test@123456` |
| TC-01-002 | 用户名为空 | `（空）/ Test@123456` |
| TC-01-003 | 密码为空 | `testuser01 / （空）` |
| TC-01-004 | 用户名不存在 | `notexist999 / Test@123456` |
| TC-01-005 | 密码错误 | `testuser01 / WrongPassword123` |
| TC-06-004 | 连续错误5次触发验证码 | 连续5次错误密码 |
| TC-06-005 | 连续错误10次锁定 | 连续10次错误密码 |
| TC-06-006 | 锁定账号登录 | `lockeduser / Test@123456` |
| TC-06-008 | 响应密码脱敏 | 抓包检查响应不含密码字段 |

#### Postman请求示例

```javascript
// Pre-request Script（可选：前端加密密码）
const crypto = require('crypto-js');
const password = pm.variables.get("password") || "Test@123456";
const encryptedPassword = CryptoJS.AES.encrypt(password, "PUBLIC_KEY").toString();
pm.variables.set("encrypted_password", encryptedPassword);

// 请求体
{
  "username": "{{username}}",
  "password": "{{encrypted_password}}",
  "captcha": "{{captcha}}",
  "captcha_key": "{{captcha_key}}",
  "remember_me": false
}

// Tests
pm.test("响应状态码为200", function() {
    pm.response.to.have.status(200);
});

pm.test("响应包含access_token", function() {
    var jsonData = pm.response.json();
    pm.expect(jsonData.data).to.have.property('access_token');
    pm.expect(jsonData.data.access_token).to.not.be.empty;
});

pm.test("响应不包含密码字段", function() {
    var jsonData = pm.response.json();
    pm.expect(jsonData.data).to.not.have.property('password');
    pm.expect(jsonData.data).to.not.have.property('password_hash');
});

// 存储Token供后续接口使用
if (pm.response.code === 200) {
    var jsonData = pm.response.json();
    pm.globals.set("access_token", jsonData.data.access_token);
    pm.globals.set("refresh_token", jsonData.data.refresh_token);
}
```

```json
  "code": 200,
```

| 手机号格式错误 | 400 | `请输入正确的手机号码` |
| 邮箱格式错误 | 400 | `请输入正确的邮箱地址` |

```javascript
});

// SEC-09: SQL注入检测
pm.test("SEC-09: SQL注入防护", function() {
    var jsonData = pm.response.json();
    // 如果返回200且无过滤，payload可能被执行（漏洞）
    if (pm.response.code === 200) {
        console.error("⚠️ SQL注入漏洞：恶意输入被接受");
    }
    pm.expect(pm.response.code).to.not.eql(200);
});
```

## 八、常见问题与排查

### 8.1 接口返回404

**可能原因：**
1. API Base URL配置错误
2. 接口路径不正确（区分 `/api/auth/login` vs `/auth/login`）
3. 接口未部署到测试环境

**排查步骤：**
```bash
# 1. 验证服务是否启动
curl -v http://localhost:8080/health

# 2. 验证接口路径
curl -X OPTIONS http://localhost:8080/api/auth/login

# 3. 检查接口文档确认路径
```

### 8.2 登录接口返回401但不确定原因

**排查步骤：**
1. 检查请求头 `Content-Type` 是否正确
2. 检查请求体是否为标准JSON格式（无尾部逗号）
3. 检查是否有特殊字符未URL编码
4. 检查账号是否已在测试环境注册

```javascript
// Postman Console中查看实际发送的请求
console.log(pm.request.body());
```

### 8.3 验证码发送接口返回429

**说明：** 这是正常的频率限制响应，不属于Bug。

**验证方法：**
```javascript
pm.test("频率限制正常触发", function() {
    pm.expect(pm.response.code).to.eql(429);
    var msg = pm.response.json().message;
    pm.expect(msg).to.include('频繁');
});
```

### 8.4 Token刷新接口返回过期

**可能原因：**
1. Refresh Token已过期（通常有效期7-30天）
2. 密码已被修改
3. 用户已被禁用

**排查步骤：**
1. 用用户名密码重新登录获取新Token
2. 检查数据库中用户状态
3. 检查Token有效期配置

### 8.5 第三方OAuth回调失败

**常见错误：**

| 错误类型 | 可能原因 | 解决方式 |
|---------|---------|---------|
| `redirect_uri_mismatch` | 回调URL配置不匹配 | 在开放平台修改回调URL |
| `401 invalid_client` | AppID或AppSecret错误 | 检查开放平台配置 |
| 回调无响应 | 防火墙阻止 | 检查服务器网络配置 |

**排查日志：**
```bash
# 查看OAuth回调日志
grep "oauth" /var/log/app.log | tail -50
```
