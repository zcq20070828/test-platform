| TD-08-09 | 登录接口响应 | API响应JSON中不应含password/pwd/hash等字段 | Charles/DevTools | TC-06-008 |
| TD-08-10 | 用户信息接口响应 | 用户详情接口不应返回密码字段 | Postman | TC-06-008 |
| TD-08-11 | 错误响应信息 | 不应提示"用户名不存在"（应统一为"用户名或密码错误"） | 手动检查 | TC-01-004 |

**数据构造说明：**
- 暴力破解测试需在**测试环境**中进行，严禁对生产环境操作
- JMeter脚本需配置合理的请求间隔，避免对测试服务造成过大压力
- CSRF Token需从登录页HTML中提取（通常在`<meta>`标签或隐藏字段中）
- ⭐ 需与开发确认IP限速配置（阈值、时间窗口）
- ⭐ 需与开发确认CSRF防护实现方式（Cookie-based / Token-based）

## 十、数据构造方法

### 10.1 测试账号构造

| 方法 | 说明 | 适用场景 |
|------|------|---------|
| 手动注册 | 通过注册页面手动创建测试账号 | 少量账号（<10个） |
| API批量注册 | 调用注册接口批量创建 | 大量账号需求 |
| 数据库直接插入 | 通过SQL直接向用户表插入记录 | 快速初始化测试数据 |
| 脚本生成 | 编写Python/Shell脚本批量注册 | 自动化测试环境搭建 |

**推荐脚本示例（Python伪代码）：**

```python
# 批量注册测试账号
import requests

BASE_URL = "http://test-server/api"
accounts = [
    {"username": "testuser01", "password": "Test@123456", "phone": "13800138000"},
    {"username": "testuser02", "password": "Pass@654321", "phone": "15912345678"},
    # ... 更多账号
]

for acc in accounts:
    resp = requests.post(f"{BASE_URL}/register", json=acc)
    print(f"Register {acc['username']}: {resp.status_code}")
```

### 10.4 密码样本构造规则

| 密码类型 | 构造规则 | 示例 |
|---------|---------|------|
| 合规密码 | ≥8位 + 大写 + 小写 + 数字 + 特殊字符 | `Test@123456` |
| 长度不足 | < 8位（其余合规） | `Ab@1` |
| 纯字母 | 仅大小写字母 | `abcdefgh` |
| 纯数字 | 仅数字 | `12345678` |
| 弱密码 | 来自OWASP常见弱密码列表 | `123456`, `password` |
| 特殊字符 | 含`<>/\"'`等可能触发注入的字符 | `P@ss<w0rd` |

### 10.5 手机号构造规则

| 格式 | 规则 | 示例 |
|------|------|------|
| 中国大陆手机号 | `1[3-9]XXXXXXXXX`（11位） | `13800138000` |
| 国际格式 | `+86-1[3-9]XXXXXXXXX` | `+8613800138000` |
| 错误格式 | 不符合正则`^1[3-9]\d{9}$` | `12345678901` |

### 10.6 邮箱构造规则

| 格式 | 规则 | 示例 |
|------|------|------|
| 标准邮箱 | `local@domain.tld` | `user@example.com` |
| 含点号 | 本地部分允许点号（非首尾） | `first.last@domain.com` |
| 含加号 | Gmail等支持+标签 | `user+tag@gmail.com` |
| 错误格式 | 缺少@、域名、本地部分等 | `test@`, `@domain.com` |
