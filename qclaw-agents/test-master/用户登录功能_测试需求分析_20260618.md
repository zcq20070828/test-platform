## 二、安全性需求

### 2.1 密码策略

| 编号 | 测试要点 | 优先级 |
|------|---------|--------|
| S-01 | 密码长度限制（最小8位，最大64位） | P0 |
| S-02 | 密码复杂度要求（大小写+数字+特殊字符） | P0 |
| S-03 | 密码不能与用户名相同 | P1 |
| S-04 | 密码不能为常见弱密码（123456、password等） | P1 |
| S-05 | 密码在传输过程中加密（HTTPS/TLS） | P0 |
| S-06 | 密码在数据库中加盐哈希存储（bcrypt/argon2） | P0 |
| S-07 | 修改密码时需验证旧密码 | P0 |

### 2.2 防暴力破解

| 编号 | 测试要点 | 优先级 |
|------|---------|--------|
| S-08 | 连续5次输错密码后锁定账号15分钟 | P0 |
| S-09 | 锁定期间即使密码正确也无法登录 | P0 |
| S-10 | 登录失败次数基于IP聚合限制（防分布式暴力破解） | P0 |
| S-11 | 登录接口增加图形验证码/滑块验证 | P1 |
| S-12 | 检测到异常登录行为时触发二次验证 | P1 |
| S-13 | 登录接口限流（Rate Limiting） | P0 |

### 2.3 会话管理

| 编号 | 测试要点 | 优先级 |
|------|---------|--------|
| S-14 | 会话超时自动失效（如30分钟无操作） | P0 |
| S-15 | 同一账号同时只允许一个终端登录（单点登录策略） | P1 |
| S-16 | 多设备同时登录时的策略（互踢/共存） | P1 |
| S-17 | 主动登出后Token立即失效 | P0 |
| S-18 | 修改密码后所有已有会话失效 | P0 |
| S-19 | Token采用JWT时验证签名完整性，防篡改 | P0 |
| S-20 | 会话ID不可预测，使用安全随机数生成 | P0 |
| S-21 | 登录成功后记录日志（时间、IP、设备信息） | P1 |
