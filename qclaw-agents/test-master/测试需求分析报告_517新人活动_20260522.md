## 一、测试范围与目标

### 1.1 测试范围

| 维度 | 范围说明 | 备注 |
|------|---------|------|
| **活动模块** | 模块一（免费领权益）、模块二（新人礼）、模块三（用户回馈礼）、模块四（更多精彩活动） | 四个模块全覆盖 |
| **终端覆盖** | iOS、Android、鸿蒙系统、Web端、微信小程序、支付宝小程序 | 重点：鸿蒙系统 |
| **用户类型** | 新用户（首次注册+再活跃用户）、老用户、黑名单用户、注销重注册用户 | 身份识别为核心 |
| **奖品类型** | 白银会员季卡、100G云空间年卡、支付宝红包、云朵、其他权益 | 奖品发放链路完整 |
| **关联系统** | 风控系统（自有+IDaaS）、短信通知系统、会员权益系统、存储空间系统、支付系统 | 端到端覆盖 |
| **活动周期** | 2026-05-17 ~ 2026-12-31（229天） | 长周期稳定性重点 |

### 1.2 测试目标

| 目标分类 | 具体目标 | 验收标准 |
|---------|---------|---------|
| **功能正确性** | 确保新老用户身份识别准确，权益领取链路完整，奖品发放无误 | 身份识别准确率100%，权益发放成功率≥99.9% |
| **用户区分准确性** | 100% 正确区分新用户/老用户身份，权益发放不错不漏 | 错发率=0，漏发率=0 |
| **风控有效性** | 自有风控 + IDaaS 双层风控正确拦截黑产/作弊行为 | 刷奖拦截率≥99%，误杀率≤0.1% |
| **多端一致性** | iOS/Android/鸿蒙/Web/小程序各端体验一致 | UI差异≤5%，功能一致性100% |
| **活动周期稳定性** | 跨越 7+ 个月长周期活动，系统稳定运行 | 可用性≥99.9%，无内存泄漏 |
| **安全性合规** | 防止刷奖、薅羊毛、SQL注入、XSS 等安全风险 | 安全漏洞=0（P0级） |
| **性能达标** | 高并发场景下系统响应及时，无超发 | 峰值TPS≥5000，响应时间达标 |

### 1.3 测试约束与限制

| 约束项 | 说明 |
|--------|------|
| **测试环境** | 无法完全模拟生产环境流量，压测结果需折算 |
| **测试数据** | 真实手机号/支付宝账号数量有限，部分场景需Mock |
| **第三方依赖** | IDaaS、支付宝、短信通道等外部系统测试受限于沙箱环境 |
| **时间窗口** | 活动上线时间固定（5月17日），测试时间有限 |
