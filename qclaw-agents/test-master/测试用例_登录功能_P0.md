## 一、基础登录功能测试用例

### TC-001 (对应TP-001)
**测试标题**：使用正确的用户名和密码登录

**前置条件**：
1. 系统正常运行
2. 已注册有效用户（用户名：validuser，密码：Valid@123）
3. 用户账号状态正常（未锁定、未禁用、未注销）

**测试步骤**：
1. 打开浏览器，访问登录页面
2. 在用户名输入框输入：validuser
3. 在密码输入框输入：Valid@123
4. 点击"登录"按钮
5. 观察页面跳转和行为

**测试数据**：
- 用户名：validuser（6-20位内合法用户名）
- 密码：Valid@123（8-32位，包含大写+小写+数字+特殊字符）

**预期结果**：
1. 登录成功
2. 页面跳转到系统首页或用户指定的目标页面
3. URL发生变化，符合预期（如从 /login 跳转到 /home）
4. 浏览器Cookie中正确写入Session ID

**测试类型**：功能测试

**优先级**：P0

### TC-002 (对应TP-002)
**测试标题**：登录成功后检查浏览器Cookie中Session ID

**前置条件**：
1. 系统正常运行

5. 记录Cookie名称、值、属性

**测试数据**：
- 用户名：validuser
- 密码：Valid@123

**预期结果**：
1. Cookie名称符合后端配置（如JSESSIONID、SESSION等）
2. Cookie值不为空，格式正确（通常为32位或更长字符串）
3. Set-Cookie响应头包含完整的Cookie属性（Domain、Path、Expires/Max-Age、HttpOnly、Secure等）

**测试类型**：功能测试 + 安全测试

**优先级**：P0

### TC-003 (对应TP-003)
**测试标题**：登录前后Session ID变化（Session Fixation防护）

**前置条件**：
1. 系统正常运行
2. 已注册有效用户
3. 浏览器已打开开发者工具

**测试步骤**：
1. 打开登录页面（未登录状态）
2. 按F12打开开发者工具，查看Request Headers中是否已有Cookie
3. 如果存在Cookie，记录Session ID值（Session ID Before）
4. 使用有效凭证登录
5. 登录成功后，查看Response Headers中的Set-Cookie
6. 记录登录后的Session ID值（Session ID After）
7. 对比登录前后的Session ID

**测试数据**：
- 用户名：validuser
- 密码：Valid@123

**预期结果**：
1. 登录前（如有Session ID）与登录后Session ID不同
2. 响应头中Set-Cookie的Session值与登录前不同
3. 旧的Session ID在服务器端失效

**测试类型**：安全测试

**优先级**：P0
