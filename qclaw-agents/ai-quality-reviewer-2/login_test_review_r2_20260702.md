## 详细评审意见

### ✅ 优点

1. **安全类型覆盖全面**：明确覆盖了 SQL注入、暴力破解、账号枚举、XSS、传输加密5大类安全测试，建立了安全测试专项清单，一目了然。
2. **优先级分层清晰**：P0 覆盖核心登录路径、验证码校验、失败锁定等阻断性问题；P1/P2 分层合理，符合实际测试资源分配逻辑。
3. **账号枚举防护验证到位**：LOGIN-006 和 LOGIN-030 均明确要求错误提示统一为"账号或密码错误"，不暴露账号是否存在，有效防止信息泄露。
4. **暴力破解防护测试链完整**：LOGIN-015（触发锁定）→ LOGIN-016（锁定后拒绝正确密码）→ LOGIN-017（解锁后恢复），三用例形成完整的锁定-验证-解锁验证链路。
5. **测试数据类型丰富**：涵盖了正常账号、锁定账号、未激活账号、已注销账号、多登录方式、多格式等多种数据类型，为后续接口测试和自动化提供了良好基础。
6. **图形验证码和短信验证码覆盖完整**：正确/错误/过期/频率限制均有对应用例（P0 级），覆盖率高。
7. **关联功能入口有测试**：忘记密码跳转（LOGIN-018）和注册跳转（LOGIN-019）均纳入 P0，完整覆盖了用户旅程。

### ⚠️ 需改进项

#### 🔴 安全维度（最重要）

**1. SQL注入/XSS 安全用例优先级过低（风险点）**
- LOGIN-037 和 LOGIN-038 均为 P2 级，但 SQL 注入和 XSS 属于OWASP Top 10 高危漏洞，建议提升至 P1。
- 当前仅测试了 2 种 SQL 注入 payload（`' OR '1'='1` 和 `admin'--`）和 2 种 XSS payload，建议补充：
  - SQL注入：`' OR 1=1 --`、`" OR "1"="1`、`'; DROP TABLE users; --`、UNION 注入等
  - XSS：`<img src=x onerror=alert(1)>`、`javascript:alert(1)`、编码绕过（`%3Cscript%3E`）等
- 缺少**CSRF Token**防护测试（登录请求是否携带CSRF Token）。
- 缺少**会话管理**测试：
  - 登录成功后旧Session是否正确销毁
  - Session Timeout 是否生效（闲置多久后Session失效）
  - 并发Session数量限制（同一账号最大Session数）

**2. 敏感数据传输加密（LOGIN-039）降级至 P2**
- HTTPS强制使用、密码明文传输检测属于基础安全要求，建议 P1 或更高。

**3. 缺少"异常IP登录检测"明确验收标准**
- LOGIN-036 预期结果模糊（"触发安全验证"或"发送告警"两者皆可），需明确业务策略后补测。

#### 🟡 边界值维度

**4. 验证码错误次数边界值缺失**
- LOGIN-015 明确"连续5次失败锁定"，但缺少边界测试：
  - 连续失败4次后，第5次正确密码能否登录？（N-1次边界）
  - 锁定后输入正确密码N次，锁定时间是否累加？
- 建议新增：锁定边界值专项测试用例。

**5. 手机号格式边界值不足**
- 仅测试了"正常手机号"和"未注册手机号"，缺少：
  - 11位但非有效号段（如 `00000000000`）
  - 10位手机号
  - 12位手机号
  - 含特殊字符手机号（如 `138-0013-8001`）

**6. 密码强度边界值缺失**
- 缺少密码最小长度边界测试（如密码要求至少8位，输入7位时的行为）。
- 缺少密码字符类型要求测试（大写、小写、数字、特殊字符的各类组合）。

#### 🟡 异常处理维度

**7. 服务端异常场景缺失**
- 缺少：`500 Internal Server Error` 时的用户提示（应友好提示，不暴露堆栈）。
- 缺少：数据库连接失败时的降级提示。
- 缺少：`429 Too Many Requests`（请求频率限制）的测试。

**8. 登录会话安全异常缺失**
- 缺少：Cookie 未设置 HttpOnly/Secure 标志的安全隐患检测。
- 缺少：JWT Token 在 URL 中传输（不安全）的检测。

#### 🟢 测试数据质量维度

**9. 安全攻击数据过于单一**
- SQL注入测试数据仅1种payload（`' OR '1'='1`），不足以覆盖不同数据库（MySQL/PostgreSQL/Oracle）的注入差异。
- 建议建立安全攻击向量数据矩阵，针对不同注入类型（布尔型、时间型、联合型、报错型）分别设计。

**10. 缺少测试数据版本管理说明**
- 锁定账号 `lockeduser`、未激活账号 `inactiveuser` 等特殊状态账号的创建时间和有效期未说明，实际执行时可能存在账号状态不一致的问题。
