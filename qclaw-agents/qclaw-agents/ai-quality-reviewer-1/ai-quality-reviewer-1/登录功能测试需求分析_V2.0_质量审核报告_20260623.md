#### 中等问题（扣3分）

**P1 问题 — 疲劳强度测试工具选型欠妥**

| 位置 | 问题描述 |
|------|---------|
| 3.3.3 疲劳强度测试方法 | "测试工具：JMeter + Prometheus + Grafana" |

**问题分析**：JMeter 的 WebDriver Sampler / HTTP Proxy 可用于 UI 级测试，但**不适合做长时间（4小时）UI 级持续登录测试**，原因如下：

1. 长时间 UI 自动化极易因页面元素变化（ID 变更、DOM 结构调整）导致脚本中断，缺乏自动恢复机制
2. 100 并发的 UI 级 JMeter 脚本对浏览器资源消耗巨大，测试结果受宿主机资源瓶颈影响严重
3. 工业界标准做法：接口级用 JMeter，**UI 级长时间稳定性用 Selenium Grid + 监控**

**建议修订**：将"循环登录退出"（1000次单用户）改为 Selenium 脚本执行；将"100并发4小时"改为 JMeter 接口级 + Selenium Grid 并行，区分接口性能与 UI 稳定性两个维度。

**P2 问题 — 4小时并发测试的资源隔离性未说明**

| 位置 | 问题描述 |
|------|---------|
| 2.6 疲劳强度测试，测试场景1 | "100并发持续运行4小时" |

**建议明确**：100并发是指**阶梯递增**（如从0→100逐步加压）还是**持续稳定**在100并发？两种模式验证目标不同（前者验证扩展性，后者验证稳定性）。建议补充说明或按两种场景分别设置。
