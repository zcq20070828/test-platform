## 一、需求概述

### 1.1 测试对象
用户登录功能是系统的核心认证模块，负责用户身份验证和会话管理。涵盖账号密码登录、第三方登录（微信/QQ/支付宝）、验证码登录、密码找回/重置、密码修改、会话管理及多端登录控制等子功能。

### 1.2 测试目标
验证用户登录功能的正确性、安全性、性能和用户体验，确保满足业务需求和安全标准。具体目标包括：
- 功能正确性：所有登录方式、密码管理流程在正常和异常场景下行为正确
- 安全合规性：满足 GB/T 22239-2019 等保要求及 OWASP Top 10 防护标准，同时符合 GB/T 39752-2021 认证安全专项标准
- 性能达标性：登录接口响应时间及并发能力满足预期指标
- 体验友好性：错误提示清晰、操作流程便捷

### 1.3 参考标准
- GB/T 22239-2019 信息安全技术 网络安全等级保护基本要求
- GB/T 39752-2021 信息安全技术 移动智能终端认证安全技术要求（新增）
- OWASP Top 10（2021）Web Application Security Risks
- ISO/IEC 25010:2011 软件质量模型
- 测试中台软件功能测试规范 V2.0
- 测试中台安全测试方案模板

## 三、安全策略说明（新增）

### 安全优先原则：UX与安全的冲突决策规则

> 本章节明确安全与用户体验（UX）发生冲突时的默认决策原则，用于指导测试用例设计和产品开发决策。

#### 核心原则
**安全优先原则（Security First）**：当用户体验优化与安全加固发生冲突时，**默认以安全为优先选项**，只有在满足以下条件之一时方可考虑UX优先：
1. 安全团队书面评审通过，确认无实质安全风险
2. 有可验证的补偿性安全控制措施（Compensating Controls）
3. 行业法规/合规要求明确规定了UX优先的例外场景

#### 本项目中已确认的安全优先策略（与UX权衡结论）

| # | 安全策略 | 对应UX影响 | 决策结论 | 说明 |
|---|---------|---------|---------|------|
| 1 | **登录失败提示统一化**（不区分"用户不存在"与"密码错误"） | 用户无法从提示中获知具体失败原因，UX略有下降 | **✅ 安全优先，强制执行** | 防止用户枚举攻击（User Enumeration）；即使有用户提出反馈，**不修改为差异化提示**；攻击者可批量探测有效账号 |
| 2 | 账户锁定提示不含剩余次数 | 被锁定用户无法预计解锁时间，体验模糊 | **✅ 安全优先，强制执行** | 防止攻击者通过提示信息推算剩余尝试次数 |
| 3 | 暴力破解触发验证码（5次失败） | 用户连续输错后需额外操作，体验略有摩擦 | **✅ 安全优先，强制执行** | 等效于等保2.0对认证失败控制的要求 |
| 4 | 密码强度强制要求（≥8位含大小写+数字+特殊字符） | 低安全性密码用户注册流程更长 | **✅ 安全优先，强制执行** | 防止弱密码导致账户被批量破解 |
| 5 | 禁用账户提示统一化（不暴露禁用状态） | 用户无法获知账户是否被禁用 | **✅ 安全优先，强制执行** | 防止攻击者通过"账户已禁用"提示确认有效账户M，规避账户信息泄露风险 |

#### 功能测试项3与安全测试项21的冲突说明与修正

| 项目 | V2.0（存在矛盾） | V3.0/V4.0（已修正） |
|------|----------------|----------------------|
| 功能测试项3 | 要求区分"用户不存在"与"密码错误"提示 | **修正为：安全优先——不区分，统一返回"用户名或密码错误"** |
| 安全测试项21 | 要求统一登录失败提示（不区分） | **补充说明：安全优先，避免用户枚举攻击** |
| 修正依据 | — | OWASP Authentication Cheat Sheet + GB/T 22239-2019 8.1.3.1 |

#### 其他安全vs UX场景说明

| 场景 | 安全风险 | UX影响 | 本文档立场 |
|------|---------|--------|---------|
| 记住登录时长 | Token长期有效增加被盗风险 | 用户无需频繁登录 | 平衡：默认7天，支持用户主动关闭 |

#### 4.1.2 边界值分析法

**用户名长度边界**（假设最小4位，最大32位 *示例值，需业务确认*）：
- 3位（最小-1）、4位（最小）、5位（最小+1）
- 31位（最大-1）、32位（最大）、33位（最大+1）

**密码长度边界**（假设最小8位，最大64位 *示例值，需业务确认*）：
- 7位（最小-1）、8位（最小）、9位（最小+1）
- 63位（最大-1）、64位（最大）、65位（最大+1）

**登录失败次数边界**（5次触发验证码，10次触发锁定）：
- 4次（验证码触发-1）、5次（验证码触发）、6次（验证码触发+1）
- 9次（锁定触发-1）、10次（锁定触发）、11次（锁定触发+1）

**验证码有效期边界**（5分钟）：
- 4分59秒（有效）、5分00秒（过期）
- 5分01秒（已过期，提交应失败）

**密码历史队列位置边界**（最近5次记录，队列位置0为最新）：
- 位置0（最新密码，不可设为与当前位置相同）
- 位置1（第2近的密码，历史边界内）
- 位置3（第4近的密码，历史边界中间位置）
- 位置4（最旧的历史密码——即位置4为第5近的密码，历史边界边缘）
- 位置5（超越历史长度的第6个密码，应允许重用）


#### 4.1.4 场景分析法

**正常登录场景**：
1. 用户打开登录页面
2. 输入正确的用户名和密码
3. 点击登录按钮
4. 验证登录成功，跳转到首页
5. 验证会话信息正确

**异常登录场景**：
1. 用户名不存在 → 提示"用户名或密码错误"（⚠ **统一提示，不区分具体原因**）
2. 密码错误 → 提示"用户名或密码错误"（⚠ **与上条相同提示**）
3. 账户被锁定 → 提示"账户已锁定，请30分钟后重试"
4. 账户被禁用 → 提示"登录失败，请检查账号信息或联系管理员"（⚠ **安全优先——不暴露账户禁用状态，防止攻击者确认有效账户**）
5. 网络异常 → 友好提示网络错误
6. 服务器异常 → 友好提示服务不可用

**第三方登录场景**：
1. 用户点击微信登录 → 跳转微信授权页
2. 用户同意授权 → 回调处理，匹配绑定账号
3. 已绑定 → 直接登录成功
4. 未绑定 → 引导绑定已有账号或自动注册新账号
5. 用户拒绝授权 → 返回登录页并提示

**密码找回场景**：
1. 用户点击"忘记密码"
2. 输入手机号/邮箱 → 发送验证码
3. 输入正确验证码 → 验证通过
4. 设置新密码（强度校验）→ 重置成功
5. 使用新密码登录 → 成功

### 5.5 Mock OAuth服务实现步骤（新增）

> 当第三方平台测试账号申请延迟时，使用Mock OAuth服务替代测试，确保核心登录逻辑提前验证。

**Step 2：配置应用OAuth回调地址**

```javascript
// Mock微信Token响应格式（与真实微信API格式一致）
app.get('/mock/oauth/wechat/callback', (req, res) => {
```

- Postman：在Environment中配置`{{oauth_base_url}}=http://localhost:3000/mock/oauth`

**Step 5：Mock与真实环境切换**

| RISK-04 | 性能测试不达标 | 中 | 上线时间 | 开发阶段同步进行单元级性能基线测试 | 协调DBA优化索引、协调开发优化查询 |
