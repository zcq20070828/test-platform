## 三、详细验收标准（Given-When-Then）

### T01 标准账号密码登录
```
Given 用户在登录页面
And 用户已注册账号 (username: testuser, password: Test@123)
When 用户输入正确的用户名和密码
And 点击"登录"按钮
Then 登录成功，跳转至首页
And 返回HTTP 200及有效Token
And Token包含正确的用户信息（user_id, expire_time）
```

### T02 密码错误提示
```
Given 用户在登录页面
And 用户已注册账号 (username: testuser)
When 用户输入正确用户名和错误密码
And 点击"登录"按钮
Then 返回错误提示"用户名或密码错误"
And 返回HTTP 401
And 剩余尝试次数提示（如："还剩3次尝试机会"）
And 不返回具体是用户名还是密码错误
```

### T08 登录失败锁定
```
Given 用户在登录页面
And 连续5次输入错误密码
When 第5次登录失败
Then 账号被锁定15分钟
And 返回提示"账号已锁定，请15分钟后重试"
And 锁定期间即使输入正确密码也无法登录
And 锁定时间到期后自动解锁
```

### T09 会话超时
```
Given 用户已登录成功
And 系统会话超时时间为30分钟
When 用户无操作超过30分钟后再发起请求
Then 返回HTTP 401
And 前端跳转至登录页面
And 提示"登录已过期，请重新登录"
```

### T11 手机验证码登录
```
Given 用户在登录页面选择"验证码登录"
And 用户已注册手机号 138****1234
When 用户输入手机号并点击"获取验证码"
Then 发送6位数字验证码
And 验证码5分钟内有效
And 60秒内不可重复发送

When 用户输入正确验证码并点击登录
Then 登录成功，跳转首页

When 用户输入错误验证码
Then 返回"验证码错误"
And 验证码错误3次后失效，需重新获取
```

## 四、安全测试专项

| 编号 | 测试项 | 测试方法 | 预期结果 |
|------|--------|---------|---------|
| S01 | SQL注入 | 输入 `' OR '1'='1` / `admin'--` | 登录失败，无数据泄露 |
| S02 | XSS攻击 | 输入 `<script>document.cookie</script>` | 脚本不被执行，内容被转义 |
| S03 | CSRF攻击 | 伪造跨站登录请求 | 请求被拒绝（Token校验失败） |
| S04 | 暴力破解 | 短时间大量密码尝试 | 触发锁定/限流机制 |
| S05 | 明文传输 | 抓包检查登录请求 | 密码字段加密/哈希传输 |
| S06 | Token安全 | 检查Token存储位置 | HttpOnly + Secure Cookie，非localStorage |
| S07 | 枚举防护 | 尝试不同用户名登录 | 不区分"账号不存在"和"密码错误"的提示 |
| S08 | 会话固定 | 登录后检查SessionID | 登录成功后SessionID必须更换 |
| S09 | 响应信息泄露 | 检查错误响应体 | 不含堆栈信息、数据库错误、内部IP等 |

## 八、风险识别与建议

### 🔴 高风险

1. **暴力破解风险** → 必须实现频率限制+验证码+锁定机制
2. **信息泄露风险** → 错误提示统一为"用户名或密码错误"，禁止区分用户名是否存在
3. **Token安全风险** → 必须使用HttpOnly Secure Cookie，禁止localStorage存储

### 🟡 中风险

4. **并发登录未定义策略** → 需产品明确：互踢/报错/共存？
5. **第三方登录回调安全** → OAuth state参数校验，防CSRF
6. **验证码爆破** → 限制验证码尝试次数，短时失效

### 💡 建议

- 登录接口增加限流（如同一IP 10次/分钟）
- 实现登录日志审计（时间、IP、设备、结果）
- 设计渐进式安全策略：第1-3次失败仅提示，第4-5次弹验证码，第6次起锁定
- 预留风控接口，为后续AI风控分析做准备
