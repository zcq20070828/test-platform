# 登录页面用户名输入框测试需求分析

## 1. 需求概述

### 1.1 功能描述
登录页面用户名输入框允许用户输入用户名进行身份验证，支持合法用户名的校验和非法输入的风险防护。

### 1.2 利益相关者
- **最终用户**：需要使用用户名登录系统的用户
- **业务负责人**：关注用户体验和安全性
- **技术团队**：前端开发、后端开发、测试工程师
- **安全团队**：关注SQL注入、XSS等安全风险

### 1.3 业务价值
- 确保合法用户能够正常登录
- 防止恶意用户通过非法输入攻击系统
- 提供友好的用户反馈体验

---

## 2. 功能性需求分析

### 2.1 输入规则
| 规则项 | 要求 | 说明 |
|--------|------|------|
| 字符长度 | 1-20字符 | 最小1字符，最大20字符 |
| 允许字符 | 字母、数字、下划线 | 正则：`^[a-zA-Z0-9_]+$` |
| 必填项 | 是 | 不允许为空 |
| 前后空格 | 自动trim | 提交前自动去除首尾空格 |

### 2.2 校验规则

#### 2.2.1 前端JS校验
- **实时校验**：用户输入时实时校验格式
- **提交前校验**：点击登录按钮前再次校验
- **错误提示**：在输入框下方显示红色错误提示文字
- **校验时机**：
  - onBlur（失去焦点时）
  - onChange（输入内容变化时）
  - onSubmit（表单提交时）

#### 2.2.2 后端API校验
- **接口路径**：`POST /api/login`
- **请求参数**：`{ "username": "xxx", "password": "xxx" }`
- **校验逻辑**：
  - 非空校验
  - 长度校验（1-20字符）
  - 格式校验（只允许字母、数字、下划线）
  - 特殊字符过滤/转义
- **返回结果**：
  - 成功：`{ "code": 200, "message": "登录成功", "data": { "token": "xxx" } }`
  - 失败：`{ "code": 400, "message": "用户名格式错误" }`

### 2.3 用户体验要求
- 输入框默认显示提示文字（placeholder）："请输入用户名"
- 错误提示文字颜色：红色（#FF0000）
- 错误提示出现位置：输入框正下方
- 错误提示消失时机：用户修改输入内容后自动消失

## 5. 安全风险分析

### 5.1 SQL注入风险

**风险等级**：🔴 高危

**风险描述**：
如果后端未对用户名输入进行严格的过滤和转义，攻击者可构造恶意SQL语句，绕过身份验证、窃取数据、篡改数据。

**防护措施**：
1. 使用参数化查询（Prepared Statement）或ORM框架
2. 对特殊字符进行转义（如单引号、双引号、反斜杠）
3. 使用白名单验证（只允许字母、数字、下划线）
4. 最小权限原则：数据库账号只给必要的权限
5. 错误信息不暴露数据库细节

**测试验证**：
- 尝试各种SQL注入payload，确认都被拦截
- 检查后端日志，确认没有执行恶意SQL
- 使用SQLMap等工具进行自动化扫描

### 5.2 XSS跨站脚本风险

**风险等级**：🟡 中危

**风险描述**：
如果后端未对用户名输入进行HTML转义，攻击者可注入恶意脚本，窃取用户Cookie、篡改页面内容、跳转恶意网站。

**防护措施**：
1. 对用户输入进行HTML转义（如 `<` 转义为 `&lt;`）
2. 使用Content Security Policy (CSP) 禁止内联脚本
3. 对输出到页面的数据进行转义
4. 使用HttpOnly标志保护Cookie
5. 输入验证：白名单验证 + 黑名单过滤

**测试验证**：
- 尝试各种XSS payload，确认都被转义
- 查看页面源码，确认脚本标签被转义
- 使用XSSer、BeEF等工具进行自动化测试

### 5.3 暴力破解风险

**风险等级**：🟡 中危

**风险描述**：
如果没有暴力破解防护，攻击者可编写脚本批量尝试用户名密码组合，破解用户账号。

**防护措施**：
1. 登录失败多次后显示验证码
2. 账号锁定：连续失败N次后锁定账号一段时间
3. IP限制：同一IP连续失败N次后限制访问
4. 使用验证码（如Google reCAPTCHA）
5. 多因素认证（MFA）

**测试验证**：
- 连续输入错误用户名密码，确认触发验证码或账号锁定
- 使用Burp Suite Intruder模块进行暴力破解测试

### 5.4 敏感信息泄露风险

**风险等级**：🟡 中危

**风险描述**：
如果前端JS代码、后端错误信息、日志中包含敏感信息（如数据库连接信息、接口细节），可能被攻击者利用。

**防护措施**：
1. 前端JS代码压缩混淆
2. 错误信息不暴露技术细节（如"数据库连接有误"改为"系统错误"）
3. 日志脱敏：不记录密码、Token等敏感信息
4. 定期安全审计代码

**测试验证**：
- 查看前端JS源码，确认没有敏感信息
- 触发各种错误，查看错误信息是否暴露技术细节

### 5.5 CSRF跨站请求伪造风险

**风险等级**：🟡 中危

**风险描述**：
如果没有CSRF防护，攻击者可构造恶意页面，诱导已登录用户点击，自动提交登录表单或其他敏感操作。

**防护措施**：
1. 使用CSRF Token
2. 验证Referer头
3. 使用SameSite Cookie属性
4. 关键操作需要二次确认

**测试验证**：
- 构造恶意页面，尝试自动提交登录表单
- 使用Burp Suite生成CSRF PoC，验证是否被拦截

## 6. 验收标准

### 6.1 功能验收标准

**Given-When-Then格式**：

```
验收标准1：用户名为空时不允许提交
Given 用户打开登录页面
When 用户不输入用户名，直接点击登录按钮
Then 显示错误提示"用户名不能为空"，不提交表单

验收标准2：用户名长度在1-20字符之间时允许提交
Given 用户打开登录页面
When 用户输入1-20字符的用户名，点击登录按钮
Then 前端校验通过，提交表单到后端

验收标准3：用户名超过20字符时不允许提交
Given 用户打开登录页面
When 用户输入超过20字符的用户名，点击登录按钮
Then 显示错误提示"用户名长度不能超过20字符"，不提交表单

验收标准4：用户名包含非法字符时不允许提交
Given 用户打开登录页面
When 用户输入包含特殊字符（除下划线）的用户名，点击登录按钮
Then 显示错误提示"用户名只能包含字母、数字和下划线"，不提交表单
```

### 6.2 安全验收标准

```
验收标准5：SQL注入防护
Given 用户打开登录页面
When 用户输入SQL注入语句（如 ' OR '1'='1）
Then 后端过滤/转义特殊字符，不执行恶意SQL，返回"用户名格式错误"

验收标准6：XSS防护
Given 用户打开登录页面
When 用户输入XSS脚本（如 <script>alert('xss')</script>）
Then 后端转义HTML标签，不执行脚本，返回"用户名格式错误"

验收标准7：暴力破解防护
Given 用户连续多次输入错误用户名
When 失败次数达到阈值（如5次）
Then 显示验证码或锁定账号
```

### 6.3 性能验收标准

```
验收标准8：前端JS校验响应时间
Given 用户在用户名输入框输入内容
When 触发校验（onBlur或onChange）
Then 错误提示在100ms内显示

验收标准9：后端API响应时间
Given 用户提交登录表单
When 后端接收请求
Then 在200ms内返回响应（正常网络环境下）
```
