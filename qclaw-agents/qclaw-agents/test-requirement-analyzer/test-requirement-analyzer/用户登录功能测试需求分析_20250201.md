# 用户登录功能 — 测试需求分析报告

**版本：** V1.0  
**日期：** 2025-02-01  
**分析依据：** 需求分析方法论（Requirements Analysis Skill）+ 通用测试知识库（Test Knowledge Base）  
**优先级定义（MoSCoW 模型）：**

| 级别 | 含义 | 说明 |
|------|------|------|
| **P0** | Must Have | 核心功能/安全底线，缺失则系统不可用或存在严重安全风险 |
| **P1** | Should Have | 重要功能，非核心但影响用户体验或业务完整性 |
| **P2** | Could Have | 辅助功能，增强体验，可临时降级 |
| **P3** | Won't Have (this time) | 未来考虑，当前版本可暂缓 |

## 2. 安全需求分析

### 2.1 密码安全

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-CRYPTO-001 | **HTTPS 传输**：登录请求强制使用 HTTPS 协议传输，禁止 HTTP 明文传输 | P0 | 安全 |
| S-CRYPTO-002 | **密码传输加密**：密码在传输过程中进行加密（建议 HTTPS + 前端加盐哈希处理） | P0 | 安全 |
| S-CRYPTO-003 | **密码存储加密**：服务端密码使用 bcrypt/scrypt/Argon2 等强哈希算法加盐存储，禁止明文存储 | P0 | 安全 |
| S-CRYPTO-004 | **禁止密码日志**：密码不得记录到日志文件中（包括访问日志、错误日志） | P0 | 安全 |
| S-CRYPTO-005 | **密码复杂度策略**：密码长度≥8位，需包含大小写字母、数字、特殊字符中的至少3种 | P0 | 安全 |
| S-CRYPTO-006 | **旧密码限制**：设置新密码时，禁止与最近N次历史密码相同（建议 N≥3） | P1 | 安全 |
| S-CRYPTO-007 | **默认密码修改**：系统生成的默认/初始密码强制要求用户在首次登录后修改 | P1 | 安全 |

### 2.2 暴力破解防护

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-BRUTE-001 | **登录频率限制**：同一 IP 在单位时间内登录失败超过阈值触发限流（如每分钟最多 10 次） | P0 | 安全 |
| S-BRUTE-002 | **账号锁定策略**：同一账号连续登录失败 N 次（建议 5-10 次）后锁定该账号 | P0 | 安全 |
| S-BRUTE-003 | **锁定时长**：锁定有明确时间（如 15 分钟），超时自动解锁 | P1 | 安全 |
| S-BRUTE-004 | **验证码机制**：连续失败 3 次后弹出验证码（图形/滑块/行为式验证码） | P1 | 安全 |
| S-BRUTE-005 | **验证码绕过检测**：验证码不可绕过，不可重复使用，不可被 OCR/机器学习轻易破解 | P1 | 安全 |
| S-BRUTE-006 | **IP 黑名单**：短时内大量失败请求的 IP 自动加入黑名单 | P1 | 安全 |
| S-BRUTE-007 | **分布式暴力破解**：测试使用不同 IP 对同一账号的暴力破解是否被有效拦截 | P1 | 安全 |
| S-BRUTE-008 | **递增延迟策略**：连续失败后，服务端逐步增加响应延迟时间，增加攻击者枚举成本 | P2 | 安全 |

### 2.3 注入与脚本攻击防护

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-INJECT-001 | **SQL 注入防护**：在用户名/密码输入框中注入 SQL 语句（`' OR '1'='1`、`--`等），验证是否被拦截 | P0 | 安全 |
| S-INJECT-002 | **SQL 注入盲注检测**：通过时间盲注、布尔盲注等方式探测是否存在注入点 | P1 | 安全 |
| S-INJECT-003 | **XSS 防护**：在用户名中注入 JavaScript 脚本（`<script>alert(1)</script>`），验证是否被转义 | P0 | 安全 |
| S-INJECT-004 | **存储型 XSS**：恶意脚本是否在登录失败回显中被存储并执行 | P1 | 安全 |
| S-INJECT-005 | **NoSQL 注入**：如果使用 NoSQL 数据库，验证 NoSQL 注入防护 | P1 | 安全 |
| S-INJECT-006 | **LDAP 注入检测**：如果系统集成 LDAP 认证，验证 LDAP 注入防护 | P1 | 安全 |
| S-INJECT-007 | **参数化查询**：确认所有登录相关数据库查询使用参数化查询或 ORM 预编译 | P1 | 安全 |

### 2.4 会话与请求伪造防护

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-CSRF-001 | **CSRF 防护**：登录接口具备 CSRF Token 或 SameSite Cookie 等防护机制 | P0 | 安全 |
| S-CSRF-002 | **Referer/Origin 校验**：服务端校验登录请求的 Referer/Origin 头，拒绝跨站请求 | P1 | 安全 |
| S-CSRF-003 | **会话固定攻击**：登录前后 Session ID 是否变更，防止会话固定攻击 | P1 | 安全 |
| S-CSRF-004 | **会话劫持防护**：Token 绑定 IP/User-Agent，检测异常环境变化强制重新认证 | P1 | 安全 |
| S-CSRF-005 | **重放攻击防护**：登录请求包含时间戳/Nonce 等防重放机制 | P1 | 安全 |
| S-CSRF-006 | **Cookie 安全属性**：会话 Cookie 设置 Secure、HttpOnly、SameSite 属性 | P0 | 安全 |
| S-CSRF-007 | **Token 泄露检测**：Token 不在 URL 参数中传输，不暴露于 Referer 头 | P1 | 安全 |

### 2.5 传输与数据安全

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-TRANS-001 | **HTTPS 强制跳转**：HTTP 请求自动 301/302 跳转到 HTTPS | P0 | 安全 |
| S-TRANS-002 | **HSTS 配置**：服务端返回 HSTS 响应头，强制浏览器使用 HTTPS | P1 | 安全 |
| S-TRANS-003 | **TLS 强度**：TLS 协议版本≥1.2，禁用 SSLv2/SSLv3/TLSv1.0 | P1 | 安全 |
| S-TRANS-004 | **敏感信息脱敏**：API 响应中密码字段脱敏（不返回空密码字段），用户敏感信息日志脱敏 | P0 | 安全 |
| S-TRANS-005 | **请求参数脱敏**：前端/服务端日志中，密码参数记录为 `******` 或完全排除 | P1 | 安全 |
| S-TRANS-006 | **响应头安全**：设置 X-Content-Type-Options、X-Frame-Options、X-XSS-Protection 等安全响应头 | P0 | 安全 |
| S-TRANS-007 | **登录接口限流**：登录接口配置服务端限流策略（令牌桶/漏桶算法） | P0 | 安全 |

### 2.6 API 安全

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| S-API-001 | **接口白名单**：登录接口仅在白名单域名/IP 下可访问 | P1 | 安全 |
| S-API-002 | **敏感接口保护**：找回密码、修改密码等接口需携带额外的身份验证（如原密码或验证码） | P0 | 安全 |
| S-API-003 | **枚举攻击防护**：用户名枚举防护——登录失败不区分用户名或密码错误 | P0 | 安全 |
| S-API-004 | **批量注册检测**：防止通过登录接口批量探测有效用户名的攻击 | P1 | 安全 |
| S-API-005 | **CORS 配置**：跨域资源共享配置正确，不允许任意域跨域调用登录接口 | P1 | 安全 |

## 3. 性能需求分析

### 3.1 并发处理能力

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| P-CONCUR-001 | **预估并发数**：明确系统需要支持的并发登录用户数（如 ≥ 1000 QPS） | P0 | 性能 |
| P-CONCUR-002 | **并发登录成功率**：在目标并发数下，登录成功率 ≥ 99.9% | P0 | 性能 |
| P-CONCUR-003 | **突增流量处理**：短时间内并发数突增至 2-3 倍目标值时系统是否雪崩 | P1 | 性能 |
| P-CONCUR-004 | **资源释放**：高并发登录后资源（数据库连接、线程池）是否正确释放 | P1 | 性能 |

### 3.2 响应时间

| 编号 | 测试需求点 | 优先级 | 类型 |
|------|-----------|--------|------|
| P-RESP-001 | **正常登录响应时间**：常规网络条件下，登录请求到响应 ≤ 500ms（P95） | P0 | 性能 |
