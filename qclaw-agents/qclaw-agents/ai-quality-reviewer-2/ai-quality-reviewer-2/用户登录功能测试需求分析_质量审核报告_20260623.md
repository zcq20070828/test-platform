## 三、各维度评分（满分100分）

### 3.1 完整性（25分）—— 得分：20/25

**评分依据：**

| 维度 | 覆盖情况 |
|------|---------|
| 登录方式 | ✅ 账号密码、手机验证码、OAuth、扫码、生物识别（5/5） |
| 功能测试点 | ✅ 58项，覆盖正向/逆向/边界 |
| 安全测试点 | ✅ 21项，含OAuth专项安全（S-019~S-021） |
| 边界值/等价类 | ✅ 完整覆盖用户名/密码/手机号/验证码 |
| 性能测试 | ✅ 10项，含并发/延迟/泄漏 |
| 兼容性测试 | ✅ 浏览器+OS+分辨率 |
| 风险评估 | ✅ 高/中/低三级分类 |
| 测试数据 | ✅ 正向28条+逆向17条+边界20条 |

**扣分项（-5分）：**
1. **网络切换/弱网测试缺失（-2分）**：登录流程中涉及网络状态变化的场景（如扫码轮询中断、验证码获取中切换WiFi/移动网络、OAuth回调等待时断网）均无独立测试点。
2. **UI交互/多Tab测试缺失（-2分）**：不同登录方式间的切换动画、A/B页面输入状态不互相干扰、多Tab同时登录行为均未覆盖。
3. **国际化/无障碍测试零覆盖（-1分）**：附录R-017/R-018在风险评估中提及，但无对应测试点，仅标注"P2抽检"，实际执行无保障。

---

### 3.2 准确性（25分）—— 得分：22/25

**评分依据：**

| 检查点 | 结果 |
|-------|------|
| 测试点编号连续无断号 | ✅ F-001~F-058、S-001~S-021均连续 |
| 测试数据ID编号（D-001~D-048） | ✅ 连续 |
| 边界值数值准确（最小/最大±1） | ✅ 符合规范 |
| 错误提示文案前后一致 | ✅ 正文表格与测试数据表一致 |
| P0~P2优先级逻辑合理 | ✅ 核心阻断→用户体验→次要优化 |

**扣分项（-3分）：**
1. **F-007与等价类定义存在矛盾（-2分）**：F-007描述"用户名前后有空格 → 自动trim后登录成功"，但等价类表中"首尾空格"归为无效等价类，输入`<空格>abcd<空格>`预期应为"格式错误"。两者存在冲突，需明确系统究竟是trim还是拒绝。
2. **生物识别测试点重复（-1分）**：F-055"不同设备生物识别差异处理"与F-058"设备更换后生物识别重新授权"描述高度重叠，实质为同一场景的两种表述，易导致测试用例重复。

---

### 3.3 专业性（25分）—— 得分：20/25

**优点：**
- 整体框架完整：功能/安全/性能/兼容性四维覆盖，结构清晰
- 安全测试深度好：S-019~S-021覆盖OAuth专项攻击面（redirect_uri绕过、state缺失CSRF、code重放）
- 风险评估有缓解措施对应：每个R-XXX均有对应措施，不是空谈
- 测试数据覆盖全面：含账号锁定边界（D-047/D-048）、已使用验证码等专项数据

**扣分项（-5分）：**
1. **优先级体系内部不一致（-2分）**：测试点使用P0/P1/P2三级，附录B缺陷严重性使用P0~P3四级，易导致执行人员困惑（"P1缺陷"对应哪个P1？）。建议统一为同一体系。
2. **生物识别安全测试不够深入（-2分）**：生物识别安全测试仅F-052/F-053，缺乏活体检测（3D面具、屏幕翻拍）测试，生物特征模板迁移/重放攻击未覆盖。
3. **会话管理测试深度不足（-1分）**：Token刷新/过期、Refresh Token旋转、登出后Token是否立即失效等场景未覆盖。

---

### 3.4 可执行性（25分）—— 得分：22/25

**优点：**
- 测试点格式统一：编号、测试点名称、预期结果、优先级四要素完整
- 测试数据可落地：D-001~D-048可直接用于用例设计，无歧义
- 边界值可直接转化为测试数据，无需二次推导
- 优先级清晰，可直接指导测试排期

**扣分项（-3分）：**
1. **部分测试点缺乏前置条件说明（-1分）**：如F-024"验证码输入错误3次"的测试，前提是同一验证码连续输错3次还是累计3次？未明确。
2. **扫码登录测试点部分描述模糊（-1分）**：F-045"同一二维码多人扫码"中"已被扫描"的提示是PC端展示还是手机端展示？归属哪一端未说明。
3. **性能指标缺少说明文档引用（-1分）**：P-001~P-010的性能指标（≤2s/≤3s等）无出处，部分指标可能依赖具体系统SLA，建议标注来源或"参照SLA定义"。

## 五、改进建议（按优先级）

### 🔴 P0（建议立即补充）

1. **补充网络切换/弱网场景测试点**
   - 新增测试点：F-059~F-062（建议）
     - F-059：WiFi切换到移动网络过程中发起登录（手机端）
     - F-060：登录过程中网络中断→恢复后重试流程
     - F-061：扫码登录轮询过程中网络中断→恢复后扫码有效性
     - F-062：OAuth授权回调等待期间断网→返回后重试

2. **明确F-007空格处理策略**
   - "前后空格自动trim"与等价类"首尾空格为无效"二选一统一，建议采用"提示去除空格"而非静默trim（更安全）

### 🟡 P1（建议本轮迭代补充）

3. **统一优先级与缺陷严重性体系**
   - 将附录B缺陷严重性（P0~P3）统一为P0~P2，或将测试点优先级改为Block/Major/Minor/Cosmetic

4. **补充生物识别活体检测安全测试**
   - 新增测试点：F-059：使用高清打印照片/屏幕翻拍尝试骗过Face ID → 应拒绝

5. **补充会话Token管理测试点**
   - 新增测试点：登录后Token过期自动刷新、Refresh Token旋转、登出后Token立即失效

6. **F-055与F-058合并或明确区分**
   - 两者描述重叠，建议明确：一个覆盖"同设备换账号"场景，一个覆盖"换设备"场景

### 🟢 P2（建议后续版本补充）

7. **补充UI交互测试点**
   - 登录方式切换动画、输入框焦点状态、多Tab并发登录行为

8. **性能指标补充来源说明**
   - 标注"参照系统SLA定义"或具体数值来源

9. **国际化/无障碍测试点**
   - 虽然标注P2抽检，建议至少补充1~2个代表性测试点
