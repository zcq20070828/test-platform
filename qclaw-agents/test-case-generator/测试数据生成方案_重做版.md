## 一、数据生成目标

为用户登录功能测试用例提供**安全、规范、可执行**的测试数据集，确保：

1. **数据安全性**：敏感信息已脱敏处理
2. **数据完整性**：覆盖所有测试场景
3. **数据可追溯**：每条数据有唯一标识和用途说明
4. **数据规范性**：符合测试数据管理标准

---

## 二、数据脱敏策略

### 2.1 脱敏原则

| 数据类型 | 脱敏方法 | 示例 |
|---------|---------|------|
| **邮箱地址** | 使用测试域名 + 编号 | `test_user_001@test.example.com` |
| **密码** | 使用固定测试密码（明文标注） | `TestPass@123` |
| **IP地址** | 使用内网地址或掩码 | `192.168.1.***` |
| **用户ID** | 使用UUID或编号 | `USER_001` |
| **时间戳** | 使用相对时间或占位符 | `2025-01-22T10:00:00Z` |

### 2.2 测试环境隔离

**重要声明**：
- 所有测试数据仅用于**测试环境**
- 测试环境与生产环境**完全隔离**
- 测试数据**禁止**用于真实业务
- 测试完成后需**清理**测试数据

## 四、数据使用规范

### 4.1 数据准备流程

```
1. 创建测试环境数据库
2. 执行数据初始化脚本
3. 验证数据完整性
4. 执行测试用例
5. 清理测试数据
6. 恢复测试环境
```

### 4.2 数据管理要求

| 要求项 | 具体措施 |
|--------|---------|
| **访问控制** | 测试数据仅限测试团队访问 |
| **版本管理** | 数据脚本纳入版本控制 |
| **定期清理** | 每周清理过期测试数据 |
| **审计日志** | 记录数据创建、修改、删除操作 |

### 4.3 数据生命周期

```
创建 → 使用 → 归档 → 销毁
 ↓      ↓      ↓      ↓
验证   测试   备份   删除
```

## 五、数据生成脚本（示例）

### 5.1 初始化脚本

```sql
-- 测试用户数据初始化
-- 环境：测试环境
-- 警告：禁止在生产环境执行

INSERT INTO users (user_id, email, password_hash, status, created_at)
VALUES
('USER_001', 'test_user_001@test.example.com', '$2a$10$encrypted_hash_here', 'active', NOW()),
('USER_002', 'test_user_002@test.example.com', '$2a$10$encrypted_hash_here', 'active', NOW()),
('USER_003', 'test_user_003@test.example.com', '$2a$10$encrypted_hash_here', 'active', NOW());

-- 失败次数初始化
INSERT INTO login_attempts (user_id, attempt_count, last_attempt_at)
VALUES
('USER_001', 0, NULL);
```

### 5.2 清理脚本

```sql
-- 测试数据清理
-- 环境：测试环境
-- 警告：仅用于测试环境

DELETE FROM login_attempts WHERE user_id LIKE 'USER_%';
DELETE FROM users WHERE email LIKE '%@test.example.com';
DELETE FROM sessions WHERE user_id LIKE 'USER_%';
```

## 七、风险评估与缓解措施

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 测试数据泄露 | 中 | 使用脱敏数据，定期更换密码 |
| 误用于生产环境 | 高 | 脚本包含环境检查，禁止生产执行 |
| 数据污染 | 中 | 测试后执行清理脚本 |
| 并发数据竞争 | 低 | 使用独立测试账号 |
