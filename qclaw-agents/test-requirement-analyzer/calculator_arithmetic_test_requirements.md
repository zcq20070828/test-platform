## 2. 需求背景与范围界定

### 2.1 问题陈述

基础计算器需提供可靠的四则运算能力，作为核心用户交互功能。当前需明确各项运算的功能边界、输入输出规范、异常场景处理和UI交互要素，以保障功能质量和用户体验。

### 2.2 范围内

- 两个操作数的二元四则运算（加法、减法、乘法、除法）
- 整数与小数运算
- 单步运算（不包含连续运算的运算符优先级链式计算）
- 显示屏输入输出交互
- 按钮点击/键盘输入交互
- 错误状态提示与恢复
- 连续运算（前一步结果作为下一步输入）

### 2.3 范围外

- 科学计算功能（三角函数、对数、指数等）
- 括号分组运算
- 运算历史记录
- 计算器主题/换肤
- 多语言本地化（除数字格式外）
- 百分比计算
- 取模运算

## 4. EPIC → 需求 → 用户故事

### EPIC-1：四则运算核心逻辑

#### 需求 1.1：加法运算（ADD）

**用户故事**  
US-ADD-01：作为用户，我希望输入两个数字并执行加法，能获得准确的求和结果。  
US-ADD-02：作为用户，我希望支持小数加法，结果精度合理。  
US-ADD-03：作为用户，我希望多次连续加法能正确累积。

#### 需求 1.2：减法运算（SUB）

**用户故事**  
US-SUB-01：作为用户，我希望输入两个数字并执行减法，能获得准确的差。  
US-SUB-02：作为用户，我希望支持结果为负数的情况。  
US-SUB-03：作为用户，我希望大数减小数和小数减大数都能正确处理。

#### 需求 1.3：乘法运算（MUL）

**用户故事**  
US-MUL-01：作为用户，我希望输入两个数字并执行乘法，能获得准确的积。  
US-MUL-02：作为用户，我希望支持含小数的乘法。  
US-MUL-03：作为用户，我希望任意数乘以 0 结果为 0。

#### 需求 1.4：除法运算（DIV）

**用户故事**  
US-DIV-01：作为用户，我希望输入两个数字并执行除法，能获得准确的商。  
US-DIV-02：作为用户，我希望除法结果显示至合理精度（如小数点后 10 位）。  
US-DIV-03：作为用户，我希望任何数除以 1 结果保持不变。  
US-DIV-04：作为用户，我希望 0 除以任何非零数结果为 0。

---

### EPIC-2：异常处理与边界场景

#### 需求 2.1：除零保护

**用户故事**  
US-ERR-01：作为用户，当我试图用 0 作除数时，我希望看到明确的错误提示而非崩溃。  
US-ERR-02：作为用户，我希望触发除零错误后能够一键清除并恢复正常操作。

#### 需求 2.2：溢出处理

**用户故事**  
US-ERR-03：作为用户，当运算结果超出显示范围时，我希望看到"溢出"或科学计数法提示。  
US-ERR-04：作为用户，当输入数字超长时，我希望输入被截断或收到提示。

#### 需求 2.3：非法输入防护

**用户故事**  
US-ERR-05：作为用户，我不允许在数字中重复输入小数点。  
US-ERR-06：作为用户，当输入不完整的表达式时（如只有一个操作数），按等号不应崩溃。  
US-ERR-07：作为用户，当我连续按运算符时，应以最后一次按下的运算符为准。

#### 需求 2.4：精度处理

**用户故事**  
US-ERR-08：作为用户，我希望浮点运算结果尽量精确，避免明显的精度丢失（如 0.1+0.2=0.3）。  
US-ERR-09：作为用户，我希望了解当前计算器的最大显示精度（如 10 位有效数字）。

#### 需求 3.1：等号（=）行为

## 7. 边界条件分析

### 7.1 输入数值边界

| 边界类型 | 边界值 | 测试要点 |
|----------|--------|---------|
| 整数最小值 | 0 和 1 | 0 参与运算的各类场景 |
| 整数最大值 | 显示位数上限（如 15 位数字：999999999999999） | 最大数加法/乘法是否溢出 |
| 负数 | -1、-100、-(最大数) | 负数的各类运算组合 |
| 小数最小正数 | 0.0000000001 | 极小数值参与运算的精度 |
| 小数精度 | 小数点后 10 位及以上 | 截断或四舍五入策略 |

### 7.2 运算结果边界

| 边界类型 | 场景 | 预期 |
|----------|------|------|
| 结果 = 0 | 减法：5 - 5 = 0 | 显示 "0" |
| 结果 > 0 | 加法取正 | 正数显示 |
| 结果 < 0 | 减法的负数结果 | 带负号显示 |
| 结果 → ±∞ | 溢出场景 | 溢出提示 |
| 结果 → 0⁺ | 极小正数除法 | 精度控制 |
| 结果恰好整数 | 整除场景 | 不显示多余小数位 |
| 结果是循环小数 | 1 ÷ 3 = 0.333... | 截断或显示有限位数 |

### 7.3 输入操作边界

| 操作序列 | 测试场景 | 预期 |
|----------|----------|------|
| 快速连续按键 | 极快点击数字和运算符 | 输入不丢失、不紊乱 |
| 运算符重复 | 5 + + + + 3 = | 视为 5 + 3 = 8 |
| 等号前无第二操作数 | 5 + = | 视为 5 + 5 = 10 |
| 等号后直接按数字 | 10 + 5 = → 输入 3 | 开始新输入，结果变为 3 |
| 运算结束再按运算符 | 20 - 5 = → + | 结果 15 作为新起始值 |
| 多小数点输入 | 1.2.3 | 第二个小数点被忽略 |
| 前导多个0 | 0 0 0 5 | 显示 "5" |

## 8. 风险评估

| 风险ID | 风险描述 | 严重程度 | 概率 | 缓解措施 |
|--------|---------|---------|------|---------|
| RISK-01 | 浮点精度问题导致结果有微小偏差 | 中 | 高 | 使用十进制运算库或适当精度截断；测试覆盖 0.1+0.2 等经典场景 |
| RISK-02 | 除零导致应用崩溃/白屏 | 致命 | 中 | 在运算层前置检查除数是否为 0，返回错误状态而非执行运算 |
| RISK-03 | 超大数值溢出导致显示异常或结果错误 | 高 | 中 | 限制最大显示位数；溢出时转为科学计数法 |
| RISK-04 | 连续快速按键导致状态机错乱 | 高 | 中 | 状态机设计防御式，每个按键事件独立处理 |
| RISK-05 | 连续运算状态丢失（如按运算符后按清除再按等号） | 中 | 低 | 清晰的运算状态分离（current/previous/operator） |
| RISK-06 | 负号和小数点组合操作时序问题 | 中 | 低 | 测试覆盖：先输入负号再输小数、先小数再负号等 |
| RISK-07 | 跨平台数字格式差异（如 1,000 vs 1000） | 中 | 中 | 内部统一使用无千分位分隔格式；显示时可选加分隔符 |
| RISK-08 | 显示屏单行状态信息过载 | 低 | 低 | 保证主数据优先显示，辅助状态信息使用小字辅助行 |

## 10. AI可执行范围 vs 人工必须覆盖范围

### ✅ AI 可自动覆盖的测试范围

| 测试类型 | 说明 |
|----------|------|
| 等价类划分测试 | 四则运算各等价类的自动化用例生成与执行 |
| 边界值测试 | 数值边界、操作边界的自动化验证 |
| 基础四则运算功能验证 | 各运算组合的正确性断言 |
| 除零异常检测 | 除零时错误提示验证 |
| 连续运算逻辑 | 状态机转换的正确性 |
| UI布局检查 | 按钮存在性、位置、标签文字 |

### ⚠️ 人工必须覆盖的测试范围

| 测试类型 | 说明 | 原因 |
|----------|------|------|
| **跨平台兼容性测试** | 不同操作系统/浏览器/分辨率下的显示效果 | UI 渲染因平台而异 |
| **触控交互测试** | 触摸屏上的点击精度、滑动误触、多点触控 | 模拟器无法完全模拟真实触感 |
| **浮点精度验收** | 业务层对精度的要求判断（如金融场景） | 精度需求需人工裁决 |
| **用户体验评审** | 按钮大小是否舒适、颜色是否可识别、反馈是否及时 | 主观体验依赖人类判断 |
| **无障碍测试** | 屏幕阅读器兼容性、键盘 Tab 导航、高对比度模式 | 需要人工操作辅助工具验证 |
| **边缘场景探索性测试** | 极速连击、混合快捷键、中断恢复（如来电/通知） | 复杂交互序列需人脑探索 |
| **视觉回归测试** | 不同主题/字体/缩放比例下的显示完整性 | 需要人工比对截图差异 |
| **合规性验证** | 特定行业（如金融）对计算精度的合规要求 | 合规结果需人工签署 |

## 11. 测试策略建议

### 11.1 测试层级

```
单元测试（运算逻辑）      →  自动化，覆盖率 ≥ 95%
├── 集成测试（状态机）    →  自动化，覆盖率 ≥ 90%
├── UI 测试（组件交互）   →  自动化（AI 可执行）+ 人工补充
└── E2E 测试（完整流程）  →  手工 + 探索性测试
```

### 11.2 推荐测试工具与框架

| 测试层级 | 推荐工具 |
|----------|---------|
| 单元测试 | Jest / JUnit / pytest |
| 集成测试 | 同单元测试框架 + 状态机 DSL |
| UI 自动化 | Playwright / Cypress / Appium |
| 探索性测试 | 人工 + 测试检查清单 |
| 浮点精度 | 使用 BigNumber 类库（如 decimal.js） |

### 11.3 建议测试轮次

| 轮次 | 范围 | 执行者 |
|------|------|--------|
| Round 1 | Smoke: 四则运算主流程 + 除零 | AI 自动化 |
| Round 2 | 边界值 + 等价类全覆盖 | AI 自动化 |
| Round 3 | 连续运算状态机 + 清除逻辑 | AI 自动化 |
| Round 4 | UI 交互 + 显示格式化 | AI + 人工 |
| Round 5 | 探索性测试 + 跨平台兼容 + 无障碍 | 人工 |
| Round 6 | 回归测试 | AI 自动化 |

## 12. 附录：UI交互要素规格

### 12.1 按钮布局（标准布局）

```
┌─────┬─────┬─────┬─────┐
│  C  │ CE  │  ←  │  ÷  │
├─────┼─────┼─────┼─────┤
│  7  │  8  │  9  │  ×  │
├─────┼─────┼─────┼─────┤
│  4  │  5  │  6  │  -  │
├─────┼─────┼─────┼─────┤
│  1  │  2  │  3  │  +  │
├─────┼─────┼─────┼─────┤
│ +/- │  0  │  .  │  =  │
└─────┴─────┴─────┴─────┘
```

### 12.2 按键类型与样式

| 类型 | 按钮 | 推荐样式 |
|------|------|---------|
| 数字键 | 0-9, . | 浅色背景，深色文字，圆形或圆角方形 |
| 运算符 | +, -, ×, ÷ | 深色背景（如橙/蓝），白色文字 |
| 功能键 | C, CE, ←, +/- | 灰色背景，深色文字 |
| 等号键 | = | 与运算符同色但稍大，突出显示 |

### 12.3 显示屏规格

| 要素 | 规格 |
|------|------|
| 显示对齐 | 右对齐 |
| 最大位数 | 15 位（含负号和小数点） |
| 超长处理 | 数字过长时自动缩小字号；无法缩小时科学计数法 |
| 精度显示 | 浮点结果最多显示 10 位小数，末尾 0 不显示 |
| 错误显示 | 居中显示 "Error" 或 "不能除以 0" |

### 12.4 反馈规范

| 事件 | 视觉反馈 | 说明 |
|------|---------|------|
| 按键按下 | 按钮缩放至 95% + 背景色加深 | 持续 100ms |
| 按键释放 | 恢复原始大小和颜色 | — |
| 非法操作 | 屏幕闪烁/抖动 + 错误信息 | 持续 200ms |
| 等号运算完成 | 等号按钮短暂高亮 + 结果显示 | 高亮持续 150ms |
| 错误状态 | 全屏闪烁红色边框 + 错误提示 | 需用户干预才能消除 |
