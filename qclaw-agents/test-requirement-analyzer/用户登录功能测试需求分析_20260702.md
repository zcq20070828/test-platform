## 1. 功能需求分析

### 1.1 核心业务流程

用户登录功能的典型业务流程如下：

```
用户访问登录页面 → 输入用户名和密码 → (可选)输入验证码 → 提交登录
→ 系统验证用户身份 → 返回登录结果
→ 成功：创建会话，跳转首页/原请求页面
→ 失败：提示错误信息，允许重新登录
```

**关键业务规则**：
- 用户必须提供有效的身份凭证（用户名/手机号/邮箱 + 密码）
- 系统需要验证凭证的正确性
- 登录成功后创建会话（Session/Token），用于后续请求的身份识别
- 登录失败应提供明确的错误提示，但不能泄露敏感信息
- 支持验证码机制防止自动化攻击

### 1.2 输入项识别

| 输入项 | 数据类型 | 长度限制 | 必填 | 格式要求 | 说明 |
|--------|---------|---------|------|---------|------|
| 用户名 | String | 4-50字符 | 是 | 字母开头，支持字母、数字、下划线 | 也可以是手机号或邮箱 |
| 密码 | String | 6-20字符 | 是 | 包含字母和数字，区分大小写 | 需要加密传输 |
| 验证码 | String | 4-6字符 | 条件必填 | 字母数字组合，不区分大小写 | 连续失败N次后显示 |
| 记住我 | Boolean | - | 否 | true/false | 延长会话有效期 |
| 设备信息 | String | - | 自动获取 | User-Agent、设备ID | 用于安全审计 |

### 1.3 输出项识别

| 输出项 | 数据类型 | 成功场景 | 失败场景 | 说明 |
|--------|---------|---------|---------|------|
| HTTP状态码 | Number | 200 | 400/401/403 | 标准HTTP响应码 |
| 响应消息 | String | "登录成功" | 具体错误提示 | 用户可见的提示信息 |
| 认证Token | String | JWT/SessionID | null | 用于后续请求的身份凭证 |
| 用户信息 | Object | 用户基本信息 | null | 用户ID、昵称、角色等 |
| 过期时间 | Timestamp | Token过期时间 | null | 会话有效期 |
| 跳转URL | String | 首页/原请求页面 | null | 登录成功后的目标页面 |

## 2. 测试范围界定

### 2.1 功能测试范围

#### ✅ 包含范围
- 正常登录流程测试（各种有效凭证组合）
- 异常登录流程测试（错误凭证、格式错误、空值等）
- 验证码功能测试（显示条件、验证逻辑、刷新机制）
- 记住我功能测试（会话延长逻辑）
- 多设备登录测试（同一账号不同设备登录）
- 退出登录功能测试
- 密码找回入口测试
- 登录状态保持测试（会话超时、Token刷新）

#### ❌ 不包含范围
- 用户注册功能（独立模块）
- 密码找回流程（独立模块）
- 第三方登录（OAuth/SSO等，需单独测试）
- 用户信息修改功能
- 权限管理功能

### 2.2 非功能测试范围

| 类型 | 测试范围 | 测试目标 |
|------|---------|---------|

| | 并发登录能力 | 支持100+并发用户同时登录 |
| | 高峰期压力测试 | 模拟早晚高峰登录场景 |
| **安全测试** | SQL注入防护 | 参数中注入SQL语句 |
| | XSS跨站脚本 | 输入框注入恶意脚本 |
| | CSRF跨站请求伪造 | 伪造登录请求 |
| | 暴力破解防护 | 密码错误锁定机制 |
| | 敏感数据传输 | 密码加密传输（HTTPS） |
| | 会话安全 | Token/Session有效期管理 |
| **兼容性测试** | 浏览器兼容性 | Chrome、Firefox、Safari、Edge |
| | 移动端适配 | iOS Safari、Android Chrome |
| | 操作系统 | Windows、macOS、Linux |
| **易用性测试** | 界面友好性 | 提示信息清晰、布局合理 |
| | 操作便捷性 | Tab键切换、回车提交 |
| | 可访问性 | 支持屏幕阅读器 |

### 3.3 安全场景

| 编号 | 场景描述 | 测试方法 | 预期结果 |
|------|---------|---------|---------|
| TC-SEC-001 | SQL注入攻击 | 输入 `' OR '1'='1`、`admin'--` 等 | 登录失败，不执行注入语句 |
| TC-SEC-002 | XSS攻击 | 输入 `<script>alert(1)</script>` | 脚本被转义或不执行 |
| TC-SEC-003 | CSRF攻击 | 伪造跨站登录请求 | 请求被拒绝，提示来源不合法 |
| TC-SEC-004 | 暴力破解 | 工具连续尝试密码 | N次错误后锁定或要求验证码 |
| TC-SEC-005 | 明文密码传输 | 抓包查看请求 | 密码已加密（如RSA/AES） |
| TC-SEC-006 | 会话劫持 | 复制他人Token访问 | Token与设备/IP绑定，访问失败 |
| TC-SEC-007 | 会话超时 | 登录后等待超时时间 | 自动退出，需重新登录 |
| TC-SEC-008 | Token泄露 | 获取他人Token | Token有设备绑定或时效限制 |
| TC-SEC-009 | 重复提交 | 快速多次点击登录按钮 | 只处理一次请求 |
| TC-SEC-010 | 重放攻击 | 截获请求重复发送 | 时间戳或Nonce验证，拒绝请求 |
| TC-SEC-011 | 弱密码检测 | 使用"123456"、"password"等 | 系统提示密码强度不足 |
| TC-SEC-012 | 敏感信息泄露 | 查看响应、日志、错误提示 | 不显示密码、SQL语句等敏感信息 |
