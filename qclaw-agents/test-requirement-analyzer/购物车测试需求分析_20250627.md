## 一、需求背景与范围界定

### 1.1 业务背景
购物车模块是电商平台的核心交易链路节点，承载商品选购、数量调整、订单确认等关键用户操作，直接影响用户下单转化率和客单价。

### 1.2 功能范围
| 范围类型 | 内容 |
|---------|------|
| **纳入范围** | 添加商品、数量修改、删除商品、结算下单 |
| **不纳入** | 商品搜索、收藏夹、价格计算规则（促销活动另计） |

### 1.3 利益相关者
| 角色 | 关注点 |
|------|--------|
| 买家 | 操作便捷、价格准确、下单流畅 |
| 商家 | 库存准确、订单有效、避免超卖 |
| 运营 | 促销规则生效、转化率监控 |
| 技术 | 高并发处理、数据一致性 |

## 二、功能点拆解（EPIC → 需求 → 用户故事）

### EPIC-001：购物车核心功能

---

#### 需求-001：添加商品

| 用户故事 | 描述 |
|---------|------|
| US-001-01 | 作为买家，我希望将商品加入购物车，以便后续统一结算 |
| US-001-02 | 作为买家，我希望查看购物车商品列表，以便确认选购商品 |
| US-001-03 | 作为买家，我希望看到商品价格实时更新，以便了解总价变化 |

**验收标准（Given-When-Then）：**

```
AC-001-01: 商品正确加入购物车
  Given 用户已登录，商品A库存充足且未下架
  When 用户点击"加入购物车"按钮
  Then 购物车数量+1，显示"添加成功"提示

AC-001-02: 数量累计正确
  Given 用户已将商品A（数量1）加入购物车
  When 用户再次添加同一商品A（数量1）
  Then 购物车中商品A数量显示为2，总价=单价×2

AC-001-03: 价格实时更新
  Given 购物车中已有商品A（单价100元）
  When 商品A价格变更为80元
  Then 购物车中商品A单价显示为80元，总价同步更新

AC-001-04: 已售罄商品不可添加
  Given 商品B库存为0或已下架
  When 用户点击"加入购物车"
  Then 显示"商品已售罄/已下架"提示，按钮置灰
```

#### 需求-002：修改数量

| 用户故事 | 描述 |
|---------|------|
| US-002-01 | 作为买家，我希望增加商品数量，以便一次性购买多件 |
| US-002-02 | 作为买家，我希望减少商品数量，以便调整购买量 |
| US-002-03 | 作为买家，我希望直接输入数量，以便精确指定购买量 |
| US-002-04 | 作为买家，我希望库存不足时获得提示，以便及时调整 |

**验收标准（Given-When-Then）：**

```
AC-002-01: 数量增加
  Given 购物车中商品A数量为1，库存为10
  When 用户点击"+"按钮
  Then 商品A数量变为2，总价=单价×2

AC-002-02: 数量减少
  Given 购物车中商品A数量为3
  When 用户点击"-"按钮
  Then 商品A数量变为2，总价=单价×2

AC-002-03: 数量下限为1
  Given 购物车中商品A数量为1
  When 用户点击"-"按钮
  Then 数量保持为1，"-"按钮置灰

AC-002-04: 库存上限校验
  Given 购物车中商品A数量为1，商品库存为5
  When 用户将数量修改为6
  Then 提示"库存不足，当前剩余5件"，数量保持不变

AC-002-05: 价格联动
  Given 购物车中商品A数量为2（单价50元）
  When 用户将数量改为3
  Then 总价从100元更新为150元
```

#### 需求-003：删除商品

| 用户故事 | 描述 |
|---------|------|
| US-003-01 | 作为买家，我希望删除单个商品，以便移除不需要的商品 |
| US-003-02 | 作为买家，我希望清空购物车，以便重新选择商品 |
| US-003-03 | 作为买家，我希望删除前有确认提示，以免误操作 |

**验收标准（Given-When-Then）：**

```
AC-003-01: 单条删除
  Given 购物车中有商品A和商品B
  When 用户点击商品A的删除按钮
  Then 商品A从列表移除，商品B保留，购物车数量更新

AC-003-02: 清空购物车
  Given 购物车中有多个商品
  When 用户点击"清空购物车"并确认
  Then 所有商品移除，购物车显示为空

AC-003-03: 删除确认弹窗
  Given 购物车中有商品
  When 用户点击"清空购物车"
  Then 弹出确认弹窗"确定清空购物车？"，点击确认执行清空，点击取消返回

AC-003-04: 误删恢复（可选）
  Given 用户刚删除商品A
  When 30分钟内点击"撤销"
  Then 商品A恢复至购物车原位置
```

#### 需求-004：结算下单

| 用户故事 | 描述 |
|---------|------|
| US-004-01 | 作为买家，我希望查看订单信息汇总，以便确认购买内容 |
| US-004-02 | 作为买家，我希望选择收货地址，以便指定配送位置 |
| US-004-03 | 作为买家，我希望使用优惠码，以便享受促销活动 |
| US-004-04 | 作为买家，我希望进入支付页面，以便完成付款 |

**验收标准（Given-When-Then）：**

```
AC-004-01: 订单信息汇总
  Given 购物车中有商品A×2（100元）、商品B×1（50元）
  When 用户点击"去结算"
  Then 显示订单汇总：商品件数3件，商品总价250元

AC-004-02: 地址选择
  Given 用户有多个收货地址
  When 用户在结算页选择地址B
  Then 订单配送地址更新为地址B

AC-004-03: 默认地址
  Given 用户未选择地址，但已设置默认地址
  When 用户进入结算页
  Then 默认地址自动选中

AC-004-04: 地址为空拦截
  Given 用户未添加任何收货地址
  When 用户点击"去结算"
  Then 提示"请先添加收货地址"，跳转地址添加页

AC-004-05: 优惠码应用
  Given 订单原价100元，用户有满100减10优惠码
  When 用户输入优惠码并点击"使用"
  Then 优惠金额显示10元，实付金额=90元

AC-004-06: 优惠码无效提示
  Given 用户输入无效优惠码"ABC123"
  When 点击"使用"
  Then 提示"优惠码不存在或已过期"

AC-004-07: 支付入口跳转
  Given 订单信息完整（地址+商品+金额）
  When 用户点击"提交订单"
  Then 跳转至支付页面，显示待支付金额
```

## 三、优先级排序（MoSCoW）

| 优先级 | 功能点 | 说明 |
|-------|--------|------|
| **Must（必须有）** | 商品加入购物车、数量修改、订单汇总、去结算跳转 | 核心链路 |
| **Must（必须有）** | 单条删除、库存校验 | 防超卖 |
| **Should（应该有）** | 清空购物车、确认弹窗、地址选择 | 重要体验 |
| **Should（应该有）** | 价格联动更新、优惠码 | 业务功能 |
| **Could（可以有）** | 误删恢复、直接输入数量 | 增强体验 |
| **Won't（不会有）** | 批量操作、购物车分享 | 本期不实现 |

## 四、边界条件分析

| 场景 | 测试要点 |
|------|---------|
| **并发超卖** | 多用户同时抢购最后1件库存，验证不会超卖 |
| **数量边界** | 数量=0、负数、超大数字输入校验 |
| **价格精度** | 小数计算（99.99×3）、优惠券叠加计算 |
| **会话过期** | 登录态过期后操作购物车，验证跳转登录 |
| **网络异常** | 添加商品时断网，验证失败重试机制 |
| **数据一致性** | 页面刷新后购物车数据与服务器同步 |

## 五、风险评估

| 风险项 | 严重程度 | 概率 | 缓解措施 |
|-------|---------|------|---------|
| 超卖问题 | 🔴 高 | 中 | 库存预扣减+乐观锁 |
| 价格显示错误 | 🔴 高 | 低 | 多处价格一致性校验 |
| 购物车数据丢失 | 🟡 中 | 低 | 本地缓存+服务端持久化 |
| 结算页数据陈旧 | 🟡 中 | 中 | 实时拉取最新库存/价格 |
| 优惠码叠加漏洞 | 🔴 高 | 低 | 优惠码互斥规则校验 |

## 六、非功能性需求

| 类型 | 要求 |
|------|------|
| **性能** | 购物车页面加载 < 500ms |
| **并发** | 支持1000用户同时操作 |

## 七、AI可执行范围 vs 人工必须覆盖范围

### AI可执行范围 ✅
- 正常流程功能测试用例
- 边界值测试用例
- 界面交互测试用例
- 简单业务逻辑验证

### 人工必须覆盖范围 🔴
- **支付安全测试**：优惠券叠加漏洞、金额篡改
- **并发压测**：超卖场景、高并发下的库存一致性
- **兼容性测试**：多机型、多浏览器UI一致性
- **探索性测试**：用户异常操作路径挖掘
- **回归测试**：历史缺陷验证
