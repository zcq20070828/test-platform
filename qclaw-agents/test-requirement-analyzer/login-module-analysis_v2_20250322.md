## 二、需求概述

### 2.1 项目背景

用户登录模块是系统安全的第一道防线，涉及用户身份认证、会话管理、密码安全等多个核心安全领域。本分析基于用户提出的「生成用户登录模块的测试用例」需求，从测试需求分析角度对登录功能进行完整拆解。

### 2.2 需求目标

| 序号 | 目标 | 优先级 | 来源 |
|------|------|--------|------|
| 1 | 覆盖账号密码登录的正向和异常场景 | Must Have | 用户明确指定 |
| 2 | 覆盖验证码校验的安全性和可用性 | Must Have | 功能完整性要求 |
| 3 | 覆盖「记住我」的会话保持场景 | Should Have | 用户明确指定 |
| 4 | 覆盖密码找回全链路 | Must Have | 账号生命周期完整性 |
| 5 | 覆盖登录安全防护机制 | Must Have | OWASP安全基线要求 |

### 2.3 利益相关者

| 角色 | 关注点 |
|------|--------|
| **最终用户（C端）** | 登录便捷性、错误提示友好度、找回密码顺畅 |
| **安全审计方** | 密码加密传输、防暴力破解、会话安全 |
| **开发团队** | 接口规范、边界条件、异常处理 |
| **测试团队** | 可测试性、验收标准明确性、覆盖率 |

### 2.4 成功指标

- 需求分解覆盖率 ≥ 95%（所有识别出的功能点均有AC覆盖）
- 数据一致性：各层级计数无矛盾
- 标准引用：风险评估引用 OWASP ASVS / NIST SP 800-63 等安全标准

## 三、范围界定

### 3.1 在范围内

| 编号 | 功能 | 说明 |
|------|------|------|
| F-01 | 账号密码登录 | 用户名/手机号/邮箱 + 密码组合校验 |
| F-02 | 验证码校验 | 图形验证码 + 短信/邮箱验证码 |
| F-03 | 记住登录（记住我） | 长期免登录 Token 机制 |
| F-04 | 密码找回 | 通过验证码重置密码 |
| F-05 | 登录态管理 | Token 过期、刷新、登出 |
| F-06 | 安全防护 | 防暴力破解、防重放、异常检测 |

### 3.2 不在范围内（本次不分析）

| 功能 | 说明 |
|------|------|
| 第三方登录（OAuth） | 微信/QQ/Google 等联合登录，不涉及密码认证 |
| 生物特征登录 | 指纹/人脸登录（属于设备层认证） |
| 注册流程 | 仅分析找回密码场景中涉及的身份验证 |
| 权限管理（RBAC） | 登录后的角色权限分配不在本次分析范围 |
| SSO 单点登录 | 多系统统一认证属于独立模块 |

## 六、验收标准（AC）— Given-When-Then 格式

### 6.1 EPIC-01：账号密码登录（8条AC）

**AC-001：正常登录成功** [FP-01.1.1]
- **Given** 用户已注册且账号状态正常
- **When** 用户输入正确的用户名/手机号和匹配的密码，点击登录
- **Then** 系统返回登录成功（HTTP 200），跳转至首页，返回有效 Token（JWT格式）
- **验证方式**：✅ AI可覆盖 — 接口自动化验证

**AC-002：密码错误登录失败** [FP-01.2.3]
- **Given** 用户已注册，累计失败次数未达上限
- **When** 用户输入正确的用户名和错误的密码
- **Then** 系统返回「账号或密码错误」（HTTP 401），不提示具体是"账号不存在"还是"密码错误"，登录失败次数 +1
- **验证方式**：✅ AI可覆盖 — 验证响应不泄露敏感信息
- **参考标准**：OWASP ASVS V2.1.1（认证失败不应指示哪个字段不正确）

**AC-003：用户名不存在** [FP-01.2.3]
- **Given** 用户未注册
- **When** 用户输入不存在的用户名和任意密码
- **Then** 系统返回统一的「账号或密码错误」（HTTP 401），不泄露账号存在性信息
- **验证方式**：✅ AI可覆盖 — 对比AC-002的响应体无差异

**AC-004：空输入校验** [FP-01.2.1]
- **Given** 用户位于登录页面
- **When** 用户用户名为空或密码为空时点击登录
- **Then** 前端即时提示「请输入用户名」或「请输入密码」，请求不发送至后端
- **验证方式**：✅ AI可覆盖 — 前端校验/接口层校验

**AC-005：密码复杂度校验** [FP-01.1.1]
- **Given** 系统设定了密码复杂度规则（≥8位，含字母+数字，建议含特殊字符）
- **When** 用户输入密码不满足复杂度要求
- **Then** 系统返回「密码不满足安全要求」，提示具体规则
- **验证方式**：✅ AI可覆盖 — 枚举多种不符合规则的密码
- **参考标准**：NIST SP 800-63B（最小8位，不强制复杂字符组合，但本项目如已设定则需遵循）

**AC-006：登录频率限制** [FP-01.3.1]
- **Given** 某 IP 或某账号在单位时间（如5分钟）内失败 ≥5 次
- **When** 该用户再次尝试登录
- **Then** 系统返回「操作过于频繁，请 N 分钟后重试」（HTTP 429），并展示倒计时
- **验证方式**：✅ AI可覆盖 — 批量请求测试
- **参考标准**：OWASP ASVS V2.2.5（认证失败率限制）、NIST SP 800-63B（限速/锁定）

**AC-007：密码加密传输** [FP-01.1.2]
- **Given** 用户提交登录表单
- **When** 密码从前端传输到后端
- **Then** 密码必须经过 HTTPS + 前端加密（RSA 公钥加密或类似方案），传输链路不可见明文
- **验证方式**：⚠️ 人工必须覆盖 — 需抓包工具（Charles/Whistle/Wireshark）验证
- **参考标准**：OWASP ASVS V2.1.7（密码必须使用强加密算法传输）、PCI DSS

**AC-008：SQL注入防护** [FP-01.2.2]
- **Given** 系统使用参数化查询
- **When** 用户名字段输入 SQL 注入语句（如 `' OR 1=1 --`）
- **Then** 系统返回「账号或密码错误」（HTTP 401），不泄露数据，不产生 SQL 错误信息
- **验证方式**：✅ AI可覆盖 — 自动化安全扫描
- **参考标准**：OWASP ASVS V5.3（输入验证和编码）

### 6.2 EPIC-02：验证码校验（5条AC）

**AC-009：图形验证码正常展示** [FP-02.1.1]
- **Given** 用户访问登录页面
- **When** 登录页面加载
- **Then** 展示图形验证码图片，内容为 N 位随机字符（数字+字母），图片含干扰线/扭曲/随机颜色
- **验证方式**：⚠️ 人工必须覆盖 — 需主观判断可读性

**AC-010：图形验证码校验失败** [FP-02.1.1]
- **Given** 用户输入了正确的账号密码
- **When** 用户输入错误图形验证码并提交
- **Then** 系统返回「验证码错误」（HTTP 400），刷新验证码图片，不校验密码
- **验证方式**：✅ AI可覆盖

**AC-011：短信/邮箱验证码发送成功** [FP-02.2.1]
- **Given** 用户已提供有效的手机号/邮箱
- **When** 用户点击「获取验证码」
- **Then** 验证码成功发送到绑定的手机/邮箱，按钮进入 60s 倒计时，发送接口有频率限制
- **验证方式**：⚠️ 人工必须覆盖 — 依赖第三方网关，需验证送达率和延迟

**AC-012：验证码有效期校验** [FP-02.3.1]
- **Given** 系统设定验证码有效期 T 分钟（通常5分钟）
- **When** 用户在有效期后提交验证码
- **Then** 系统返回「验证码已过期，请重新获取」（HTTP 400）
- **验证方式**：✅ AI可覆盖 — 修改系统时间或等待过期

**AC-013：验证码重发间隔限制** [FP-02.3.2]
- **Given** 用户已点击「获取验证码」
- **When** 用户在 60s 倒计时内再次点击
- **Then** 按钮不可点击，提示「请 N 秒后再试」；后端接口返回频率限制错误
- **验证方式**：✅ AI可覆盖

### 6.3 EPIC-03：记住登录（记住我）（4条AC）

**AC-014：记住登录状态生效** [FP-03.1.1]
- **Given** 用户勾选「记住我」并登录成功
- **When** 用户关闭浏览器重新访问
- **Then** 系统自动恢复登录态（通过持久化 Token），无需重新输入密码
- **验证方式**：⚠️ 人工必须覆盖 — 需在浏览器中操作验证 Cookie/Token 持久化

**AC-015：未勾选记住我—会话级登录** [FP-03.1.1]
- **Given** 用户未勾选「记住我」并登录成功
- **When** 用户关闭浏览器重新访问
- **Then** 系统要求重新登录（会话级 Token 无持久化）
- **验证方式**：✅ AI可覆盖

**AC-016：Token 被篡改安全拦截** [FP-03.1.2]
- **Given** 用户持有一个有效 Token
- **When** Token 在客户端被篡改后发起请求
- **Then** 系统返回 401 Unauthorized，要求重新登录
- **验证方式**：✅ AI可覆盖 — 修改 Token 的 payload 或签名后发送
- **参考标准**：OWASP ASVS V3.2（基于会话的 Token 必须防篡改）

**AC-017：Token 自动续期** [FP-03.3.1]
- **Given** 系统设定 Token 有效期（记住我模式：30天；会话模式：24h）
- **When** Token 即将过期且用户有活跃操作
- **Then** 系统静默刷新 Token，维持登录态，不中断用户操作
- **验证方式**：✅ AI可覆盖 — 时序测试，等待 Token 接近过期验证刷新行为

### 6.4 EPIC-04：密码找回（4条AC）

**AC-018：找回密码—身份验证** [FP-04.1.1]
- **Given** 用户点击「忘记密码」
- **When** 用户输入注册手机号/邮箱并获取验证码
- **Then** 验证码发送成功，系统进入密码重置步骤
- **验证方式**：✅ AI可覆盖

**AC-019：验证码错误不允许重置** [FP-04.1.1]
- **Given** 用户处于密码重置流程
- **When** 用户输入错误的验证码
- **Then** 系统返回「验证码错误」（HTTP 400），不允许进入下一步
- **验证方式**：✅ AI可覆盖

**AC-020：新密码强度校验通过** [FP-04.2.1]
- **Given** 用户通过身份验证进入密码重置
- **When** 用户输入符合复杂度要求的新密码并确认
- **Then** 系统返回「密码重置成功」（HTTP 200）
- **验证方式**：✅ AI可覆盖

**AC-021：重置后强制重新登录** [FP-04.3.1]
- **Given** 用户已成功重置密码
- **When** 重置流程结束
- **Then** 系统强制登出当前会话，跳转至登录页，提示「请使用新密码登录」
- **验证方式**：✅ AI可覆盖

### 6.5 EPIC-05：登录安全防护（3条AC）

**AC-022：连续失败锁定账号** [FP-05.1.1]
- **Given** 同一账号连续登录失败 N 次（如 10 次）
- **When** 该账号再次尝试登录（无论密码正确与否）
- **Then** 系统提示「账号已被临时锁定，请 N 分钟后再试」（HTTP 429/403）
- **验证方式**：✅ AI可覆盖 — 批量登录请求直到触发锁定
- **参考标准**：OWASP ASVS V2.2.5、NIST SP 800-63B（建议对已知账号的连续失败尝试限制为最多10次）

**AC-023：会话超时自动退出** [FP-05.2.1]
- **Given** 用户已登录但长时间无操作（如 30 分钟）
- **When** 用户发起请求
- **Then** 系统返回 401 Unauthorized，要求重新登录
- **验证方式**：⏱ 时序测试 — AI可辅助，需确认超时阈值配置
- **参考标准**：OWASP ASVS V3.1.1（空闲会话超时）

**AC-024：异常登录告警** [FP-05.3.1]
- **Given** 用户登录 IP 与历史登录地差异超过阈值
- **When** 登录成功
- **Then** 系统向用户绑定手机/邮箱发送「新设备登录提醒」通知
- **验证方式**：⚠️ 人工必须覆盖 — 需在真实网络环境验证 IP 识别逻辑
