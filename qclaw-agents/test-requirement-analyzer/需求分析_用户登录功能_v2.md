## 3. 业务背景

### 3.1 问题陈述

用户需要通过安全、可靠的方式访问系统资源。当前缺少统一的用户登录功能，导致用户无法完成身份认证并进入系统。该功能是系统的**入口级能力**，所有业务模块均依赖此功能实现用户隔离与权限控制。

### 3.2 业务价值

- **用户获取**：登录是用户进入系统的唯一入口，直接影响用户转化率
- **安全保障**：身份认证是第一道防线，防止未授权访问
- **合规需求**：满足《网络安全法》《个人信息保护法》对用户身份认证的基本要求
- **数据隔离**：通过用户身份区分，实现数据级权限控制

### 3.3 成功指标（KPI）

| 指标 | 目标值 | 测量方式 |
|------|-------|---------|
| 登录成功率 | ≥ 99.5% | 登录成功次数 / 总登录请求次数 |
| 登录响应时间（P95） | ≤ 2秒 | APM 监控 |
| 用户侧登录转化率 | ≥ 85% | 发起登录到成功登录的转化 |
| 暴力破解拦截率 | 100% | 安全日志审计 |
| 平均无故障登录 | ≥ 99.9% | 可用性监控 |

## 5. 功能性需求（详细规格）

### 5.1 需求 1：账号密码登录（P0 — 必须有）

**优先级论证（MoSCoW + 加权评分）：**
- 业务价值：10/10（无此功能系统不可用）
- 用户影响：10/10（覆盖 100% 用户）
- 加权总分：9.5/10 → **P0**

#### 功能描述
支持用户通过用户名、手机号或邮箱 + 密码的方式完成身份认证。

#### 输入字段定义

| 字段 | 类型 | 校验规则 |
|------|------|---------|
| 账号标识 | 字符串 | 用户名 4-20位字母数字下划线 / 手机号 11位数字 / 邮箱 标准email格式 |
| 密码 | 字符串 | 8-20位字符，至少含1个字母+1个数字（支持特殊字符） |

#### 用户故事与验收标准

**US-1.1：账号密码登录**

```
Scenario 1.1.1：使用用户名成功登录
Given 用户"zhangsan"已注册，密码正确
When 用户在登录页输入用户名"zhangsan"和正确密码
Then 登录成功，返回 200
And 返回用户基本信息与会话令牌（token）
And 页面跳转到系统首页

Scenario 1.1.2：使用手机号成功登录
Given 用户手机号"13800138000"已绑定账号，密码正确
When 用户输入手机号和正确密码
Then 登录成功，返回 200

Scenario 1.1.3：使用邮箱成功登录
Given 用户邮箱"a@b.com"已绑定账号，密码正确
When 用户输入邮箱和正确密码
Then 登录成功，返回 200

Scenario 1.1.4：密码错误
Given 已注册用户"zhangsan"
When 用户输入正确的用户名 + 错误密码
Then 返回 401
And 提示"用户名/密码错误，您还有 N 次尝试机会"

Scenario 1.1.5：账号不存在
Given 用户"unknown"未注册
When 用户输入不存在的用户名 + 任意密码
Then 返回 401
And 提示"用户名/密码错误"（不区分是账号不存在还是密码错误，防枚举攻击）

Scenario 1.1.6：输入格式不合法
Given 用户未输入或输入格式不合规
When 用户在账号字段输入少于4个字符
Then 前端立即提示"请输入正确格式的账号信息"
And 登录按钮保持禁用状态

Scenario 1.1.7：必填字段为空
Given 用户未填写任何字段
When 用户点击登录按钮
Then 前端提示"请输入账号"和"请输入密码"
And 不发起登录请求
```

**US-1.4：登录状态保持**

```
Scenario 1.4.1：会话有效期
Given 用户已成功登录，获得会话令牌
When 用户在有效期内（默认30分钟）发起任意请求
Then 请求通过认证，返回正常数据

Scenario 1.4.2：会话过期
Given 用户已登录但超过30分钟无操作
When 用户发起请求
Then 返回 401
And 提示"会话已过期，请重新登录"

Scenario 1.4.3：记住我延长会话
Given 用户勾选了"记住我"
When 用户成功登录
Then 会话有效期为7天
And 7天内无需重新输入密码
```

### 5.2 需求 2：安全策略（P0 — 必须有）

**优先级论证：** 安全是整个系统的基石，缺失将导致合规风险和数据泄露风险。
加权总分：9.0/10 → **P0**

**US-2.1：失败锁定**

```
Scenario 2.1.1：触发锁定
Given 用户"zhangsan"的账号
When 用户连续 5 次输入错误密码
Then 账号被临时锁定 30 分钟
And 返回 423 "账号已锁定，请30分钟后再试"
And 无论后续输入正确密码与否，均拒绝登录

Scenario 2.1.2：锁定到期自动解锁
Given 用户"zhangsan"的账号已被锁定29分钟
When 等待至锁定满30分钟后
Then 账号自动解锁
And 用户可以正常登录

Scenario 2.1.3：锁定期间管理员可手动解锁（预留）
Given 用户"zhangsan"账号被锁
When 管理员调用解锁接口
Then 账号即时解锁
```

**US-2.2：异常检测**

```
Scenario 2.2.1：异地登录检测
Given 用户上次登录 IP 在北京
When 检测到来自其他城市的登录请求
Then 标记为"异常登录"
And 发送登录提醒通知给用户

Scenario 2.2.2：非常用设备登录
Given 用户绑定设备列表中包含设备A
When 收到来自设备B的登录请求
Then 记录为新设备登录
And 可选：触发二次验证
```

**US-2.3：安全退出**

```
Scenario 2.3.1：主动退出
Given 用户已登录
When 用户点击"退出登录"
Then 服务端立即失效当前会话令牌
And 清除客户端存储的令牌
And 返回登录页面

Scenario 2.3.2：多设备退出
Given 用户已在设备A和设备B登录
When 用户在设备A退出
Then 仅设备A的会话失效
And 设备B不受影响
```

## 6. 非功能性需求

### 6.1 性能规格

| 指标 | 目标值 | 说明 |
|------|-------|------|
| **平均响应时间** | < 1秒 | 从请求发出到返回结果的 P50 时间 |
| **P95 响应时间** | < 2秒 | 95分位响应时间 |
| **P99 响应时间** | < 5秒 | 99分位响应时间 |
| **并发支持** | 1,000+ 并发用户 | 单节点 |
| **吞吐量** | ≥ 500 TPS | 每秒登录事务数 |
| **系统可用性** | ≥ 99.9% | 月度 SLA |

### 6.2 安全要求

| 要求 | 规格 |
|------|------|
| **传输加密** | 全链路 HTTPS，禁用 HTTP |
| **密码存储** | bcrypt 或 PBKDF2 哈希，禁止明文/MD5/SHA1 |
| **防暴力破解** | 连续 5 次失败锁定 30 分钟，递增延迟 |
| **防枚举攻击** | 错误提示不区分"账号不存在"和"密码错误" |
| **SQL 注入防护** | 参数化查询，禁止拼接 SQL |
| **XSS 防护** | 输出编码，CSP 头设置 |
| **CSRF 防护** | Token 验证或 SameSite Cookie |
| **会话令牌** | JWT 或随机 SessionID，HTTPOnly + Secure + SameSite |
| **登录频率限制** | 单 IP 每分钟不超过 20 次登录请求 |

### 6.3 可用性要求

| 要求 | 规格 |
|------|------|
| **正常运行时间** | 99.9%（月度约 43 分钟最大停机） |
| **维护窗口** | 凌晨 02:00-04:00 |
| **降级策略** | 登录服务不可用时，已登录用户会话不受影响（缓存层维持） |
| **灾备方案** | 多可用区部署，主备切换 < 30秒 |

### 6.4 可扩展性要求

- **水平扩展**：登录服务无状态设计，支持水平扩展
- **缓存策略**：会话信息存储在 Redis 等分布式缓存，支持集群
- **接口版本**：API 版本化（/api/v1/login），向后兼容

### 6.5 合规要求

| 法规 | 对应要求 |
|------|---------|
| 《网络安全法》 | 用户实名认证、日志留存 ≥ 6个月 |
| 《个人信息保护法》 | 收集用户信息需明确告知目的和范围 |
| 《数据安全法》 | 敏感数据分类分级、加密存储 |
| GDPR（如适用） | 用户数据可删除权、数据可携带权 |

## 7. 输入边界条件

### 7.1 字段边界

| 字段 | 最小值 | 最大值 | 格式 |
|------|-------|-------|------|
| 用户名 | 4字符 | 20字符 | 字母/数字/下划线，字母开头 |
| 密码 | 8字符 | 20字符 | 包含字母+数字，可含特殊字符 |
| 手机号 | 11位 | 11位 | 纯数字，以1开头 |
| 邮箱 | 6字符 | 50字符 | 标准 email 格式 |
| 验证码 | 6位 | 6位 | 纯数字 |

### 7.2 业务边界

| 边界项 | 阈值 | 说明 |
|-------|------|------|
| 失败锁定次数 | 5次 | 连续失败计数，成功后重置 |
| 锁定时长 | 30分钟 | 自动解锁 |
| 会话超时（默认） | 30分钟 | 无操作自动过期 |
| 会话超时（记住我） | 7天 | 勾选记住我时的有效期 |
| 最大在线设备数 | 5个 | 超出后提示或踢出最早设备 |
| 单IP频率限制 | 20次/分钟 | 超出返回 429 Too Many Requests |
| 验证码有效期 | 5分钟 | 超时需重新获取 |
| 验证码发送间隔 | 60秒 | 防短信轰炸 |

| AT-11 | 验证码登录成功 | 手机号已绑定 | 输入正确验证码 | 200 登录成功 |
| AT-12 | 验证码过期 | 验证码发出 5 分钟后 | 输入验证码 | 401 提示过期 |
| AT-13 | 记住我 | 登录时勾选"记住我" | 关浏览器再打开 | 会话保持 7天 |
| AT-14 | 频率限制 | 单 IP 超过 20 次/分钟 | 继续发送登录请求 | 429 + 稍后重试提示 |

### 8.2 安全验收

| 编号 | 测试项 | 方法 | 预期结果 |
|------|-------|------|---------|
| SA-01 | SQL 注入 | 用户名/密码字段注入 SQL 语句 | 请求被拦截，返回 400 或报错不泄露 SQL |
| SA-02 | XSS 攻击 | 输入 <script> 标签 | 输出编码，不执行脚本 |
| SA-03 | 暴力破解 | 自动化工具快速尝试密码 | 5次失败后锁定，IP 频率限制 |
| SA-04 | 会话劫持 | 尝试使用他人令牌 | 令牌验证失败，返回 401 |
| SA-05 | 密码传输检测 | 抓包确认传输协议 | 全链路 HTTPS（TLS 1.2+） |
| SA-06 | 密码存储检测 | 查看数据库存储方式 | bcrypt/PBKDF2 哈希，非明文 |
| SA-07 | Token 安全属性 | 检查 Cookie 属性 | HTTPOnly + Secure + SameSite=Strict |
| SA-08 | 枚举攻击 | 尝试不同存在/不存在的账号 | 错误提示统一，不区分存在与不存在 |

### 8.3 性能验收

| 编号 | 场景 | 并发数 | 目标 |
|------|------|-------|------|
| PA-01 | 低负载登录 | 100 并发 | P50 < 1s, P95 < 2s |
| PA-02 | 中负载登录 | 500 并发 | P50 < 1.5s, P95 < 3s |
| PA-03 | 峰值负载登录 | 1000 并发 | P50 < 2s, P95 < 5s |
| PA-04 | 持续压力测试 | 500 并发持续 30 分钟 | 无错误率 < 0.5%，CPU < 80% |

## 9. 约束条件

| 约束 | 说明 |
|------|------|
| 技术栈 | 后端必须与现有微服务架构兼容（Java/Go/Node.js） |
| 前端框架 | 与现有前端框架一致（React/Vue/小程序） |
| 数据库 | 用户数据存储在现有 MySQL 集群中 |
| 缓存 | 会话数据使用 Redis 集群 |
| 认证标准 | 密码哈希使用 bcrypt（成本因子 ≥ 10） |
| 第三方依赖 | 短信验证码依赖第三方 SMS 网关，需考虑降级方案 |
| 合规约束 | 日志留存 ≥ 6个月，敏感数据加密存储 |
| 部署约束 | 容器化部署，K8s 环境 |

## 11. 风险分析

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 暴力破解导致账号批量冻结 | 中 | 高 | 递增锁定策略 + 基于 IP 的频率限制 + 设备指纹 |
| 短信验证码被拦截/滥用 | 中 | 中 | 图形验证码 + 频率限制 + 风控模型 |
| 会话令牌泄露 | 低 | 高 | 短期令牌 + 刷新令牌 + 设备绑定 + 异常检测 |
| 并发峰值导致登录服务宕机 | 中 | 高 | 水平扩展 + 限流降级 + 熔断保护 |
| 第三方 SMS 服务不可用 | 低 | 中 | 增加备用通道 + 降级为密码登录方案 |
| 密码哈希算法选择不当 | 低 | 高 | 选 bcrypt (cost≥10) 或 PBKDF2，定期评估 |
