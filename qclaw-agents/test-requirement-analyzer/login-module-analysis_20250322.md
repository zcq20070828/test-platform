## 5. 验收标准（AC）— Given-When-Then 格式

### EPIC-01: 账号密码登录

**AC-001：正常登录成功**
- **Given** 用户已注册且账号状态正常
- **When** 用户输入正确的用户名/手机号和匹配的密码，点击登录
- **Then** 系统返回登录成功，跳转至首页，返回有效 Token

**AC-002：密码错误登录失败**
- **Given** 用户已注册，累计失败次数未达上限
- **When** 用户输入正确的用户名和错误的密码
- **Then** 系统返回「账号或密码错误」，不提示具体是"账号不存在"还是"密码错误"，登录失败次数 +1

**AC-003：用户名不存在**
- **Given** 用户未注册
- **When** 用户输入不存在的用户名和任意密码
- **Then** 系统返回统一的「账号或密码错误」，不泄露账号存在性信息

**AC-004：空输入校验**
- **Given** 用户位于登录页面
- **When** 用户用户名或密码为空时点击登录
- **Then** 前端即时提示「请输入用户名」或「请输入密码」，请求不发送至后端

**AC-005：密码字符复杂度校验**
- **Given** 系统设定了密码复杂度规则（≥8位，含字母+数字）
- **When** 用户输入密码不满足复杂度要求
- **Then** 系统返回「密码不满足安全要求」，提示具体规则

**AC-006：登录频率限制**
- **Given** 某 IP 或某账号在单位时间（如5分钟）内失败 ≥5 次
- **When** 该用户再次尝试登录
- **Then** 系统返回「操作过于频繁，请 N 分钟后重试」，并展示倒计时，请求暂不校验密码

### EPIC-02: 验证码校验

**AC-007：图形验证码正常展示**
- **Given** 用户访问登录页面
- **When** 登录页面加载
- **Then** 展示图形验证码图片，内容为 N 位随机字符（数字/字母），不易被 OCR 轻易识别

**AC-008：图形验证码校验失败**
- **Given** 用户输入了正确的账号密码
- **When** 用户输入错误图形验证码并提交
- **Then** 系统返回「验证码错误」，刷新验证码图片，不校验密码

**AC-009：短信/邮箱验证码发送成功**
- **Given** 用户已提供有效的手机号/邮箱
- **When** 用户点击「获取验证码」
- **Then** 验证码成功发送到绑定的手机/邮箱，按钮进入 60s 倒计时

**AC-010：验证码有效期校验**
- **Given** 系统设定验证码有效期 T 分钟（通常5分钟）
- **When** 用户在有效期后提交验证码
- **Then** 系统返回「验证码已过期，请重新获取」

**AC-011：验证码重发间隔限制**
- **Given** 用户已点击「获取验证码」
- **When** 用户在 60s 倒计时内再次点击
- **Then** 按钮不可点击，提示「请 N 秒后再试」

### EPIC-03: 记住登录（记住我）

**AC-012：记住登录状态生效**
- **Given** 用户勾选「记住我」并登录成功
- **When** 用户关闭浏览器重新访问
- **Then** 系统自动恢复登录态，无需重新输入密码

**AC-013：未勾选记住我—会话级登录**
- **Given** 用户未勾选「记住我」并登录成功
- **When** 用户关闭浏览器重新访问
- **Then** 系统要求重新登录

**AC-014：Token 过期后主动刷新**
- **Given** 系统设定 Token 有效期（记住我模式：30天；会话模式：24h）
- **When** Token 即将过期且用户有活跃操作
- **Then** 系统静默刷新 Token，维持登录态

**AC-015：Token 被篡改安全拦截**
- **Given** 用户持有一个有效 Token
- **When** Token 在客户端被篡改后发起请求
- **Then** 系统返回 401 Unauthorized，要求重新登录

### EPIC-04: 密码找回

**AC-016：找回密码—身份验证**
- **Given** 用户点击「忘记密码」
- **When** 用户输入注册手机号/邮箱并获取验证码
- **Then** 验证码发送成功，系统进入密码重置步骤

**AC-017：验证码错误不允许重置**
- **Given** 用户处于密码重置流程
- **When** 用户输入错误的验证码
- **Then** 系统返回「验证码错误」，不允许进入下一步

**AC-018：新密码强度校验通过**
- **Given** 用户通过身份验证进入密码重置
- **When** 用户输入符合复杂度要求的新密码并确认
- **Then** 系统返回「密码重置成功」

**AC-019：新密码与旧密码相同被拒绝**
- **Given** 用户通过身份验证进入密码重置
- **When** 用户输入的新密码与当前密码相同
- **Then** 系统返回「新密码不能与当前密码相同」

**AC-020：密码重置后强制重新登录**
- **Given** 用户已成功重置密码
- **When** 重置流程结束
- **Then** 系统强制登出当前会话，跳转至登录页，提示「请使用新密码登录」

### EPIC-05: 登录安全防护

**AC-021：连续失败锁定账号**
- **Given** 同一账号连续登录失败 N 次（如 10 次）
- **When** 该账号再次尝试登录（无论密码正确与否）
- **Then** 系统提示「账号已被临时锁定，请 N 分钟后再试」

**AC-022：会话超时自动退出**
- **Given** 用户已登录但长时间无操作（如 30 分钟）
- **When** 用户发起请求
- **Then** 系统返回 401 并要求重新登录

**AC-023：异常 IP 登录告警**
- **Given** 用户登录 IP 与历史登录地差异超过阈值
- **When** 登录成功
- **Then** 系统向用户绑定手机/邮箱发送「新设备登录提醒」通知

**AC-024：密码传输加密**
- **Given** 用户提交登录表单
- **When** 密码从前端传输到后端
- **Then** 密码必须经过 HTTPS + 前端加密（RSA 公钥加密或类似方案），传输链路不可见明文

## 7. 边界条件分析

| 类别 | 条件 | 预期处理 |
|------|------|---------|
| **输入长度** | 密码 < 最小长度（如6位） | 前端拦截，提示长度不足 |
| **输入长度** | 密码 > 最大长度（如128位） | 截断或拒绝，提示超长 |
| **输入长度** | 用户名 > 最大长度 | 前端拦截或后端截断处理 |
| **输入字符** | 用户名含 SQL 注入语句（`' OR 1=1`） | 参数化查询，防止注入 |
| **输入字符** | 用户名含 XSS 脚本（`<script>`） | HTML 实体编码过滤 |
| **输入字符** | 用户名含表情符号/Unicode | 按规则校验，允许或拒绝 |
| **并发场景** | 同一账号多地同时登录 | 根据策略（允许/踢出/拒绝）处理 |
| **并发场景** | 验证码重试并发提交 | 锁定验证码为一次性使用 |
| **网络异常** | 请求超时/断网 | 前端友好提示「网络异常，请检查」 |
| **设备类型** | 移动端 vs Web 端 UI 适配 | 布局自适应，交互一致 |

## 8. 风险评估

| 风险ID | 风险描述 | 影响等级 | 发生概率 | 风险等级 | 缓解措施 |
|--------|---------|---------|---------|---------|---------|
| R-01 | 密码传输过程中被中间人截获 | 🔴 严重 | 🟡 中 | **高** | 强制 HTTPS + 前端 RSA 加密 |

| R-03 | 短信验证码被拦截/盗用 | 🟡 较大 | 🟢 低 | **中** | 有效期短 + 绑定手机设备指纹 |
