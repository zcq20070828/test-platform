## 六、验收标准（Given-When-Then）

### AC-001: 正常登录成功
```
Given 用户已注册且账号状态正常
When  用户输入正确的账号和密码，点击登录
Then  系统返回 200 状态码
And   响应包含有效 Token 或 SessionID
And   页面跳转至首页
And   首页显示用户昵称或头像
```

### AC-002: 密码错误
```
Given 用户已注册，账号状态正常
When  用户输入正确账号但错误密码，点击登录
Then  系统返回 401 状态码
And   提示"用户名或密码错误"（与AC-003使用相同文案）
And   记录本次错误，显示剩余尝试次数（如：还剩4次）
And   不创建任何会话
```

### AC-003: 账号不存在
```
Given 用户输入的账号在系统中不存在
When  用户点击登录
Then  系统返回 401 状态码
And   提示"用户名或密码错误"（与AC-002使用完全相同文案）
And   不创建任何会话
And   不暴露"账号不存在"的提示（防账号枚举攻击）
```

### AC-004: 空输入拦截
```
Given 用户未在账号框或密码框输入内容
When  用户点击登录按钮
Then  对应输入框下方显示"请输入账号"/"请输入密码"
And   前端阻止表单提交
And   不发起任何后端接口调用
```

### AC-005: 账号锁定
```
Given 用户在同一设备上连续输错密码达到5次
When  用户第6次尝试登录（无论密码是否正确）
Then  系统返回 403 状态码
And   提示"账号已锁定，请30分钟后重试"
And   锁定期间即使输入正确密码也无法登录
And   解锁后可正常登录
```

### AC-006: 会话超时
```
Given 用户已成功登录且会话有效
When  用户在30分钟（假设值）内无任何操作
And   用户之后发起任意业务请求
Then  系统返回 401 状态码
And   页面跳转至登录页
And   提示"登录状态已过期，请重新登录"
```

### AC-007: 验证码登录
```
Given 用户已注册且手机号有效
When  用户输入正确手机号和5分钟内获取的有效验证码
Then  系统返回 200 状态码
And   登录成功，跳转首页
```

### AC-008: 图形验证码
```
Given 连续登录失败触发图形验证码
When  用户正确识别并输入图形验证码
Then  图形验证码校验通过
And   可继续后续登录流程
```

## 七、安全测试要点

| 安全项 | 测试方法 | 预期结果 | 风险级别 |
|--------|----------|----------|----------|
| **密码加密传输** | 使用抓包工具（如Charles/Fiddler）查看登录请求 | 密码字段已加密（如HTTPS + AES/RSA），无明文密码 | 🔴 高 |
| **防暴力破解** | 模拟连续5次错误密码登录 | 第6次被锁定，返回403，提示30分钟后重试 | 🔴 高 |
| **防账号枚举** | 使用存在账号与不存在账号分别登录 | 两种情况的错误提示完全相同，不暴露账号是否存在 | 🔴 高 |
| **会话安全** | 检查Cookie/Token属性 | HttpOnly、Secure、SameSite 属性正确设置 | 🟡 中 |
| **并发登录控制** | 两台设备同时使用同一账号登录 | 按业务规则执行（踢出旧会话/允许多设备） | 🟡 中 |
| **登录日志审计** | 查询登录日志记录 | 记录登录时间、IP、设备类型、结果 | 🟢 低 |
| **撞库攻击防护** | 短时间内大量不同账号密码组合 | IP封禁或触发验证码 | 🔴 高 |
| **弱密码策略** | 尝试登录常见弱密码 | 系统拒绝弱密码或提示修改 | 🟡 中 |

## 八、风险评估矩阵

| 风险项 | 可能性 | 影响度 | 风险值 | 应对策略 |
|--------|--------|--------|--------|----------|
| 密码暴力破解 | 🟡 中 | 🔴 高 | 🔴 高 | 错误次数限制（5次）+ 账号锁定（30分钟）+ 验证码 |

| 弱密码策略绕过 | 🟢 低 | 🔴 高 | 🟡 中 | 注册时密码强度校验 + 强制修改弱密码提示 |
| XSS钓鱼攻击 | 🟢 低 | 🔴 高 | 🟡 中 | 输出编码 + Content-Security-Policy |

## 九、⚠️ 禁止 AI 覆盖范围（必须人工测试）

| 范围 | 原因 | 建议测试方式 |
|------|------|--------------|
| **生物识别登录**（指纹/面容/声纹） | 需要真机硬件环境和实际生物特征 | 使用真机 + 实际生物特征测试 |
| **OTP 动态令牌**（短信/邮件验证码） | 需要实际接收短信/邮件，或模拟运营商响应 | 集成测试环境 + 运营商mock |
| **SSO 单点登录集成** | 需要多系统联动，多团队协作 | 端到端集成测试 |
| **安全渗透测试** | 需要专业安全工具和技能 | 安全团队专项测试 |
| **用户体验/无障碍评审** | 需要人工主观判断 | 人工评审或用户访谈 |
