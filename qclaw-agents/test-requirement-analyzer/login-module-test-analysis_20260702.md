## 1. 概述

### 1.1 测试目标

对系统**登录模块**进行功能测试验证，确保不同凭据输入场景下系统行为符合预期。核心验证点：
- 正确凭据 → 成功登录
- 错误密码 → 登录失败并提示
- 不存在账号 → 登录失败并提示

### 1.2 测试范围

| 项目 | 内容 |
|------|------|
| **被测对象** | 登录模块（用户名 + 密码认证） |
| **测试层级** | 功能测试（冒烟级 / 系统功能级） |
| **测试类型** | 正向功能验证、负面路径验证、边界验证 |
| **范围** | 限登录认证流程本身，不涉及注册、找回密码、第三方登录 |

### 1.3 利益相关者

| 角色 | 关注点 |
|------|--------|
| **最终用户** | 登录顺畅、错误提示清晰、操作反馈及时 |
| **产品经理** | 功能完整性、用户体验符合 PRD |
| **开发团队** | 接口与校验逻辑正确、异常处理完善 |
| **安全团队** | 密码存储与传输安全、暴力破解防护 |
| **测试团队** | 用例覆盖充分、可测性良好 |

## 2. 功能需求拆解

### 2.1 功能模块结构

```
登录模块
├── 2.1 输入组件
│   ├── 用户名输入框
│   ├── 密码输入框
│   └── 登录按钮
├── 2.2 认证校验引擎
│   ├── 用户存在性校验
│   ├── 密码正确性校验
│   └── 登录状态管理
├── 2.3 输出反馈组件
│   ├── 登录成功 → 跳转目标页面
│   ├── 密码错误 → 失败提示
│   └── 账号不存在 → 不存在提示
└── 2.4 安全防护机制
    └── (可选)验证码、失败次数限制、加密传输
```

### 2.2 功能需求分解

| 需求 ID | 功能描述 | 关联场景 |
|---------|---------|---------|
| FR-01 | 用户输入凭据并提交后，系统校验用户名是否存在 | 场景 2、3 |
| FR-02 | 用户名存在时，校验密码是否正确 | 场景 1、2 |
| FR-03 | 各项校验通过后，为用户建立登录会话并跳转 | 场景 1 |
| FR-04 | 校验失败时，向用户展示对应错误提示 | 场景 2、3 |
| FR-05 | 空输入/格式异常时给出提示（扩展场景） | 边界场景 |

## 4. 预期输出定义

### 4.1 场景级预期输出

| 场景 | 前端表现 | 后端行为 | 会话状态 |
|------|---------|---------|---------|
| **场景 1：登录成功** | 页面跳转至首页/控制台，无错误提醒 | 返回 200 / token / session | ✅ 已建立 |
| **场景 2：密码错误** | 表单上方/输入框下方显示"密码错误，请重试" | 返回 401/403，明确错误码 | ❌ 未建立 |
| **场景 3：账号不存在** | 表单上方显示"账号不存在，请检查后重试" | 返回 404，明确错误码 | ❌ 未建立 |

### 4.2 验收标准（Given-When-Then）

#### 场景 1：登录成功
```
Given  用户 A 已在系统中注册，用户名为 "valid_user"，密码为正确值
When   用户在登录页面输入 "valid_user" / 正确密码 并点击登录
Then   系统验证通过，用户跳转至目标页面，服务端返回有效会话凭证
```

#### 场景 2：密码错误
```
Given  用户 A 已在系统中注册，密码为 "correct_pwd"
When   用户在登录页面输入 "valid_user" / "wrong_pwd" 并点击登录
Then   系统停留在登录页，显示错误提示"密码错误，请重试"，不建立会话
```

#### 场景 3：账号不存在
```
Given  用户 "ghost_user" 在系统中不存在
When   用户在登录页面输入 "ghost_user" / 任意密码 并点击登录
Then   系统停留在登录页，显示错误提示"账号不存在，请检查后重试"，不建立会话
```

## 5. 测试关注点分析

### 5.1 功能关注点

| 关注点 | 说明 | 优先级 |
|-------|------|--------|
| ✅ 正向流程正确性 | 正确凭据 → 正常登录 | P0 |
| ✅ 错误阻断逻辑 | 密码错误/账号不存在 → 正确阻断 | P0 |
| ✅ 提示信息准确性 | 不同失败原因给出不同提示 | P0 |
| ✅ 登录状态保持 | Session/Token 时效及刷新 | P1 |
| ✅ 登出闭环 | 登录成功后可否正常登出 | P1 |

### 5.2 安全关注点

| 关注点 | 说明 | 优先级 |
|-------|------|--------|
| 🔒 密码不可见 | 密码输入框用掩码（`type=password`） | P0 |
| 🔒 错误不泄露敏感信息 | 不得暴露"用户名存在但密码错误" vs "账号不存在"的差异（安全最佳实践通常应返回统一错误信息） | P1 |
| 🔒 传输加密 | 表单提交必须走 HTTPS | P0 |
| 🔒 暴力破解防护 | 连续失败 N 次后临时锁定 / 加入验证码 | P1 |
| 🔒 会话安全 | Token 使用 HttpOnly + Secure Cookie，防 XSS | P1 |
| 🔒 SQL 注入防护 | 后端需使用参数化查询，防止注入 | P0 |

> **⚠ 安全提示**：从安全角度，生产系统建议对「账号不存在」和「密码错误」返回**相同的通用错误信息**（如"用户名或密码错误"），防止攻击者枚举有效用户名。测试时应根据产品实际设计验证。

### 5.3 用户体验关注点

| 关注点 | 说明 | 优先级 |
|-------|------|--------|
| 🎯 提示友好性 | 错误文案简洁明了，不带技术术语 | P1 |
| 🎯 输入保留 | 密码错误时是否清空密码？用户名是否保留？ | P2 |
| 🎯 加载状态 | 点击登录后应有加载指示，防重复提交 | P1 |
| 🎯 键盘操作 | 支持 Enter 键提交表单 | P2 |
| 🎯 错误位置 | 提示信息出现在用户视线自然停留区（如输入框下方或表单顶部） | P2 |

## 7. 风险识别

| 风险 ID | 风险描述 | 影响 | 概率 | 等级 | 缓解措施 |
|---------|---------|------|------|------|---------|
| R-01 | **信息泄露风险**：系统对不同失败原因返回差异化的错误提示，攻击者可枚举有效用户名 | 高 | 中 | 🔴 高 | 安全建议统一返回"用户名或密码错误"；如产品要求明确区分，需评估风险 |
| R-02 | **暴力破解风险**：登录接口无频率限制，攻击者可字典攻击 | 高 | 中 | 🔴 高 | 实施 N 次失败后锁定 + 验证码 + 渐进延迟 |
| R-03 | **会话管理缺陷**：Token/Session 时效未设合理过期或被固定 | 中 | 低 | 🟡 中 | 设 Token 有效期 + 滑动刷新；禁会话固定 |
| R-04 | **前端校验绕过**：前端校验（如空值检查）可被接口直接调用绕过 | 中 | 中 | 🟡 中 | 后端必须独立校验所有字段，前端仅做辅助 |
| R-05 | **SQL 注入**：用户名字段未参数化处理 | 高 | 低 | 🟡 中 | 强制使用预编译语句 / ORM 参数化查询 |
| R-06 | **测试环境依赖**：缺少预置的测试账号数据，阻塞用例执行 | 中 | 高 | 🟡 中 | 测试前置条件中增加账号数据初始化脚本 |
| R-07 | **密码加密变更**：密码哈希算法/盐值策略变化导致已有账号不可用 | 高 | 低 | 🟡 中 | 测试关注密码加密升级方案的向后兼容性 |

## 8. 建议与备注

### 8.1 测试范围扩展建议

当前需求覆盖了 3 个核心场景（P0），建议在后续迭代中补充：

1. **密码锁定机制**：N 次失败后账号临时锁定及解锁流程
2. **多设备登录**：同一账号是否允许同时在多设备登录
3. **记住我（Remember Me）**：长期 Token 的颁发与安全
4. **重置密码后首次登录**：验证强制修改密码逻辑
5. **国际化**：错误提示在不同语言环境下的显示

### 8.2 质量衡量标准

| 指标 | 目标值 |
|------|-------|
| P0 用例通过率 | 100% |
| P1 用例通过率 | ≥ 95% |
| 测试覆盖率（等价类） | ≥ 90% |
| 安全用例覆盖率 | 100% |
| 登录页面加载时间 | ≤ 2s |
