## 5. 功能性需求（详细规格）

### 5.1 需求 1：账号密码认证（核心入口）

#### 输入字段（框架）

| 字段 | 类型 | 校验规则（建议） | 确认状态 |
|------|------|-----------------|---------|
| 账号标识 | 字符串 | 支持用户名/手机号/邮箱三种格式，自动识别 | 🟢 逻辑稳定 |
| 密码 | 字符串 | 最少位数、是否包含特殊字符等需确认 | 🔴 需确认密码策略 |

**🚩 密码策略待确认问题：**
- 最小/最大长度？→ **[假设]** 建议 8-20 位
- 复杂度要求（大小写/数字/特殊字符）？→ **[假设]** 至少 1 字母 + 1 数字
- 是否支持特殊字符/Unicode/中文字符？
- 历史密码限制？密码有效期？

#### US-1.1：用户使用账号+密码登录

```
Scenario：登录成功
Given 用户已注册，凭据正确
When 用户输入有效的账号和对应的正确密码
Then 登录成功
And 返回会话令牌（token/session）
And 页面跳转到系统首页/目标页
```

```
Scenario：密码错误
Given 用户已注册
When 用户输入有效的账号 + 错误的密码
Then 返回 "用户名或密码错误"（统一提示，不区分"账号不存在"与"密码错误"，防枚举攻击）
And 记录失败次数
```

```
Scenario：账号不存在
Given 系统中无此账号记录
When 用户输入任意账号 + 任意密码
Then 返回统一错误提示 "用户名或密码错误"
```

```
Scenario：必填字段为空
Given 用户未填写账号或密码
When 用户点击登录按钮
Then 前端立即提示相应字段为必填
And 不发起网络请求
```

✏️ **格式校验**（前端预校验 + 后端二次校验）：

```
Scenario：账号格式不合法
Given 用户输入的账号格式异常（如过短/过长/包含非法字符）
When 用户提交登录请求
Then 前端立即提示格式错误
And 不发起网络请求
```

### 5.2 需求 2：安全防护

#### US-2.1：防暴力破解

| 参数 | 建议值 | 确认状态 |
|------|-------|---------|
| 连续失败锁定阈值 | 5 次 | **[假设]** 需安全团队确认 |
| 锁定时长 | 30 分钟 | **[假设]** 可配置 |
| 计数重置时机 | 成功登录后重置 | 🟢 逻辑稳定 |
| IP 级频率限制 | 每分钟 N 次 | **[假设]** 需确认 N 值 |

```
Scenario：触发锁定
Given 用户连续输入错误密码达阈值
When 用户发出下一次登录请求
Then 返回 "账号已锁定，请稍后再试"
And 锁定期间即使输入正确密码也拒绝
```

```
Scenario：锁定到期自动解锁
Given 用户账号处于锁定状态
When 锁定期满后再次尝试
Then 账号自动解锁
And 可正常登录
```

#### US-2.2：安全退出

```
Scenario：用户主动退出
Given 用户已登录
When 用户点击"退出登录"
Then 服务端立即失效当前会话令牌
And 清除客户端存储的认证信息
And 跳转至登录页
```

#### US-2.3：异常登录检测（可选）

**[假设]** 以下为建议的安全增强功能，优先级取决于业务安全等级：

| 检测类型 | 说明 | 触发响应 |
|---------|------|---------|
| 异地登录检测 | 上次与本次登录 IP 地域差异大 | 发送安全提醒通知 |
| 新设备登录 | 从未见过的设备指纹 | 可选触发二次验证 |
| 异常时间登录 | 非用户常规时段（如凌晨 3 点） | 记录标记，可选告警 |

## 14. 改进对照：v2 → v3
