## 四、MoSCoW 优先级排序

### 🔴 Must Have（必须有 — 核心功能，不可协商）

| 编号 | 需求 | 测试范围 | 理由 |
|------|------|---------|------|
| M1 | 邗箱/用户名 + 密码登录 | 正向登录、逆向登录、输入校验 | 登录是系统入口，没有它系统不可用 |
| M2 | 登录失败提示（不含敏感信息） | 各种失败场景的错误信息验证 | 安全要求：不能泄露"用户不存在"vs"密码错误" |
| M3 | 密码加密传输（HTTPS） | 抓包验证密码不明文传输 | 安全底线 |
| M4 | 密码加密存储（bcrypt/scrypt） | 数据库检查密码非明文 | 安全底线 |
| M5 | 暴力破解防护（限频+锁定） | 连续失败5次锁定、频率限制 | 安全合规 |
| M6 | 会话超时自动退出 | 超时时间验证、超时后操作验证 | 安全合规 |
| M7 | 登录后跳转正确页面 | 跳转路由验证、权限页面验证 | 基础可用性 |

### 🟡 Should Have（应该有 — 重要但可推迟）

| 编号 | 需求 | 测试范围 | 理由 |
|------|------|---------|------|
| S1 | 密码重置/找回 | 重置流程、邮箱验证、时效验证 | 用户高频需求，影响留存 |
| S2 | 密码强度校验与提示 | 弱密码拦截、规则提示 | 降低安全风险 |
| S3 | 记住我/自动登录 | Cookie有效期、跨浏览器验证 | 用户体验提升 |
| S4 | 并发登录控制 | 同账号多端登录策略 | 企业安全要求 |
| S5 | 登出功能 | 登出后Session清除、登出后页面跳转 | 完整会话生命周期 |
| S6 | 异常IP/设备告警 | 新设备登录通知、异地登录告警 | 安全增强 |

### 🟢 Could Have（可以有 — 最好有，时间允许时包含）

| 编号 | 需求 | 测试范围 | 理由 |
|------|------|---------|------|
| C1 | 多因素认证（MFA） | 二次验证流程、验证码时效 | 安全增强，但用户体验变复杂 |
| C2 | 社交登录（微信/Google） | OAuth流程、Token验证、绑定逻辑 | 提升注册转化率 |
| C3 | 登录历史/活动日志 | 日志记录完整性、查询功能 | 安全审计 |
| C4 | 生物识别登录（指纹/面部） | 生物认证流程、降级处理 | 移动端体验提升 |

### ⚪ Won't Have（本次发布不在范围）

| 编号 | 需求 | 理由 |
|------|------|------|
| W1 | 单点登录（SSO） | 需要企业级基础设施，后续版本 |
| W2 | LDAP集成 | 仅企业客户需要 |
| W3 | 自定义认证提供商（OAuth Provider） | 复杂度高，优先级低 |

## 六、Kano 模型分类（用户满意度视角）

| 类型 | 需求 | 缺失时 | 满足时 |
|------|------|---------|--------|
| **基本型需求** | 基础登录、加密传输/存储、失败提示、暴力破解防护 | 极度不满（系统不可用/不安全） | 不增加满意度（理所当然） |
| **期望型需求** | 密码重置、密码强度校验、记住我、会话超时、登出 | 不满（体验差） | 满意度线性增加 |
| **兴奋型需求** | MFA、社交登录、生物识别、异常IP告警 | 不在意 | 惊喜，满意度大幅提升 |

> **优先级策略**：基本型需求 → 期望型需求 → 兴奋型需求

### 7.2 密码安全（M2/M3/M4/M5 + S2）— 测试点矩阵

| T-S01 | HTTPS传输验证 | 安全测试 | 抓包确认密码字段在TLS加密通道内 |

| T-S09 | 验证码机制触发 | 场景分析法 | 失败3次后出现验证码，防止自动化攻击 |
| T-S10 | 弱密码拦截 | 等价类划分 | "123456"、"password"等弱密码不允许设置 |
| T-S11 | 密码强度提示 | 场景分析法 | 实时显示密码强度等级（弱/中/强） |
| T-S12 | 登录失败不区分"用户不存在"vs"密码错误" | 安全测试 | 统一提示"邮箱或密码错误" |

| **可用性** | 系统可用性 | 工作时间99% | 登录服务在SLA时间内可用 |
| **安全** | HTTPS强制 | 全站HTTPS | HTTP请求自动重定向到HTTPS |
| **安全** | Cookie安全 | HttpOnly+Secure+SameSite=Strict | 抓包验证Cookie属性 |

## 九、验收标准（Given-When-Then）

### 核心验收标准

```
AC-01: 正常登录
Given 用户已注册账号且账号状态正常
When 用户输入正确的邮箱和密码点击登录
Then 系统验证成功，创建Session，跳转主页，显示用户信息

AC-02: 登录失败-密码错误
Given 用户已注册账号
When 用户输入正确邮箱和错误密码点击登录
Then 系统提示"邮箱或密码错误"，不提示密码错误（不泄露信息），失败计数+1

AC-03: 登录失败-账号不存在
Given 该邮箱未在系统注册
When 用户输入未注册邮箱和任意密码点击登录
Then 系统提示"邮箱或密码错误"，不提示账号不存在（不泄露信息）

AC-04: 暴力破解防护
Given 同一账号连续登录失败4次
When 第5次输入错误密码
Then 账号被锁定30分钟，提示"账号已锁定，请30分钟后重试"

AC-05: Session超时
Given 用户已登录且Session有效期30分钟
When 用户30分钟内无任何操作后点击页面功能
Then 系统清除Session，跳转登录页，提示"登录已过期，请重新登录"

AC-06: 安全传输
Given 用户在登录页面输入密码
When 点击登录提交请求
Then 密码在TLS加密通道传输，不在URL/日志中明文出现

AC-07: 密码重置
Given 用户已注册且记得注册邮箱
When 用户点击"忘记密码"输入注册邮箱
Then 系统发送重置邮件（24h有效），用户通过链接设置新密码后可登录

AC-08: 登出功能
Given 用户已登录
When 用户点击登出
Then 系统清除Session/Token，跳转登录页，回退无法访问已登录页面
```

## 十三、总结

本次分析基于 **requirements-analysis** Skill 的专业方法论（EPIC分解、MoSCoW/RICE/Kano优先级、Given-When-Then验收标准）和 **test-knowledge-base** 知识库的测试标准（等价类/边界值/场景分析法/安全测试），将"用户登录"从一句话需求拆解为：
