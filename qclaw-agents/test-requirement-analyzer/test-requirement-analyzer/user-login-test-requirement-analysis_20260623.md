## 1. 测试范围分析

|------|------|

| **认证逻辑** | 密码验证、Token/Session生成、多因素认证（如有） |
| **密码策略** | 密码复杂度校验、密码过期提示、密码错误次数管理 |
| **会话管理** | 登录态维持、Token刷新、超时退出、多点登录控制 |
| **异常流程** | 登录失败处理、账号锁定/解锁、忘记密码/重置密码 |
| **安全防护** | 暴力破解防御、CSRF Token、验证码机制、登录环境校验 |
| **第三方登录** | 微信/QQ/Google OAuth 集成（如适用） |
| **日志审计** | 登录成功/失败日志记录、异常登录告警 |

### 2.2 功能测试策略详情

#### 2.2.1 等价类划分法

| 输入域 | 有效等价类 | 无效等价类 |
|--------|-----------|-----------|
| **用户名** | 已注册的合法账号（邮箱/手机号/用户名） | 未注册账号、空值、含特殊字符 |
| **密码** | 正确的密码 | 错误密码、空密码、大小写不一致 |
| **验证码** | 正确验证码 | 错误验证码、过期验证码、空验证码 |
| **登录方式** | 密码登录、短信验证码登录 | 不支持的登录方式 |

#### 2.2.2 边界值分析法

| 边界项 | 边界值 | 测试点 |
|--------|--------|--------|
| 密码最小长度 | 6位 | 5位、6位、7位 |
| 密码最大长度 | 20位 | 19位、20位、21位 |
| 错误次数阈值 | 5次 | 4次、5次、6次 |
| 验证码有效期 | 60秒 | 59秒、60秒、61秒 |
| Session超时时间 | 30分钟 | 29分、30分、31分（不活跃后） |

#### 2.2.3 场景法

| 场景ID | 场景描述 | 优先级 |
|--------|---------|--------|
| S01 | **正常登录场景**：输入正确用户名+密码+验证码 → 登录成功跳转首页 | P0 |
| S02 | **密码错误场景**：输入正确用户名+错误密码 → 提示"用户名或密码错误" | P0 |
| S03 | **连续输错锁定场景**：连续5次输错密码 → 账号临时锁定 | P0 |
| S04 | **忘记密码→重置→登录场景**：忘记密码入口→验证身份→重置→新密码登录 | P1 |
| S05 | **Token过期场景**：登录后等待Token过期 → 自动跳转登录页 | P1 |
| S06 | **多点登录场景**：同一账号在另一设备登录 → 已有Session处理策略 | P1 |
| S07 | **验证码失效场景**：输入旧验证码 → 提示验证码错误 | P1 |
| S08 | **退出登录场景**：登录后退出 → Session销毁 → 需重新登录访问受保护资源 | P0 |

#### 2.2.4 判定表法

登录条件组合共有 3 个条件（用户名有效性、密码正确性、验证码正确性），理论上 2³ = 8 种组合。服务端校验按「验证码优先 → 用户名密码联合校验」顺序执行，各组合预期结果如下：

| 条件 | 组合1 | 组合2 | 组合3 | 组合4 | 组合5 | 组合6 | 组合7 | 组合8 |
|------|:-----:|:-----:|:-----:|:-----:|:-----:|:-----:|:-----:|:-----:|
| **C1: 用户名是否有效** | Y | Y | Y | Y | N | N | N | N |
| **C2: 密码是否正确** | Y | Y | N | N | Y | Y | N | N |
| **C3: 验证码是否正确** | Y | N | Y | N | Y | N | Y | N |
| **E1: 登录成功** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| **E2: 验证码错误** | ❌ | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ | ✅ |
| **E3: 用户名或密码错误** | ❌ | ❌ | ✅ | ❌ | ✅ | ❌ | ✅ | ❌ |

| 组合 | 条件描述 | 预期结果 | 返回码 | 说明 |
|:----:|---------|---------|:------:|------|
| **组合1** | 有效用户名 + 正确密码 + 正确验证码 | ✅ **登录成功**，返回 access_token 和 refresh_token，跳转首页 | 200 | 唯一能成功登录的组合 |
| **组合2** | 有效用户名 + 正确密码 + **错误验证码** | ❌ **验证码错误**，提示"验证码有误，请重新输入" | 400 | 验证码优先校验，不进入密码比对阶段 |
| **组合3** | 有效用户名 + **错误密码** + 正确验证码 | ❌ **用户名或密码错误**，统一提示，不区分用户已注册但密码错误 | 401 | 防止用户枚举攻击，错误信息不暴露具体哪一项出错 |
| **组合4** | 有效用户名 + **错误密码** + **错误验证码** | ❌ **验证码错误**（验证码优先），提示"验证码有误，请重新输入" | 400 | 即使密码错误也先校验验证码，两种错误只报一种 |
| **组合5** | **无效用户名** + 完全正确的"密码" + 正确验证码 | ❌ **用户名或密码错误**，统一提示，不暴露"用户不存在" | 401 | 防止用户枚举——攻击者无法通过错误提示判断用户是否注册 |
| **组合6** | **无效用户名** + 正确的"密码" + **错误验证码** | ❌ **验证码错误**，提示"验证码有误，请重新输入" | 400 | 验证码优先校验 |
| **组合7** | **无效用户名** + **错误密码** + 正确验证码 | ❌ **用户名或密码错误**，统一提示 | 401 | 与组合5结果一致，无法区分用户名无效还是密码错误 |
| **组合8** | **无效用户名** + **错误密码** + **错误验证码** | ❌ **验证码错误**（验证码优先），提示"验证码有误，请重新输入" | 400 | 验证码优先校验 |

> **校验顺序说明**：服务端按「验证码 → 用户名+密码组合」顺序校验。验证码错误时直接返回，不继续校验用户名密码；验证码通过后才校验用户名密码，且失败时统一提示"用户名或密码错误"。

### 2.3 接口测试策略

依据知识库中接口测试标准，重点覆盖以下检查点：

| 检查维度 | 检查项 | 预期标准 |
|---------|-------|---------|
| **正常逻辑** | 正确凭据登录，返回200 + Token | HTTP 200，响应体含 access_token, refresh_token, expires_in |
| **参数校验** | 空参数/缺失参数/非法参数 | HTTP 400，错误信息明确 |
| **鉴权异常** | 无Token/过期Token/伪造Token访问受保护接口 | HTTP 401/403 |
| **请求方法** | GET请求登录接口 | HTTP 405 Method Not Allowed |
| **Content-Type** | 非JSON格式请求 | HTTP 415/400 |
| **重复提交** | 同一Token/验证码重复提交 | 幂等性校验 / 防重放 |
| **响应时间** | 正常登录响应时间 | ≤ 500ms（基准标准），性能压测场景 ≤ 3s |
| **响应结构** | 响应体字段检查 | 与API文档一致 |

> **响应时间说明**：登录接口涉及密码哈希比对、数据库查询、Token 签发等多个环节，低于 200ms 在工程实践中极难稳定达到。依据知识库中服务端性能指标定义（优秀 < 1s）和基准测试准出标准（≤ 500ms），调整为 ≤ 500ms，并发场景 ≤ 3s。

### 2.4 安全测试策略

参考安全测试方法指南，重点关注：

#### 2.4.1 基础安全测试项

| 安全维度 | 测试点 | 预期 |
|---------|-------|------|
| **SQL注入** | 用户名/密码字段注入 `' OR 1=1 --` | 登录失败，无数据泄露 |
| **XSS** | 用户名输入 `<script>alert(1)</script>` | 过滤或转义，不执行 |
| **CSRF** | 伪造跨站请求 | CSRF Token校验拦截 |
| **暴力破解** | 短时间内大量错误尝试 | 验证码机制 + 账号临时锁定 |
| **密码传输** | 抓包检查密码是否明文传输 | 必须HTTPS + 加密传输 |
| **会话固定** | 登录前后Session ID是否变化 | 登录后重新生成Session ID |
| **Token安全** | 见 2.4.4 Token安全全项检查 | 详见表 |
| **敏感信息泄露** | 错误提示是否暴露账号存在性 | 统一"用户名或密码错误"提示 |
| **验证码安全** | 验证码能否被OCR识别/绕过 | 干扰足够，服务端二次校验 |
| **日志脱敏** | 登录日志是否记录明文密码 | 日志中密码字段脱敏 |

#### 2.4.2 OAuth 2.0 第三方登录安全测试（新增）

OAuth 2.0 授权码模式最高频漏洞为 state 参数缺失导致的 CSRF 攻击（攻击者可绑定受害者账号至自己的第三方身份）。以下为完整的 OAuth 安全测试矩阵：

| 安全维度 | 测试点 | 测试方法 | 预期结果 |
|---------|-------|---------|---------|
| **State参数CSRF防护** | 请求OAuth授权时是否生成并校验state参数 | 1) 抓取 OAuth 回调请求，篡改/移除 state 参数重放；2) 替换为攻击者获取的合法 state 绑定到受害者账号 | state 缺失或不匹配时拒绝绑定，HTTP 403 |
| **State参数不可预测性** | state 参数是否为高熵随机值 | 连续多次请求分析 state 生成模式 | 每次 state 唯一且不可预测（≥128位随机值），不可被枚举 |
| **State参数重用防护** | state 参数是否可重复使用 | 成功回调后，用同一 state 再次发起回调 | state 一次性有效，重复使用被拒绝 |
| **授权码劫持** | 授权码（authorization_code）是否一次性使用 | 成功回调后再次使用同一 code 请求 Token | 返回错误，拒绝重复兑换 |
| **重定向URI校验** | redirect_uri 是否被严格白名单校验 | 修改回调 redirect_uri 为攻击者控制的域名 | 非白名单 URI 被拒绝，避免授权码劫持 |
| **Client Secret泄露** | client_secret 是否仅在后端持有 | 检查前端请求/响应中是否暴露 client_secret | 前端不可见，仅后端安全存储 |
| **Token劫持-回调日志泄露** | OAuth 回调 URL 中的 code 参数是否被日志记录 | 检查服务端日志、访问日志中是否包含 code 参数 | 日志中 code 参数必须脱敏 |
| **第三方账号绑定校验** | 第三方账号是否已绑定其他本地账号 | 1) 第三方账号 A 绑定本地账号 1 后，再用 A 登录；2) 使用同一第三方账号多次绑定不同本地账号 | 已绑定的第三方账号只能登录对应本地账号；重复绑定时提示"该第三方账号已被绑定" |
| **解绑后安全** | 解绑第三方账号后，旧绑定关系是否彻底清除 | 解绑后使用旧的第三方令牌尝试登录本地账号 | 解绑后无法通过旧的第三方身份登录 |
| **OAuth回调重放** | 回调完整请求（含 code+state）是否可重放 | 录制完整回调请求，稍后时间重放 | 重放请求被拒绝（code/state 一次性） |

#### 2.4.3 越权访问测试（新增）

安全测试中必须覆盖以下越权场景，依据安全知识库 3.3.1.1 越权漏洞检查点：

| 越权类型 | 测试点 | 测试场景 | 预期结果 |
|---------|-------|---------|---------|
| **水平越权** | 用户A能否操作用户B的登录相关数据 | 1) 使用用户 A 的 Token 请求用户 B 的账号信息接口（如 `/api/v1/user/{B_id}`）；2) 修改请求中的用户 ID 参数为其他用户 | 仅有 B 的 Token 才能操作 B 的数据；A 的 Token 访问 B 数据返回 403 或 401 |
| **水平越权** | 用户A能否看到用户B的登录日志/安全设置 | 1) 遍历安全日志中的 userId 参数；2) 尝试查看其他用户的登录 IP 历史、设备历史 | 只能返回当前登录用户的安全数据，无法越权访问他人数据 |
| **水平越权** | 退出登录时能否使其他用户 Session 失效 | 使用用户 A 的 Token 调用退出接口，并指定用户 B 的 sessionId | 只能销毁自己的会话，无法操作其他用户的会话 |
| **水平越权** | Token刷新接口是否校验用户归属 | 用用户 A 的 refresh_token 尝试为用户 B 刷新 Token | 刷新 Token 时的用户身份校验，不能跨用户刷新 |
| **垂直越权** | 普通用户能否执行管理员权限的登录操作 | 1) 普通用户调用管理员专用的登录审计接口；2) 普通用户尝试查看全量登录日志 | 无权限时返回 403 Forbidden |
| **垂直越权** | 低权限角色能否访问高权限角色的登录控制台 | 尝试以普通用户 Token 访问管理后台的登录统计/锁定管理接口 | 严格 RBAC 校验，越权访问被拦截 |
| **未授权访问** | 未登录状态下能否访问需认证的接口 | 1) 不带 Token 访问 `/api/v1/user/profile`；2) 修改 Cookie/Header 伪装已登录 | 未认证请求返回 401 Unauthorized |
| **未授权访问** | 能否绕过登录直接通过 URL 访问内部页面 | 直接访问仪表盘/后台首页 URL，不经过登录流程 | 重定向至登录页或返回 401 |
| **参数篡改越权** | 修改请求参数中的角色/权限标识 | 在请求中篡改 role/admin 参数 | 服务端从 Token 中读取权限，不接受客户端传入的权限参数 |
| **IDOR（不安全的直接对象引用）** | 遍历用户 ID 参数访问注册信息 | 遍历 `/api/v1/user/register-info?id=1001~2000` 等参数 | 用户注册信息必须校验访问者身份与目标用户一致 |

#### 2.4.4 Token安全全项检查（补充完善）

| 安全维度 | 测试点 | 测试方法 | 预期结果 |
|---------|-------|---------|---------|
| **Token过期时间** | access_token 和 refresh_token 是否设置了合理的过期时间 | 1) 检查 JWT payload 中的 exp 字段；2) 等待 Token 过期后请求受保护接口 | access_token 应 ≤ 30 分钟；refresh_token 应 ≤ 7 天；过期 Token 请求返回 401 |
| **Token失效精确性** | Token 在过期瞬间的行为 | 1) 过期前 1s 请求；2) 过期瞬间请求；3) 过期后 1s 请求 | 过期时间的精度需达到秒级，不可提前失效或延迟失效 |
| **httpOnly属性** | 存储 Token 的 Cookie 是否设置了 httpOnly | 检查 Set-Cookie 响应头中的属性标志 | 必须设置 httpOnly 属性，防止 JavaScript 通过 document.cookie 读取 |
| **Secure属性** | Cookie 是否设置了 Secure 标志 | 同上 | 必须设置 Secure，确保仅通过 HTTPS 传输 |
| **SameSite属性** | Cookie 的 SameSite 策略 | 检查 Set-Cookie 中的 SameSite 属性 | 应设置为 Strict 或 Lax，防止 CSRF 攻击 |
| **Token可撤销性** | 退出登录后 Token 是否立即失效 | 1) 正常退出后使用原 Token 请求接口；2) Token 黑名单机制验证 | 退出后 Token 立即加入黑名单，被拒绝访问，返回 401 |
| **Token刷新撤销** | 使用 refresh_token 后旧 refresh_token 是否失效 | 1) 连续两次使用同一 refresh_token 刷新；2) 刷新后立即用旧的 refresh_token 再次刷新 | 刷新后旧 refresh_token 立即失效；检测到 refresh_token 重复使用应废弃所有相关 Token（暗示 Token 被盗用） |
| **Token刷新竞争条件** | 并发刷新 Token 时的行为 | 1) 同时发送 2 个 refresh 请求使用同一 refresh_token；2) 观察最终生成的 Token 数量和有效状态 | 系统需通过乐观锁或数据库事务避免重复生成多个有效 Token（双重发放漏洞） |
| **Token内容泄露** | JWT payload 中是否包含敏感信息 | 解码 JWT 检查 payload 内容 | Token 中不得包含明文密码、手机号、身份证号等 PII 数据 |
| **Token签名校验** | 伪造/篡改 Token 是否被拒绝 | 1) 修改 JWT payload 中的 userId；2) 使用换算法（alg: none）攻击；3) 使用错误密钥签名 | 任何篡改的 Token 均被拒绝，返回 401；服务端需验证签名算法白名单（拒绝 none 算法） |
| **Token未认证访问** | 无 Token 访问受保护接口 | 请求头不带 Authorization 字段 | 返回 401 Unauthorized |
| **不同端 Token 隔离** | Web 端 Token 能否在移动端使用 | 将 Web 端获取的 Token 在移动端 API 请求中使用 | 不同客户端的 Token 应该有所区分或限制，防止 Token 跨端滥用 |

### 2.5 优先级建议

| 优先级 | 测试内容 | 占比建议 |
|--------|---------|---------|
| **P0（阻塞级）** | 正常登录流程、密码错误提示、账号锁定、退出登录 | 40% |
| **P1（高级）** | Token过期、忘记密码/重置密码、验证码校验、接口参数异常 | 30% |
| **P2（中级）** | 多点登录、并发登录、Session超时、浏览器兼容性 | 20% |
| **P3（低级）** | 用户体验优化、UI细节、非主流环境兼容性 | 10% |

## 5. 质量风险评估

### 5.1 风险识别与评级

| 风险ID | 风险描述 | 可能性 | 影响程度 | 风险等级 | 应对策略 |
|--------|---------|--------|---------|---------|---------|
| R01 | **暴力破解导致账号泄露** | 中 | 严重 | **高** | 验证码 + 错误次数限制 + 锁定机制测试覆盖；安全测试纳入CI/CD门禁 |
| R02 | **SQL注入绕过认证** | 低 | 致命 | **高** | 安全专项测试、OWASP Top 10覆盖、代码审查强制参数化查询 |
| R03 | **Session固定/劫持** | 中 | 严重 | **高** | 登录后强制重新生成Session ID；全链路HTTPS |
| R04 | **高并发导致登录服务不可用** | 中 | 高 | **中高** | 100/500/1000并发压力测试；限流机制验证 |
| R05 | **密码明文传输被截获** | 低 | 严重 | **中** | HTTPS强制检查；密码传输加密验证 |
| R06 | **Token泄露导致账号冒用** | 中 | 严重 | **中高** | Token有效期策略 + 刷新机制 + 黑名单 + httpOnly 测试 |
| R07 | **验证码可绕过** | 中 | 中 | **中** | 服务端二次校验验证；自动识别/绕过测试 |
| R08 | **错误信息泄露账号存在性** | 高 | 低 | **中** | 统一"用户名或密码错误"提示 |
| R09 | **CSRF攻击导致恶意操作** | 中 | 中 | **中** | CSRF Token验证 + OAuth state参数校验测试全覆盖 |
| R10 | **跨浏览器/跨平台登录异常** | 中 | 中 | **中** | 兼容矩阵测试覆盖主流环境 |
| R11 | **密码重置流程被劫持** | 中 | 高 | **中高** | 多重身份验证；重置链接一次性有效 |
| R12 | **Token在日志中明文记录** | 高 | 中 | **中** | 日志脱敏规则验证 |
| R13 | **OAuth state参数缺失导致CSRF绑定攻击** | 中 | 严重 | **高** | OAuth回调强制校验state参数；不可预测的一次性值 |
| R14 | **水平越权访问他人账号数据** | 中 | 严重 | **高** | 接口层面严格校验用户归属；参数篡改防护 |
| R15 | **垂直越权/未授权访问敏感接口** | 中 | 严重 | **高** | RBAC权限校验全覆盖；无Token请求拦截 |
| R16 | **Token竞争条件导致双重发放** | 低 | 高 | **中** | 乐观锁/事务机制防止refresh_token并发重复发放 |
| R17 | **OAuth授权码重放/劫持** | 中 | 严重 | **高** | 授权码一次性校验 + redirect_uri白名单检查 |

### 5.3 质量风险应对

#### 5.3.1 高优先级风险（需专项应对）

| 风险 | 应对措施 | 验证方式 | 验证人/智能体 |
|------|---------|---------|-------------|
| **R01 暴力破解** | 测试验证码机制、错误次数计数器、锁定阈值、锁定持续时间 | 接口自动化 + UI自动化 | api-executor |
| **R02 SQL注入** | 所有输入字段注入测试（用户名、密码、验证码） | OWASP ZAP自动化 + 人工补充 | api-executor |
| **R03 Session劫持** | Session ID再生验证、HTTPS强制检查、Cookie安全属性检查 | 抓包 + 接口自动化 | api-executor |
| **R04 高并发** | 逐步加压测试：100→500→1000并发 | JMeter/Locust | 性能测试专项 |
| **R06 Token泄露** | Token有效期、httpOnly/Secure/SameSite属性、刷新Token撤销、黑名单机制、竞争条件 | 接口自动化 + 安全测试 | api-executor |
| **R13 OAuth state CSRF** | state参数生成不可预测性、一次性使用校验、缺失拦截 | 接口自动化 + 安全测试 | api-executor |
| **R14 水平越权** | 接口层面校验用户ID归属、IDOR参数遍历测试 | 接口自动化 + 安全扫描 | api-executor |
| **R15 垂直越权/未授权** | RBAC权限校验、无Token接口拦截、伪造角色参数检测 | 接口自动化 + 安全扫描 | api-executor |
| **R17 OAuth授权码劫持** | 授权码一次性使用、redirect_uri白名单、回调日志脱敏 | 安全测试 + 日志审计 | api-executor |

#### 5.3.2 测试准入/准出标准

**准入条件**：
- 登录功能冒烟测试通过（正常登录流程 + 退出流程）
- 测试环境就绪（服务可访问 + 数据库内预置数据完整）
- 接口文档定稿

**准出条件**：
- 用例覆盖率 100%（核心场景全覆盖）
- P0/P1级缺陷全部修复并验证通过
- P2级缺陷无阻塞项残留
- 安全测试漏洞全部修复或风险评估通过（含OAuth state防护、越权漏洞、Token安全全项）
- 并发 500 登录成功率达到 99.9% 以上
- AI质量三重审核评分 ≥ 95
