## 一、需求概述

### 1.1 业务背景

用户登录是几乎所有系统的入口功能，直接影响用户的第一体验和系统安全。一次失败的登录可能导致用户流失，一次被攻破的登录可能导致数据泄露。

**核心目标：**
- 保障用户身份认证的**正确性**和**安全性**
- 提供流畅的**登录体验**（≤3秒响应）
- 覆盖多终端、多场景的**登录方式**

### 1.2 利益相关者

| 角色 | 关注点 |
|------|--------|
| 最终用户 | 便捷登录、密码找回、多设备同步 |
| 产品经理 | 转化率、登录成功率、用户留存 |
| 安全团队 | 账户安全、防暴力破解、数据加密 |
| 开发团队 | 接口设计、会话管理、性能优化 |
| 测试团队 | 覆盖率、边界场景、兼容性 |

### 1.3 成功指标

- 登录成功率 ≥ 99.5%
- 登录响应时间 < 2s（P95）
- 暴力破解拦截率 100%
- 密码传输全程加密（HTTPS/TLS）

## 五、详细测试用例设计

### 5.1 等价类划分 — 账号密码登录

| 输入项 | 有效等价类 | 无效等价类 |
|--------|-----------|-----------|
| 用户名 | 正确格式（手机号/邮箱/用户名） | 空值、特殊字符、超长字符串、SQL注入串 |
| 密码 | 正确密码（符合长度和复杂度） | 空值、错误密码、超长字符串、含特殊符号 |

### 5.2 边界值分析 — 密码

| 测试场景 | 测试值 | 预期 |
|----------|--------|------|
| 密码最短 | min位字符 | 允许登录 |
| 密码最短-1 | min-1位字符 | 提示"密码长度不足" |
| 密码最长 | max位字符 | 允许登录 |
| 密码最长+1 | max+1位字符 | 提示"密码过长" |

### 5.3 场景法 — 完整登录流程

```
场景A：正常登录流程
  1. 打开登录页面
  2. 输入正确用户名
  3. 输入正确密码
  4. 点击登录按钮
  5. 验证：跳转首页，显示用户信息

场景B：密码错误→锁定流程
  1. 输入正确用户名 + 错误密码
  2. 重复5次
  3. 验证：第5次后账号锁定，提示"账号已锁定，请15分钟后重试"
  4. 等待15分钟后
  5. 重新登录成功

场景C：忘记密码→重置→重新登录
  1. 点击"忘记密码"
  2. 输入注册邮箱
  3. 收到重置邮件
  4. 点击重置链接
  5. 设置新密码
  6. 用新密码登录成功

场景D：异地登录提醒
  1. 在设备A（常用）正常登录
  2. 在设备B（新设备/新IP）登录
  3. 验证：设备A收到异地登录提醒
  4. 验证：设备B成功登录
```

### 5.4 安全测试专项

| 测试项 | 测试方法 | 预期 |
|--------|---------|------|
| SQL注入 | 用户名输入 `' OR 1=1 --` | 登录失败，不报数据库错误 |
| XSS攻击 | 用户名输入 `<script>alert(1)</script>` | 不执行脚本，正确转义 |
| 暴力破解 | 脚本连续尝试1000次密码 | 第5次后锁定，后续全部拦截 |
| 验证码绕过 | 复用已使用过的验证码 | 拒绝登录 |
| Token伪造 | 伪造JWT/Session ID | 拒绝访问，返回401 |
| 明文密码抓包 | 抓包检查登录请求 | 密码为密文，不可还原 |
| 会话固定攻击 | 使用固定Session ID登录 | 每次登录重新生成Session |

## 八、验收标准（Given-When-Then）

### AC-1：正常登录
```gherkin
Given 用户已注册且账号状态正常
And 用户在登录页面
When 用户输入正确的用户名和密码
And 点击"登录"按钮
Then 系统在2秒内响应
And 用户成功登录并跳转至首页
And 页面显示用户昵称/头像
```

### AC-2：密码错误保护
```gherkin
Given 用户已注册
When 用户连续输入错误密码5次
Then 系统锁定账号15分钟
And 显示剩余锁定时间
And 15分钟后自动解锁
And 解锁后可正常登录
```

### AC-3：安全传输
```gherkin
Given 用户在登录页面
When 用户输入密码
Then 密码字段以掩码形式显示（●●●●）
And 登录请求通过HTTPS传输
And 网络抓包无法获取明文密码
```

### AC-4：会话管理
```gherkin
Given 用户已登录
When 用户30分钟内无任何操作
Then 系统自动登出
And 下次操作时提示"登录已过期"
And 跳转至登录页面
```

### AC-5：密码重置
```gherkin
Given 用户忘记密码
When 用户通过邮箱请求密码重置
Then 系统发送重置邮件
And 重置链接24小时内有效
And 链接使用一次后失效
And 用户设置新密码后可用新密码登录
```

## 九、风险识别

| 风险 | 等级 | 影响 | 缓解措施 |
|------|------|------|---------|
| 密码明文存储泄露 | P0 | 用户数据大规模泄露 | 强制bcrypt/argon2加密+代码审计 |
| 暴力破解绕过锁定 | P0 | 账户被盗 | IP+设备指纹双重锁定 |
| 验证码可被OCR识别 | P1 | 自动化攻击 | 使用行为验证码+干扰强度调优 |
| Token被截获重放 | P1 | 会话劫持 | Token短期有效+刷新机制+绑定设备 |
| 弱密码允许注册 | P2 | 字典攻击成功 | 密码复杂度校验（长度+大小写+特殊字符） |
| 并发登录无控制 | P2 | 多人共享账号 | 可配置的设备数限制策略 |
