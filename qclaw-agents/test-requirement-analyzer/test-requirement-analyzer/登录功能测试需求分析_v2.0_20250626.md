## 一、需求背景与目标

### 1.1 业务背景

用户登录是几乎所有互联网应用的核心入口，承载着身份认证、安全防护、用户状态管理三大核心职责。登录功能的质量直接影响：

- **用户体验**：登录失败率高会导致用户流失
- **安全防线**：登录是系统第一道防线，缺陷可能被恶意利用
- **业务连续性**：登录故障等同于服务不可用

### 1.2 分析目标

本文档旨在将「测试用户登录功能」这一原始需求转化为：
- 结构化的功能测试点清单
- 可量化的非功能指标
- 明确的验收标准
- 可执行的测试策略

## 四、验收标准定义（Given-When-Then）

### 4.1 核心正向场景

```
【AC-001】用户名密码登录成功
Given 用户已注册账号（手机号: 13800138000，密码: Test@123）
When 用户在登录页输入正确账号和密码并提交
Then 返回HTTP 200，响应体包含有效JWT Token
And 页面跳转到首页/my-dashboard
And 登录日志记录（用户ID、时间戳、IP地址、UserAgent）

【AC-002】图形验证码校验
Given 用户连续3次登录失败
When 用户再次提交登录请求
Then 展示图形验证码
And 验证码4位数字，5分钟内有效
And 输入正确验证码后可继续登录

【AC-003】账户锁定机制
Given 同一账号5分钟内连续失败5次
When 该账号再次提交登录请求
Then 返回HTTP 429，提示"账户已锁定30分钟"
And 锁定记录写入安全日志

【AC-004】忘记密码重置
Given 用户忘记密码，点击"忘记密码"
When 输入注册手机号并完成身份验证
Then 发送重置链接到用户邮箱
And 链接24小时内有效
And 重置后密码与历史密码不重复
```

### 4.2 安全防护验收

```
【AC-005】SQL注入防护
Given 攻击者在密码框输入 "' or '1'='1"
When 提交登录请求
Then 不执行SQL，返回"用户名或密码错误"
And 记录安全告警日志

【AC-006】XSS攻击防护
Given 攻击者在用户名框输入 "<script>alert(1)</script>"
When 提交登录请求
Then 不执行脚本，过滤特殊字符
And 返回正常错误提示

【AC-007】Token防伪造
Given 攻击者篡改JWT Token的payload
When 携带伪造Token访问受保护API
Then 返回HTTP 401 Unauthorized
And 记录异常访问日志
```

## 六、测试策略

```
         ┌─────────────────┐
         │     E2E 测试     │  ← 少量关键路径（P0用例）
         │   (Playwright)   │     登录→核心功能→登出
         └────────┬────────┘
                  │
         ┌────────▼────────┐
         │   接口/集成测试   │  ← 重点覆盖（Postman/Newman）
         │    (REST API)    │     所有P0+P1用例自动化
         └────────┬────────┘
                  │
         ┌────────▼────────┐
         │   单元测试        │  ← 开发负责（持续集成）
```
