## 一、需求概述

用户登录功能为系统核心入口模块，负责用户身份验证、会话管理及权限校验。本文档从字段规则、判定逻辑、错误提示、状态保持、安全限制五个维度展开，明确测试范围与验收标准。

| 编号 | 功能模块 | 优先级 | 简要描述 |

## 二、用户名字段规则（F-01）

### 2.1 字段属性

| 属性项 | 规则描述 |
|--------|---------|
| 控件类型 | 文本输入框（`<input type="text">`） |
| 输入类型 | 支持用户名、手机号、邮箱三种格式 |
| 占位文案 | `"请输入用户名/手机号/邮箱"` |
| 自动聚焦 | 页面加载后焦点自动定位到用户名输入框 |
| 一键清除 | 输入框右侧显示清除按钮（×） |

### 2.2 长度规则

| 规则项 | 约束 | 说明 |
|--------|:----:|------|
| 最小长度 | 2字符 | 用户名至少2个字符 |
| 最大长度 | 50字符 | 用户名最多50个字符 |
| 空格处理 | 自动去除首尾空格 | 但中间空格保留（邮箱格式不允许空格） |

### 2.3 字符规则

| 规则项 | 约束 | 说明 |
|--------|:----:|------|
| 允许字符 | `A-Z a-z 0-9 _ . @ -` | 字母、数字、下划线、点、@、连字符 |
| 中文支持 | ✅ 支持 | 中文用户名可输入 |
| 特殊字符 | ❌ 不允许 | 空格、引号、尖括号、分号等 |
| 大小写 | ✅ 不区分 | 用户名比对不区分大小写 |
| 唯一性 | ✅ 全局唯一 | 注册时校验不可重复 |

### 2.4 前端校验规则

| 校验项 | 触发时机 | 提示文案 | 阻断请求 |
|--------|---------|---------|:--------:|
| 非空校验 | 失焦 + 提交 | `"请输入用户名"` | ✅ |
| 长度校验 | 实时 + 提交 | `"用户名长度需在2-50个字符之间"` | ✅ |
| 格式校验 | 提交 | `"用户名格式不正确"` | ✅ |

### 2.5 用户名字段验收标准

| AC-ID | 验收项 | 验收标准 |
|-------|--------|---------|
| AC-F01-001 | 正常输入 | 输入合法用户名（`test_user`），校验通过，可继续操作 |
| AC-F01-002 | 空值校验 | 不输入用户名点击登录，提示"请输入用户名"，不发起请求 |
| AC-F01-003 | 超长校验 | 输入51字符用户名，提示长度错误，不发起请求 |
| AC-F01-004 | 特殊字符 | 输入 `"' < > ; --` 等字符，提示格式错误，不发起请求 |
| AC-F01-005 | 空格处理 | 输入 `" test_user "`（含首尾空格），自动去除后提交 |
| AC-F01-006 | SQL注入 | 输入 `' OR '1'='1`，登录失败，无SQL错误暴露 |
| AC-F01-007 | XSS注入 | 输入 `<script>alert(1)</script>`，脚本被过滤不执行 |

## 四、登录成功/失败判定逻辑（F-03）

### 4.1 判定流程

```
用户点击"登录"
   │
   ├─【前端校验】─ 用户名非空？密码非空？格式正确？
   │    ├─ 不通过 → 前端提示错误，不发起请求
   │    └─ 通过 → 发起登录请求
   │
   ├─【后端校验】─ 用户名是否存在？
   │    ├─ 不存在 → 返回"用户名或密码错误"
   │    └─ 存在 → 继续校验
   │
   ├─【账号状态校验】─ 账号状态是否正常？
   │    ├─ 禁用 → 返回"账号已被禁用"
   │    ├─ 锁定 → 返回"账号已锁定"
   │    └─ 正常 → 继续校验
   │
   ├─【密码校验】─ 密码是否正确？
   │    ├─ 正确 → 登录成功，生成Token，返回200
   │    ├─ 错误 → 错误计数+1
   │    │    ├─ 未达上限 → 返回"用户名或密码错误"
   │    │    └─ 达到上限 → 锁定账号，返回"账号已锁定"
   │    └─ 第三方 → 检查OAuth token有效性
   │
   └─【登录成功】─ 生成Session/Token
        ├─ 生成JWT Token（含用户ID、角色、过期时间）
        ├─ 设置Cookie（HttpOnly, Secure, SameSite）
        ├─ 记录登录日志（时间、IP、设备、用户代理）
        └─ 返回跳转URL
```

### 4.2 登录成功条件

| 条件 | 说明 |
|------|------|
| 用户存在 | 数据库中可查到该用户名 |
| 账号正常 | 未被禁用、未过期、未锁定 |
| 密码正确 | 与存储的bcrypt哈希匹配 |
| Token正常 | JWT Token可正常生成 |
| IP/设备白名单 | ⚠️ 如配置了IP白名单，需在白名单内 |

### 4.3 登录失败条件

| 失败原因 | 判定逻辑 | 返回状态码 |
|---------|---------|:----------:|
| 用户名不存在 | 数据库查询返回空 | 401 |
| 密码错误 | bcrypt哈希比对不匹配 | 401 |
| 账号禁用 | 账号状态字段 = `disabled` | 403 |
| 账号锁定 | 锁定标记 = `locked` 且未到解锁时间 | 403 |
| Session过期 | Token校验失败 | 401 |
| 请求频率过高 | 超过接口频率限制 | 429 |

### 4.4 登录判定验收标准

| AC-ID | 验收项 | 验收标准 |
|-------|--------|---------|
| AC-F03-001 | 成功登录 | 正确用户名+密码 → 返回200，生成Token |
| AC-F03-002 | 失败登录 | 错误密码 → 返回401，提示"用户名或密码错误" |
| AC-F03-003 | 禁用账号 | 禁用账号 → 返回403，提示"账号已被禁用" |
| AC-F03-004 | 锁定账号 | 锁定账号 → 返回403，提示"账号已锁定" |
| AC-F03-005 | 统一错误 | 用户名不存在vs密码错误 → 返回相同文案"用户名或密码错误" |

## 五、错误提示文案与规则（F-04）

### 5.1 提示文案总表

| 触发场景 | 前端提示文案 | 后端响应文案 | 展示位置 | 文案类型 |
|---------|------------|------------|---------|---------|
| 用户名为空 | `"请输入用户名"` | 不发起请求 | 用户名输入框下方 | 前端校验 |
| 密码为空 | `"请输入密码"` | 不发起请求 | 密码输入框下方 | 前端校验 |
| 用户名超长 | `"用户名长度超出限制"` | 不发起请求 | 用户名输入框下方 | 前端校验 |
| 密码超短 | `"密码长度不足"` | 不发起请求 | 密码输入框下方 | 前端校验 |
| 密码弱 | `"密码强度过低"` | 不发起请求 | 密码输入框下方 | 前端校验 |
| **用户名/密码错误** | `"用户名或密码错误"` | `"用户名或密码错误"` | 表单顶部浮动提示 | **模糊提示** 🔴 |
| 账号禁用 | `"账号已被禁用，请联系管理员"` | 同上 | 表单顶部浮动提示 | 明确提示 |

### 5.2 提示文案规则约束

| 规则 | 约束等级 | 说明 |
|------|:--------:|------|
| **模糊统一原则** | 🔴 强制 | 用户名不存在、密码错误必须返回相同文案"用户名或密码错误" |
| **不暴露系统信息** | 🔴 强制 | 不可返回SQL错误、文件路径、操作系统信息、堆栈跟踪 |
| **不暴露用户信息** | 🔴 强制 | 不可返回"该手机号已注册"等可用于枚举的信息 |
| **友好可读** | 🟡 建议 | 提示语言简洁明了，非技术术语 |
| **位置一致** | 🟢 可优化 | 同类错误提示出现在相同位置 |

### 5.3 安全说明（为何统一模糊提示）

| 风险 | 说明 | 防御 |
|------|------|------|
| 用户名遍历 | 攻击者通过"用户不存在"vs"密码错误"枚举有效账号 | ✅ 统一为"用户名或密码错误" |
| 社工攻击 | 通过确认用户是否存在发动针对性攻击 | ✅ 同上 |
| 信息泄露 | 暴露数据库中的用户注册信息 | ✅ 同上 |

### 5.4 错误提示验收标准

| AC-ID | 验收项 | 验收标准 |
|-------|--------|---------|
| AC-F04-001 | 统一提示 | 用户名不存在和密码错误返回相同文案 |
| AC-F04-002 | 无系统信息 | 错误响应中不含SQL、路径、堆栈信息 |
| AC-F04-003 | 禁用提示明确 | 禁用账号提示包含"请联系管理员" |
| AC-F04-004 | 锁定提示含时间 | 锁定账号提示包含剩余时间 |
| AC-F04-005 | 前端阻断 | 前端检验不通过时不发起请求 |
| AC-F04-006 | 展示位置 | 错误提示出现在对应输入框下方或表单顶部 |

## 六、登录状态保持机制（F-05）

### 6.1 状态保持方式

| 方式 | 技术实现 | 说明 |
|------|---------|------|
| Session | 服务端Session + Cookie SessionID | 传统方式，服务端存储 |
| JWT Token | 客户端存储JWT | 无状态方式，客户端存储Token |
| Cookie | HttpOnly Cookie | 与Session或JWT配合使用 |

### 6.2 记住我功能（默认不勾选）

| 规则项 | 勾选"记住我" | 不勾选"记住我" |
|--------|:------------:|:--------------:|
| Token有效期 | **30天** | **Session级**（浏览器关闭即失效） |
| 刷新Token | 7天后自动刷新 | — |
| Cookie属性 | HttpOnly + Secure + SameSite.Strict | 同左 |
| 退出清除 | ✅ 清除Cookie | ✅ 清除Session |

### 6.3 Token属性

| 属性 | 值 | 说明 |
|------|:---:|------|
| 类型 | JWT (JSON Web Token) | 自包含的无状态Token |
| 签名算法 | HS256 或 RS256 | 对称/非对称签名 |
| 有效期 | 不勾选记住我：24h | 会话级Token |
| 有效期 | 勾选记住我：30天 | 长期Token |
| 刷新机制 | Refresh Token刷新 | Access Token过期后使用Refresh Token续期 |
| Cookie传输 | HttpOnly | 防止XSS窃取 |
| Cookie作用域 | Secure | 仅HTTPS传输 |
| Cookie限制 | SameSite=Strict | 防止CSRF |

### 6.4 Token校验流程

```
用户请求受保护资源
   ├─ 请求携带Token（Cookie或Authorization Header）
   ├─ 服务端校验Token
   │    ├─ 有效 → 放行请求
   │    ├─ 过期 → 尝试Refresh Token刷新
   │    │    ├─ 刷新成功 → 返回新Token，放行请求
   │    │    └─ 刷新失败 → 返回401，跳转登录页
   │    └─ 无效 → 返回401，跳转登录页
   └─ 退出登录 → 清除Token（前端+后端黑名单）
```

### 6.5 并发与多端状态

| 场景 | 规则 | 说明 |
|------|------|------|
| 多端登录 | ✅ 允许 | 同一账号可在多个设备同时登录 |
| 互踢机制 | ⚠️ 可选 | 可为新登录踢出旧会话（如微信） |
| 同设备多窗口 | ✅ 允许 | 共享同一个Session/Token |

### 6.6 状态保持验收标准

| AC-ID | 验收项 | 验收标准 |
|-------|--------|---------|
| AC-F05-001 | 勾选记住我 | 勾选→登录→关闭浏览器→重开 → 保持登录态 |
| AC-F05-002 | 不勾选记住我 | 勾选→登录→关闭浏览器→重开 → 需要重新登录 |
| AC-F05-003 | Token刷新 | Token过期后，Refresh Token可自动刷新 |
| AC-F05-004 | 退出清除 | 退出登录后，Token失效，不可回退 |
| AC-F05-005 | Cookie安全 | Cookie包含 HttpOnly + Secure + SameSite |
| AC-F05-006 | 30天有效 | 勾选后第29天可正常登录，第31天需要重新登录 |

## 七、安全限制（F-06）

### 7.1 密码错误次数锁定规则

| 规则项 | 规则值 |
|--------|:------:|
| 触发阈值 | 连续**5次**密码错误 |
| 锁定时长 | **30分钟** |
| 计数窗口 | 统计连续错误，登录成功则重置计数 |
| 触发动作 | 锁定账号 + 显示图形验证码 |
| 锁定范围 | 按用户名锁定（不影响其他用户） |
| 锁定维度 | ✅ 用户名级 + ⚠️ 可选：IP级 |

### 7.2 锁定流程

```
第1次密码错误 → 计数=1，返回"用户名或密码错误"
第2次密码错误 → 计数=2，返回"用户名或密码错误"
第3次密码错误 → 计数=3，返回"用户名或密码错误"
第4次密码错误 → 计数=4，返回"用户名或密码错误"
第5次密码错误 → 计数=5，锁定账号30分钟
                   返回"账号已锁定，请30分钟后重试"
                   ⚠️ 同时要求输入图形验证码
第6次(锁定中) → 返回"账号已锁定，请X分钟后重试"
                 （显示剩余解锁时间）
锁定到期 → 自动解锁，计数重置为0
```

### 7.3 图形验证码规则

| 规则项 | 规则描述 |
|--------|---------|
| 触发条件 | 连续**3次**密码错误后显示 |
| 验证码类型 | 4位字母数字混合（大小写不敏感） |
| 有效期 | 5分钟 |
| 刷新方式 | 点击验证码图片刷新 |
| 防自动化 | 图片有噪点、扭曲、背景干扰线 |

### 7.4 接口频率限制

| 限制项 | 规则值 |
|--------|:------:|
| 登录请求频率 | 同一IP 10次/分钟 |
| 验证码请求频率 | 同一手机号 1次/60秒 |
| Token刷新频率 | 同一Token 5次/分钟 |

### 7.5 其他安全限制

| 安全措施 | 说明 |
|---------|------|
| HTTPS强制 | 所有请求必须通过HTTPS |
