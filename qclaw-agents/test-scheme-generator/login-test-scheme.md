## 1. 测试概述

### 1.1 测试目标
对登录功能进行功能验证，覆盖正常流程与异常流程，确保登录模块的正确性、安全性和可用性。

### 1.2 测试范围
**本次覆盖：**
- 正常登录流程
- 密码错误场景

**本次不覆盖（建议后续补充）：**
- 用户名不存在
- 空输入校验
- 安全攻击（SQL注入/XSS）
- 网络异常/超时
- 多端登录冲突
- Token 过期机制
- 验证码流程
- 第三方 OAuth 登录

### 1.3 优先级定义
| 等级 | 说明 | 应对策略 |
|------|------|---------|
| **P0** | 核心功能，阻塞发布 | 必须通过，100%覆盖 |
| **P1** | 重要体验，建议首版覆盖 | 优先执行，允许小部分因环境问题跳过 |
| **P2** | 增强体验，可后续迭代 | 按时间安排，可延期 |

## 5. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 验证码干扰测试 | 批量测试时触发验证码导致误报 | 测试环境关闭验证码或配置白名单 |
| 账号被锁定 | 连续错误测试导致账号临时锁定 | 准备多个测试账号或等待锁定重置 |
| 网络延迟 | Loading 状态一闪而过难以观察 | 通过 Chrome DevTools 模拟慢速 3G |
| Session 冲突 | 多用例共用同一账号导致状态干扰 | 每个用例独立登录或使用独立测试账号 |
| 安全日志记录 | 测试产生大量错误登录日志 | 测试完成后清理测试产生的日志记录 |

## 6. 附录

### 6.1 抓包检查要点（可选）
如果测试过程中需要抓包验证，关注以下内容：

| 项目 | 检查点 |
|------|--------|
| 请求方法 | 登录请求应为 POST 而非 GET |
| 密码传输 | 密码应加密传输（HTTPS），不应在 URL 参数中 |
| 响应状态码 | 成功 200，失败 401/400 |
| Cookie/Token | 登录成功后 Set-Cookie 或 Token 响应头 |
| 请求频率 | 不应有重复的登录请求发出 |

### 6.2 等价类划分参考
| 输入项 | 有效等价类 | 无效等价类 |
|--------|-----------|-----------|
| 用户名 | 已注册的用户名 | 未注册用户名、空值、SQL 注入字符串 |
| 密码 | 对应的正确密码 | 错误密码、空值、超长密码(>128字符) |
