## 3. 测试计划

### 3.1 执行轮次规划

建议分 **三轮** 执行测试，各轮次之间设置有依赖阻断检查：

```
第一轮: P0 冒烟测试 ── 阻塞条件 ──→ 第二轮: P1 核心测试 ── 阻塞条件 ──→ 第三轮: P2 全面测试
```

#### 第一轮 ▶ SIT / 冒烟测试（P0）

| 项目 | 内容 |
|------|------|
| **目标** | 验证登录核心路径可用性，阻挡阻塞性缺陷 |
| **用例数** | 43 条 |
| **预计工时** | 0.5 ~ 1 天 |
| **执行顺序** | 功能正常路径 → 功能异常路径 → 安全关键项 → 性能基线 |
| **通过标准** | P0 通过率 = 100%（阻塞发布） |
| **阻断条件** | ⚠ 任一 P0 失败 → 中止本轮，提交开发修复 → 修复后回归 → 继续 |

**P0 执行优先子模块：**
1. **功能测试**（13 条）：F-001~F-003, F-006~F-009, F-013~F-017, F-041~F-042
2. **安全测试**（16 条）：SEC-001~SEC-007, SEC-009, SEC-011~SEC-012, SEC-019~SEC-020, SEC-023~SEC-025, SEC-027~SEC-028, SEC-033
3. **兼容性测试**（6 条）：COMP-001~COMP-003, COMP-007~COMP-008
4. **性能测试**（2 条）：PERF-002, PERF-006
5. **UI 测试**（3 条）：UI-001, UI-004, UI-009
6. **易用性测试**（3 条）：US-006, US-014

#### 第二轮 ▶ 功能深度测试（P1）

| 项目 | 内容 |
|------|------|
| **目标** | 覆盖异常场景、安全加固、兼容性基础、错误处理 |
| **用例数** | 69 条 |
| **预计工时** | 1.5 ~ 2 天 |

| **阻断条件** | ✅ 不阻塞本轮；但失败记录需要在发布前修复或评估影响 |

#### 第三轮 ▶ 全面覆盖测试（P2）

| 项目 | 内容 |
