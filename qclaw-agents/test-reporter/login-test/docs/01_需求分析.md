## 1. 功能概述

### 1.1 业务背景

登录功能是 Web 应用程序的核心安全入口，负责验证用户身份并建立会话。本文档对登录功能进行全面的需求分析，为测试用例设计提供依据。

### 1.2 功能范围

| 模块 | 说明 |
|------|------|
| 基础登录 | 用户名/邮箱 + 密码 + 验证码登录 |
| 记住登录 | "记住我"功能延长会话有效期 |
| 忘记密码 | 密码找回与重置流程 |
| 会话管理 | Session/Cookie 管理与安全控制 |

### 1.3 目标用户

- **普通用户**：使用用户名或邮箱登录
- **管理员**：拥有更高权限的管理员账号
- **测试人员**：执行登录功能测试

## 2. 功能需求规格

### 2.1 基础登录流程

#### 2.1.1 输入字段要求

| 字段 | 类型 | 必填 | 长度限制 | 格式要求 |
|------|------|------|----------|----------|
| 用户名/邮箱 | 文本 | 是 | 4-32 字符 | 支持字母、数字、下划线、中文、邮箱格式 |
| 密码 | 密码 | 是 | 6-20 字符 | 支持字母、数字、特殊字符，区分大小写 |
| 验证码 | 文本 | 是 | 4 位 | 不区分大小写，5 分钟内有效 |

#### 2.1.2 登录成功条件

1. 用户名/邮箱存在于系统中
2. 密码与用户名匹配
3. 验证码正确
4. 账号状态为"正常"（未禁用、未注销）
5. 账号已激活

#### 2.1.3 预期响应

- 登录成功：跳转到用户首页，显示欢迎信息
- 登录失败：显示错误提示，验证码刷新

### 2.2 记住我功能

| 属性 | 说明 |
|------|------|
| Cookie 有效期 | 勾选后 7 天，未勾选为会话级 |
| 安全要求 | 使用 HttpOnly、Secure 属性 |
| 覆盖规则 | 新登录覆盖旧记住状态 |

### 2.3 忘记密码流程

```
用户输入邮箱 → 系统验证邮箱存在 → 发送重置链接到邮箱 → 用户点击链接 → 设置新密码 → 完成重置
```

| 环节 | 要求 |
|------|------|
| 邮箱验证 | 检查邮箱格式和是否存在 |
| 链接有效期 | 30 分钟 |
| 链接一次性 | 使用后立即失效 |
| 新密码要求 | 同登录密码要求 |

### 2.4 安全需求

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| SEC-001 | 防 SQL 注入：所有输入字段需过滤特殊字符 | P0 |
| SEC-002 | 防 XSS 攻击：输出时进行 HTML 转义 | P0 |
| SEC-003 | 防暴力破解：连续 5 次错误锁定账号 30 分钟 | P0 |
| SEC-004 | 防暴力破解：IP 频率限制 10 次/分钟 | P0 |
| SEC-005 | 防 Session 固定攻击：登录后更换 Session ID | P0 |
| SEC-006 | 密码传输：必须使用 HTTPS 加密 | P0 |
| SEC-007 | 防 CSRF：使用 Token 验证 | P0 |
| SEC-008 | 防敏感信息泄露：登录错误提示统一化 | P1 |

### 2.5 性能需求

| 指标 | 要求 |
|------|------|
| 登录响应时间 | ≤ 2 秒（正常网络） |
| 并发登录能力 | ≥ 100 用户/秒 |
| Session 存储 | 支持 10000 并发 Session |

### 2.6 兼容性需求

| 浏览器 | 支持版本 |
|--------|----------|
| Chrome | 最近 2 个主要版本 |
| Firefox | 最近 2 个主要版本 |
| Safari | 最近 2 个主要版本 |
| Edge | 最新版本 |
| iOS Safari | iOS 12+ |
| Chrome Android | Android 6.0+ |

## 3. 用户故事

### 3.1 核心用户故事

| ID | 用户故事 | 验收标准 |
|----|----------|----------|
| US-001 | 作为已注册用户，我希望使用正确的账号密码登录系统 | 输入正确凭据后成功进入系统 |
| US-002 | 作为普通用户，我希望登录过程安全可靠 | 密码加密传输，会话安全管理 |
| US-003 | 作为健忘用户，我希望通过邮箱重置密码 | 能收到重置邮件并成功重置 |
| US-004 | 作为用户，我希望"记住我"功能正常工作 | 关闭浏览器后无需重新登录 |

### 3.2 异常场景用户故事

| ID | 用户故事 | 验收标准 |
|----|----------|----------|
| US-005 | 作为错误输入用户，我希望看到清晰的错误提示 | 错误提示明确告知问题所在 |
| US-006 | 作为攻击者，系统应阻止恶意登录尝试 | 暴力破解被有效阻止 |

## 4. 数据规格

### 4.1 用户表结构（参考）

```sql
CREATE TABLE users (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    username    VARCHAR(32) UNIQUE NOT NULL,
    email       VARCHAR(128) UNIQUE,
    password    VARCHAR(255) NOT NULL,  -- BCrypt 加密
    status      TINYINT DEFAULT 1,       -- 0:禁用 1:正常 2:注销
    is_active   BOOLEAN DEFAULT FALSE,   -- 邮箱激活状态
    created_at  DATETIME,
    updated_at  DATETIME
);

CREATE TABLE login_attempts (
    id          BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id     BIGINT,
    ip_address  VARCHAR(45),
    attempt_at  DATETIME,
    success     BOOLEAN,
    FOREIGN KEY (user_id) REFERENCES users(id)
);
```

### 4.2 登录日志字段

| 字段 | 说明 |
|------|------|
| user_id | 用户 ID（脱敏） |
| ip_address | 登录 IP |
| user_agent | 浏览器信息 |
| login_time | 登录时间 |
| login_status | 成功/失败 |
| failure_reason | 失败原因（不泄露敏感信息） |

## 5. 接口规格

### 5.1 登录接口

**POST /api/auth/login**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 用户名或邮箱 |
| password | string | 是 | 密码（已加密传输） |
| captcha | string | 是 | 验证码 |
| captcha_key | string | 是 | 验证码会话 key |
| remember | boolean | 否 | 记住我 |

**响应示例：**

```json
// 成功
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIs...",
    "user": {
      "id": "xxxxx",
      "username": "testuser",
      "avatar": "..."
    }
  }
}

// 失败
{
  "code": 401,
  "message": "用户名或密码错误",
  "data": null
}
```

### 5.2 验证码接口

**GET /api/auth/captcha**

响应：图片二进制流

## 6. 约束与限制

| 约束项 | 说明 |
|--------|------|
| 环境限制 | 需要 HTTPS 环境才能上线 |
| 网络要求 | 登录接口需要稳定的网络连接 |

## 7. 术语表

| 术语 | 说明 |
|------|------|
| Session | 服务器端会话，用于保持用户登录状态 |
| Cookie | 客户端存储，用于存放 Session ID 或记住我令牌 |
| CSRF | Cross-Site Request Forgery，跨站请求伪造 |
| XSS | Cross-Site Scripting，跨站脚本攻击 |
| SQL Injection | SQL 注入攻击 |
| BCrypt | 密码哈希算法 |
